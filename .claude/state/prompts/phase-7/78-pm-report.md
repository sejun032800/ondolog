## 4. PE 확인 — 사실 2건

1. **시행일 = 오늘(11/16).** 처리방침 §6은 "그 빌드를 처음 설치하는 날"입니다. 지금 20:36이라, 사람 작업 7단계(db push · 키 · Vault · 배포 · 빌드 · 설치)가 **자정을 넘기면 시행일이 실제와 어긋납니다.** 오늘 안에 설치하지 못하면 설치 날짜로 상수 한 줄을 고치고 법무 관문을 다시 돌립니다(Proteur 안내함).
2. **소프트 삭제된 행의 내용이 서버에 남습니다(새로 찾음 · 중요).** R108-2 결과에서 보이듯, 앱에서 "지운" 사진 · 메모 행은 **숨김 표시만 되고 행이 남습니다**(파일은 76-f 정리가 지움). 메모라면 **글 내용이 DB에 계속 남습니다**. 메시지 지우기가 같은 방식이면 대화 원문도 남습니다. 처리방침 5번 "내가 올린 사진 · 메모는 언제든 지울 수 있습니다"와 r104의 "구현을 문안에 맞춘다" 원칙에 비추면 같은 종류의 틈입니다.
   - PE 제안: 메인 세션이 **소프트 삭제를 쓰는 테이블과 남는 칸을 표로** 먼저 보고합니다. 그다음 월요일 정리(`purgeWithdrawn` 옆 단계)에서 **숨긴 지 24시간이 지난 행을 실제로 지우거나**, 내용 칸을 비웁니다. 마이그레이션 0으로 될 가능성이 큽니다.
