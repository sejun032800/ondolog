## 목표 (PM)

**코너 3종(17-1 데이트 아카이브 · 17-4 다정한 말들 · 17-5 이달의 우리)의 프롬프트와 입력 단계를 정교화한다. 실제 호출은 하지 않는다.**
(ROADMAP r16 §3 M1 — M1b)

**M1b의 경계 (ROADMAP r16).** 실제 출력을 보기 전에 굳히지 않는다. 출력 모양에 기대는 층은 출력을 본 뒤(M1c)에 고친다.

## 허용 범위

| 대상 | 할 일 |
|---|---|
| **코너 3종 프롬프트 문면** | `system` 블록의 **지시, 좋은 예/나쁜 예, 선별 기준**을 다듬는다 |
| **입력 전처리 — 채팅 입력량 상한 후보** | **2~3안**을 만들고, 안마다 `50-` 데이터셋으로 **dry 실행 글자 수와 추정 토큰 수**를 잰다 |
| **입력 전처리 — 규칙 기반 사전 선별 후보** | 후보를 만들고 각 후보가 무엇을 남기고 무엇을 빼는지 보인다 |

**근거 (원본을 직접 읽는다)**
- `docs/ONDOLOG_MASTER.md` **3-7** — 전 코너 공통 원칙, 허용/금지 표, 판단 기준
- **17-1** · **17-4**(선별 우선순위) · **17-5**

**상한·선별 후보는 PM이 M1c 전에 하나로 정한다.** 그 전까지 후보는 **하네스(`scripts/ops/`)의 dry 실행 옵션으로만** 두고 측정한다.
입력 조립(`inputAssembly.ts`) 등 운영 경로에 넣지 않는다.

**추정 토큰은 API를 부르지 않고 계산한다.** 쓴 추정 방법을 보고한다.
