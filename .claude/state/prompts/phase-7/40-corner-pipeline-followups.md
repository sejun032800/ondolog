## 범위 (PM) — 넷

### 1. 파생값을 저장 스키마 밖으로

- 근거 개수·기사 순서·지도 등 **입력에서 계산하는 값**을 저장 스키마의 `transform`에서
  빼고, **골격의 별도 단계(파생값 채우기)**로 옮긴다
- **저장 스키마는 모양만 검사한다** — `src/types/corners/`의 스키마에 계산이 남지 않는다
- 파생값 함수는 **필수, 기본값 없음**

### 2. `periodLabel`을 기간에서 만든다

- 입력·맥락으로 따로 받지 않는다. **`period`와 `cadence`에서 함수 하나로** 만든다
- 3단계에서 더한 "빈 `periodLabel`이면 멈춤"은 받는 값이 없어지므로 함께 정리한다

### 3. 대기는 직전 호출이 전송 실패였을 때만

- `llmClient`가 **자기 직전 호출이 전송 수준에서 실패했을 때만** 기다린다
- 직전 호출이 HTTP로 성공했으면 파이프라인이 `schema_invalid`로 다시 불러도 기다리지 않는다
- 지수 백오프는 §17-0-5-A대로 전송 실패에만. 층 분리는 그대로(`llmClient`는 Zod를 모른다)

### 4. 규칙 F 테스트 (§17-0-3)

- 저장소에 커밋되는 모든 파일의 **basename**이 규칙을 지키는지 검사한다
- 수집은 1부 설계를 따른다. 디렉터리명은 보지 않는다(라우트 그룹 `(tabs)` 등)
- 위반 합성 입력은 걸리고, 정상 합성 입력은 통과하고, **저장소 실제 파일이 통과**한다

## 완료 기준

- 범위 1~4가 구현·테스트됐다
- `src/types/corners/`의 저장 스키마에 **계산(`transform` 등)이 남지 않는다**
- 파생값 단계가 **필수**다(빠지면 컴파일 오류)
- `periodLabel`을 받는 자리가 없다
- **직전 호출이 성공한 뒤의 재호출은 기다리지 않고, 전송 실패 뒤의 재호출만 기다린다** —
  각각 테스트로
- 규칙 F 테스트가 있고 저장소가 통과한다
- 두 게이트 0 에러, jest 855 대비 감소 없음
