## 1단계 — P2 상대가 남은 사람의 탈퇴 (ㄱ안 · 실제 커플 전 필수, R105-2)

### ① 먼저 표 (보고 맨 앞 · 손대기 전에)

`profiles` · `auth.users`를 가리키는 **모든 외래 키**를 마이그레이션에서 찾아 표로 정리합니다. 열은 다음과 같습니다.

| 테이블.칸 | 가리키는 곳 | 지금 on delete | 비움 허용? | 탈퇴 최종 삭제를 막는가 | 바꿀 동작 |
|---|---|---|---|---|---|

- 최소 대상: `couples`(두 사람 칸) · `messages`(보낸 사람) · `data_entries`(작성자) · `date_stops`(m3 작성자) · `stories` · `issues` · `couple_dissolutions`(요청자 등) · 성격 결과 · 재검사 · 그 밖에 찾은 것 전부
- 원칙: **남은 사람의 것은 그대로 · 떠난 사람을 가리키던 칸은 비움**(`on delete set null` + 비움 허용). 떠난 사람의 **기록 행**은 030 · `purgeWithdrawn`이 이미 지우는지 표에 함께 적음
- 막는 곳이 커플 말고도 있으면 **같은 마이그레이션 `76-g-m1`에서 같은 원칙**으로

### ② 칸이 빈 커플을 견디는지 (읽기 확인 + 필요한 최소 수정)

- **기준 상태**: 해제가 끝난 뒤 남은 사람의 화면과 같아야 함
- 확인할 곳:
  - 앱(메인 · 채팅 · 피드 · 하늘 · 설정 · 매거진)
  - `issues_public`
  - `fn_connect_couple` 등 커플 관련 RPC
  - 권한 규칙 도우미(011)
  - 렌더(읽기만)
- 각 곳마다 결과를 "그대로 됨 / 작은 수정 / 번짐" 중 하나로 표시
- 상대 이름 자리에는 빈 값 대신 기존 해제 완료 표시를 씀(새 문구가 필요하면 PM 확인 목록에 적음)

### ③ `purgeWithdrawn.ts` 보류 해제

- 상대가 남은 탈퇴자도 **저장소 → 행 → 인증 사용자** 순서로 끝까지 지움
- 커플 행 · 발행된 호 · 상대의 기록 · 파일은 남김
- **PGlite 시험**:
  - 상대가 남은 탈퇴자 최종 삭제 → **이메일(인증) · 프로필 · 성격 결과 · 재검사 0**
  - 남은 사람의 커플 행(칸 비움) · 발행된 호 · 자기 기록 · 자기 장소 · 메시지 **그대로**
  - 떠난 사람이 보낸 메시지 · 남긴 기록의 처리가 ①의 표와 같음
  - 두 사람 모두 떠난 경우 기존 동작 회귀 0
- 스크립트 시험(가짜 클라이언트): "보류" 0 · 순서 · 중간 실패 재실행

### ④ 번짐 판단

다음 중 하나면 P2는 멈추고 ㄴ(익명화 — 프로필 행을 남기고 내용 · 인증 이메일을 비움)과 비교 보고:
- 앱에서 고칠 파일이 **10개를 넘음**
- 렌더 수정이 필요함
