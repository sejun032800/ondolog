## 범위 — 넷

### A. 검사 단계(훅) 필수화 (§17-0-4, r42)

- 빈 결과 판정·ID 해석·원문 채우기를 받는 자리를 **전부 필수**로 바꾼다
- **기본값(통과형)을 지운다.** 빠지면 **컴파일 오류**여야 한다
- `scopedRecords`도 필수 그대로인지 확인한다
- 참조할 ID가 없는 코너도 **"없다"고 답하는 함수를 넘기는 형태**여야 한다 —
  단계를 빼는 길이 없어야 한다

### B. 소속 단언에 기간 (§17-0-4-B, r42)

- 단언이 **커플과 기간을 함께** 본다
- 기간 기준은 **`context.period`**, 경계는 `[start, end)`(§17-0-7 Q10)
- 재소환 표시가 있는 레코드는 **"기간 이전"**을 허용한다(§17-0-4-A, Q1)
- **커플 조건은 재소환이어도 그대로** — 맥락의 커플과 다르면 막힌다

### C. 기간 판정 함수는 하나 (§17-0-4-B, r42)

- 기간 판정(재소환 포함)을 **한 함수**로 둔다
- **호출 전 단언(입력 쪽)과 ID 해석(응답 쪽)이 둘 다 그 함수를 부른다**
- 두 곳에 같은 규칙을 따로 짜지 않는다

### D. 맥락 값 검증 (§17-0-4-B, r42)

- 아래 중 하나라도 해당하면 단언은 **실패**다(LLM 호출 전)
  - 커플 식별자가 빈 문자열
  - 기간의 시작·끝이 날짜가 아님
  - 기간의 시작이 끝보다 늦음
- 실패는 2단계의 소속 단언과 **같은 방식**으로 멈춘다(실패 사유 기록 없음,
  저장 없음, 오류 전파)

### 그리고 — `brandedTypes.ts` 주석 정정

`src/engine/corners/brandedTypes.ts` 40·80행 근처의 "생성 함수는
`validateCornerContent`…" 서술은 이제 사실과 다르다. **지금의 정식 경로
(`validateCornerResponse`, `lookupCoeffBundle`)에 맞게** 고친다. 주석만,
타입 정의는 건드리지 않는다.

## 증명 — 각각 테스트로

| 무엇 | 어떻게 |
|---|---|
| 훅 필수 | 훅을 **하나씩 뺀** 호출 각각에 `@ts-expect-error` — 빈 결과·ID 해석·원문 채우기·`scopedRecords` 넷. 두 게이트 0 에러면 디렉티브가 실제로 억제 중 |
| 기간 판정 함수가 하나 | 정의가 **한 곳**, 단언 쪽과 ID 해석 쪽이 **둘 다 그것을 부른다** — 보고에 정의 위치와 두 호출 위치를 적는다 |
| 기간 경계 | 끝 시각과 같은 레코드는 **막힘**(끝 배타), 시작 시각과 같은 레코드는 **통과** |
| 재소환 — 같은 커플 | 재소환 표시 + 기간 **이전** → **통과**. 재소환 표시 없이 기간 이전 → **막힘** |
| **재소환 — 다른 커플** | 재소환 표시가 있어도 **막힘** — r39 판단의 실증. 재소환 표시로 뚫을 수 있는 건 같은 커플의 오래된 기록뿐이어야 한다 |
| 응답 쪽도 같다 | 위 재소환 두 경우를 **ID 해석 쪽에서도** 같은 결과로 |
| 맥락 값 | 빈 커플 식별자 / 날짜 아닌 기간 / 뒤집힌 기간 — 각각 **LLM 0회, 저장 0회**, 오류 전파 |
