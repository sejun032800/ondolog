## 5. 묶음마다 지킬 것

### ① 화면 · 연출 = 디자인 결과물 그대로

- 화면 모양과 연출 값(시간 · 이징 · 거리)은 **Nocturne v5 보드 HTML + patch3~8 · 모션 명세 v2 · 웹 데모**를 그대로 쓴다. 디자인 결과물이 RN 구현보다 우선한다
- RN에서 깎인 연출(화면 전환 · 시트 · 탭 이동 · 목록 등장)을 되살린다. 애니메이션은 CSS를 우선한다
- 보드와 다르게 만들어야 하면 결정 기록에 `화면 ID · 무엇이 · 왜`를 남긴다
- 1b 웹뷰 처리(글자 선택 · 길게 누르기 메뉴 · 확대 0)는 모든 새 화면에 그대로 적용한다. 채팅 말풍선 복사는 RN 동작을 따른다

### ② 한글 조합 — 입력 이벤트 방식 (R73-2)

- `useChatComposer`의 300ms 무시 방식을 **지운다**
- `compositionstart` · `compositionupdate` · `compositionend` · `beforeinput`(`inputType`)로 "키보드 앱이 다시 넣는 조합 글자"와 "사용자가 새로 친 글자"를 구분한다
- 시험(이벤트 순서를 흉내 냄)
  - "ㅋㅋ"를 치고 바로 보내면 "ㅋㅋ"가 간다
  - "안녕"을 보내고 **곧바로**(0ms) "ㅎ"를 치면 "ㅎ"가 입력 칸에 남는다
  - 조합 중 엔터 한 번은 한 번만 보내고, 빈 말풍선은 0이다
  - 연속 세 번 보내도 순서와 글자가 맞다
- 삼성 키보드와 Gboard에서 실기기 확인할 항목을 탐방 안내에 넣는다

### ③ 이미지 저장 (F2 · R74-6)

- **저장할 때마다 다른 파일 이름**을 쓴다(예: 날짜와 시각). 재설치한 뒤에도 실패하지 않아야 한다
- **갤러리에 보이게** 저장한다. 1차 플러그인(`@capacitor/filesystem` 등)으로 갤러리 노출이 안 되면 공유 시트로 저장하는 방식으로 두고 결정 기록에 남긴다. 네이티브 손수정은 하지 않는다
- 실패하면 사용자에게 보이는 안내가 있어야 한다. 원인 코드는 로그에만 남기고, 경로와 이름은 남기지 않는다

### ④ 뒤로 가기 (F1 · R71-4)

- **규칙표에 없는 화면의 기본은 "앞 화면으로"다.** 아무 동작도 하지 않는 화면은 0이어야 한다
- 고정 규칙
  - 계정이 생긴 뒤에는 온보딩으로 돌아갈 수 없다
  - **메인 탭의 첫 화면**에서 뒤로 가기를 누르면 앱이 종료된다
  - 다른 탭에서 누르면 메인 탭으로 간다(RN 동작이 다르면 RN을 따르고 결정 기록에 남긴다)
  - 시트나 뷰어가 열려 있으면 그것만 닫는다
  - 이동 직후의 연타는 한 번만 처리한다
- **모든 경로를 표로 만들어 시험한다**(화면 → 뒤로 가기 결과). 새 화면을 추가하면 표에 없을 때 시험이 실패해야 한다

### ⑤ 기능 = RN 행동 그대로

- RN 시험의 **행동 단언**(입력 → 기대 결과)을 Vitest로 옮긴다. 정적 검사 시험(파일 내용 grep 등)은 옮기지 않는다(R32-3)
- 못 옮긴 단언은 이유와 함께 이전표에 적는다
- 결함 재발 0: `51b-` B1~B18과 F1~F3이 처음부터 없어야 한다. B 번호마다 막는 시험 또는 확인 위치를 이전표 옆에 적는다

### ⑥ 묶음 끝마다

- 자동 관문: `web/`에서 `npx tsc --noEmit` · `npx vitest run` · `npm run build` · `npx cap sync android`
- `PROGRESS.md` 제목 아래 한 줄, HANDOFF의 결정 기록 갱신, **커밋할 파일 목록**(묶음별, 이름 하나씩)
- 대화가 끊겨 새 세션이 이어받아도 HANDOFF만 보고 다음 묶음부터 시작할 수 있게 쓴다
