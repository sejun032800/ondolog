## 3. 결함 — 해제 요청을 받은 쪽에 유예 화면이 뜨지 않음

**본 것 (Proteur)**
- 폰 A가 해제를 요청했습니다.
- 폰 A(요청한 쪽)에는 자세한 유예 안내가 떴습니다.
- **폰 B(받은 쪽)에는 탭 화면에 "해제 유예 7일" 줄만 보였고, 전체 화면 안내는 없었습니다.**
- 폰 B에서 설정 → 커플로 들어가면 "A가 요청했다"는 자세한 내용이 나옵니다.

**원래 설계 (HANDOFF 근거)**
- `features/settings/useDissolutionNotice.ts`(74-7 · HANDOFF 3826행 · 4257행 · 4519행)에 이렇게 되어 있습니다: "상대가 개시한 진행 중 해제가 있으면, **탭이 처음 열릴 때와 앱이 다시 보일 때(visibilitychange)** `settings-couple`(H14 상대 쪽 유예 화면)을 한 번 띄운다. 해제 id당 한 번. 내가 개시자면 0. **푸시 알림 없음.**"
- MASTER 3781행: "파기 안전장치 = 7일 유예 + 다단계 확인 + **상대방 통보** + 백업 유도"
- 51- B26 원문: "연결 해제 요청 → **양쪽 유예 화면** → 개시자 취소"

**PE 판단 — 새 기능이 아니라, 이미 있어야 할 동작이 안 된 결함입니다**
- 가장 그럴듯한 원인은 이것입니다. 이 동작은 "탭이 처음 열릴 때"와 "앱이 다시 보일 때"에만 해제 상태를 확인합니다. 폰 B가 **앱을 켜 둔 채 탭 화면에 있는 동안** 해제가 들어오면, 줄(배너)은 실시간으로 바뀌지만 전체 화면을 띄우는 확인은 돌지 않습니다.
- 확인 방법: 폰 B 앱을 껐다 켜거나 바탕으로 보냈다 돌아오면 그때 떠야 합니다. 이번에는 바로 취소해서 확인하지 못했습니다. 위임서에서 시험으로 잡게 합니다.

**PE 제안 — 작은 앱 위임 하나(`90-` 가칭 · LLM 0 · 서버 0 · 마이그레이션 0)**
1. 앱이 켜져 있는 동안 커플 상태가 `dissolving`으로 바뀌어도(실시간 · 새로 읽기) 받은 쪽에 H14 유예 화면을 **한 번** 띄웁니다. 해제 id당 한 번, 개시자는 0인 규칙은 그대로입니다.
2. 시험: 탭에 머문 채로 받기 · 바탕에서 돌아오기 · 앱을 새로 켜기 세 경우 모두 한 번만 뜨고, 개시자 쪽은 0.
3. 다음 C2 같은 사람 확인에서 두 폰으로 한 번 확인.

**PM이 정할 것 — 받은 쪽 폰에 OS 알림(푸시)도 보낼지**
- Proteur 요청은 "알림 한 번"입니다. 앱 안 전체 화면만으로 충분한지, 폰 알림까지 보낼지는 정책 문제입니다(지금 설계는 "푸시 알림 없음").
- PE 의견: 앱을 며칠 안 여는 사람은 7일 유예를 모르고 지나갈 수 있습니다. 그래서 MASTER의 "상대방 통보"를 지키려면 푸시가 있는 편이 맞다고 봅니다. 다만 **잠금 화면에 "해제"라는 말이 그대로 뜨는 것은 민감합니다.** 문구를 중립으로 두기를 권합니다(예: "커플 설정에서 확인할 일이 있어요"). 누르면 H14가 열립니다. 이렇게 하면 서버 쪽(알림 트리거 · `push_daily` kind 하나 추가)이 들어가서 위임이 조금 커집니다.
- PM이 "앱 안 전체 화면만"을 고르면 1번만 하면 됩니다.
