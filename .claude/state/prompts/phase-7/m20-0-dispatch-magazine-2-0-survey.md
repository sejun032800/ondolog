## 왜

- 매거진 2.0에서는 12개 코너와 부속 지면을 모두 만듭니다(R156-2). 지금 실리는 코너는 3개뿐입니다.
- PM이 2.0-A 범위를 정하고, 디자인 세션이 새 지면을 그리려면 다음 세 가지가 먼저 필요합니다.
  1. 저장소에 무엇이 이미 있는지
  2. MASTER 표와 지금 DB가 어디서 다른지
  3. 코너마다 어떤 데이터가 지면에 오는지(데이터 계약)
- 디자인은 이 계약을 보고 그립니다(R156-3 "구현 먼저, 모양은 나중").

## 할 일

### ① 코너 9종 + 부속 구현 현황 표

**대상**
- 코너 9종: 연애 DNA(`love_dna`) · 연애리그(`league_weekly` · `league_monthly`) · 어림짐작(`rough_guess`) · 셋로그(`offline_setlog`) · 인터뷰(`couple_interview`) · 특별 게스트 · 어깨너머 열람실 · 부록 · 협찬
- 부속: 사진 한 장 · 다음 호 예고 · 판권 · 정오 · (기존) 발행 노트의 새 재료 줄

**칸**

| 코너 | 엔진(계산 · 선별) | LLM 프롬프트 · 검사 | DB 표 · RLS | 앱 화면(입력 · 열람) | 렌더 틀 · 측정 표 | 시험 | 상태 한 줄 |
|---|---|---|---|---|---|---|---|

- 칸마다 **파일:줄**(또는 "없음 + 찾아본 곳")을 적습니다.
- 상태 한 줄은 넷 중 하나입니다: "완성" / "엔진만" / "표만" / "없음".
- MASTER 지면 제목과 기획서의 새 지면 제목(「두 사람의 결」 · 「각자의 하루」 · 「우리 사이」 · 「어깨너머」 · 「부록」 · 「협찬」)이 코드 · 틀 어디에 남아 있는지도 적습니다. 바꾸지는 않습니다.

### ② 매거진 제작 탭

- 지금 앱(`web/`)에 MASTER가 말하는 "매거진 제작 탭"(셋로그 · 인터뷰 입력이 들어가는 곳)이 있는지 확인합니다.
- 있으면 경로 · 화면 이름 · 들어 있는 항목을, 없으면 비슷한 자리(매거진 탭 · 서재 · 설정)의 현재 구조를 파일:줄로 적습니다.

### ③ `UNRESOLVED` 목록

- `src/engine/`(및 `supabase/functions/_shared/`)의 `UNRESOLVED` 선언을 모두 표로 만듭니다: 이름 · 파일:줄 · 지금 동작(throw / 기본값) · 그것을 기대하는 시험 이름 · MASTER 16-2 항목과의 짝.

### ⑤ 코너별 데이터 계약(JSON) 초안 — 디자인 묶음이 이걸 보고 그림

**대상**: 코너 9종 + 부속 4종(사진 한 장 · 다음 호 예고 · 판권 · 정오 · 발행 노트 새 줄). 기존 3코너는 지금 렌더러가 받는 모양을 **참고 계약**으로 하나만(`date_archive.json`) 적어 형식을 맞춥니다.

**계약 한 파일의 모양** (예시는 형식만):

```json
{
  "corner_id": "love_dna",
  "page_title": "두 사람의 결",
  "pages": { "min": 2, "max": 2 },
  "publish_condition": "두 사람 모두 성격 데이터가 있을 때",
  "skip_note": "성격 정보가 아직 없어 싣지 않았습니다",
  "llm_calls": 1,
  "fields": [
    { "path": "total", "type": "number", "range": [0, 100], "decimals": 1,
      "source": "engine:dnaScore.total (파일:줄)", "deterministic": true, "required": true },
    { "path": "explain", "type": "string", "max_chars": 120, "tone": "합니다체",
      "source": "llm", "checks": ["말투", "숫자 대조", "금지어"], "required": true }
  ],
  "sample": { "...": "합성 예시 값 — 실제 사람 · 원문 0" },
  "open_questions": ["…"]
}
```

**채울 규칙**
- 필드마다 출처를 적습니다: 엔진 함수(파일:줄) · DB 열 · LLM · 운영 입력. 아직 코드가 없으면 `"source": "TBD: MASTER 17-x"`로 적습니다.
- 결정론 여부, 필수 여부, 길이 상한(글자 수 · 개수), 말투(지면 = 합니다체 · 라벨 = 명사형 · 질문 = 해요체)를 적습니다.
- 반복 블록(타임라인 · 문항 · 메시지 목록)은 **개수 최소 · 최대**를 적습니다. 디자인이 1개 · 최대 개수 두 경우를 그릴 수 있어야 합니다.
- **발행 조건과 빠질 때 발행 노트 문장**(기획서 1절 · 2절 문장 그대로)을 적습니다.
- 사진이 들어가는 칸은 장수 범위 · 가로세로 비율 정보 유무를 적습니다.
- 원문을 싣는 칸(인터뷰 답 · 게스트 글 · 셋로그 한 문장)은 **"원문 불변 · 자르지 않음"** 표시와 입력 상한(앱 · 웹 입력에서 막는 글자 수 제안)을 적습니다.
- 숫자 칸은 "실제 데이터로 거슬러 올라가는 경로"를 적습니다(P4 · 판정 금지).
- 열람실은 **칸마다 20쌍 미만이면 지움 · 활성 100쌍 미만이면 코너 빠짐** 규칙과, 시험용 합성 집계 예시를 적습니다. 실제 커플 데이터는 쓰지 않습니다.
- 협찬은 "협찬" 표기 칸을 필수로 둡니다. 예시는 합성 브랜드명 "예시상점"처럼 실존하지 않는 이름만 씁니다.
- `contracts/README.md`: 공통 규칙(지면 제목 정규식 · 말투 · 잉크 위계 · 넘침은 되받기/실패 R152-2 · 쪽 수 4의 배수 · 본지 36쪽 상한 · 별지)을 기획서 3절에서 옮깁니다.

### ⑥ (따로) iOS 준비 읽기 조사 — F 사전 준비(R155-3 · R155-4)

매거진과 관계없는 항목입니다. 같은 읽기 위임이라 붙였습니다. 결과는 `survey-2-0-0.md` 맨 끝 별도 절에 적습니다.

1. **iOS 프로젝트 유무**: `web/ios/`가 있는지. 없으면 Mac에서 `npx cap add ios` 뒤 무엇이 생기는지(Capacitor 판 기준).
2. **카카오 로그인 방식**: Android에서 어떤 길인지(네이티브 SDK · 웹 리디렉트 · 커스텀 스킴). 그 길이 iOS에서 필요로 하는 것(URL 스킴 · LSApplicationQueriesSchemes · 유니버설 링크 등)을 파일:줄 근거로 적습니다.
3. **푸시**: 지금 FCM 클라이언트 경로(Capacitor 플러그인 이름 · 판)와 iOS에서 필요한 것(APNs 키를 FCM에 올림 · `GoogleService-Info.plist` · 푸시 권한).
4. **센서**: 둘러보기 센서가 iOS에서 `DeviceOrientationEvent.requestPermission()`(사용자 동작 안에서 호출)을 이미 처리하는지 파일:줄로. 없으면 iOS 위임에서 할 일로 적습니다.
5. **사진**: HEIC · 위치 지우기(0-1) 경로가 WKWebView에서도 같은 길인지.
6. **번들 id**: `com.ondolog.app.web`이 `capacitor.config` · Android 설정과 같은지(R155-4).
7. 위 항목마다 **"Mac 없이 지금 할 수 있는 것 / Mac이 와야 하는 것"**을 나눠 적습니다.

설정 파일은 읽기만 하고 고치지 않습니다.
