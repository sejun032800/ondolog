## 1부 — PROGRESS.md

### 1-1. 역할

**PROGRESS는 진행 이력입니다. 현재 상태를 다시 적지 않습니다.** 현재 상태의
원본은 ROADMAP §1이고, PROGRESS는 그것을 가리킵니다.

### 1-2. 머리말

머리말(첫 `## ` 앞)에는 "최종 갱신"·"이전 갱신"으로 시작하는 문단이
여럿 쌓여 있습니다.

- **가장 위(가장 최근) 갱신 문단 하나만 남깁니다.** 바이트 그대로
- **나머지 갱신 문단 전부를 아카이브로 옮깁니다.** 원래 순서대로, 바이트 그대로
- 남긴 문단 바로 뒤에 **아래 한 줄을 추가**합니다(허가된 유일한 추가)

  ```
  > 현재 상태의 원본은 `docs/ONDOLOG_ROADMAP.md` §1이다. 이전 갱신 이력은 `.claude/state/archive/`로 옮긴다.
  ```

`# 진행 상황` 제목과 빈 줄은 그대로 둡니다.

### 1-3. 섹션 분류

| 분류 | 기준 |
|---|---|
| **아카이브 (지정)** | `## 현재 Phase`, `## 막힌 것` — 낡은 상태 서술. PM 결정 |
| **아카이브** | **완료된 Phase(0~5)**의 상세. 상태 서술 중 **ROADMAP §1과 겹치거나 낡은 것** |
| **남김** | **진행 중·대기 Phase(6·7·11)**의 상세 중 **다른 곳에 원본이 없는 것** |

기준 B("다른 곳에 원본이 없는 것")를 그대로 씁니다. 섹션은 통째로만
옮기고, 판단이 애매하면 **남김으로 두고 보고**하세요.

### 1-4. 아카이브 파일

```
.claude/state/archive/progress-20260928.md
```

첫 줄:

```
# PROGRESS 아카이브 — 2026-09-28 정리. 원본 순서 그대로 옮겼다.
```

그 아래 머리말에서 옮긴 갱신 문단들(원래 순서) → 아카이브 섹션들(원래 순서).

"레지스트리 정리" 섹션 **끝의 이 한 줄만** 지웁니다. 허가는 정확히 이 한 줄입니다.

## 4. 쓰는 방식

- **Node로 디스크에서 읽고 씁니다.** `git show`는 비교용으로만
- **파일마다 원래 줄바꿈을 유지**합니다. PROGRESS·HANDOFF는 CRLF,
  인수인계서는 LF입니다 — 쓰기 전에 각 파일의 줄바꿈을 확인하세요
- **새로 넣는 텍스트도 그 파일의 줄바꿈으로** 씁니다
- UTF-8(BOM 없음)
- `Set-Content`·`Out-File`·`>` 리다이렉트 금지

## 5. 검증 — 전부 통과해야 합니다

**하나라도 실패하면 세 파일을 스냅샷에서 복원하고, 새 아카이브 두 개를
지우고, 멈추고 보고하세요.**

### 5-1. PROGRESS 손실 없음

- 스냅샷의 **머리말 갱신 문단과 모든 섹션**이 새 PROGRESS 또는 아카이브
  **둘 중 정확히 한 곳에 바이트 그대로** 있는가
- 새 PROGRESS 머리말이 **"`# 진행 상황` + 빈 줄 + 남긴 갱신 문단 1개 +
  지정한 한 줄"**인가
- 원본에 없던 것은 **지정한 한 줄과 아카이브 첫 줄뿐**인가

### 5-2. HANDOFF 손실 없음

- 스냅샷과 비교해 **사라진 것이 정확히**: `execute_sql` 한 줄 + 두 섹션인가
- 두 섹션이 새 아카이브에 **바이트 그대로** 있는가
- 추가된 것이 **"열린 항목"의 한 행뿐**인가

### 5-3. `execute_sql` 줄의 행방

- HANDOFF에 **0번**
- 인수인계서에 **정확히 1번** (5-2 표 안)

### 5-4. 인수인계서

- 스냅샷과 비교해 **추가된 두 행 외 변경이 없는가**

### 5-5. 줄바꿈

- PROGRESS·HANDOFF·두 아카이브: **맨 LF 0개**
- 인수인계서: 원래 LF 유지 (CR 추가 0)

### 5-6. 포인터 존재

| 포인터 | 확인 |
|---|---|
| ROADMAP §1 | `## 1. 전체 Phase 개요` 제목 + `현재 상태의 원본은 이 표다` 문장 |
| MASTER §10-7-3 | `#### 10-7-3` 제목 + 그 절 안에 `0건` 지침 |
| MASTER §10-7-5 | `#### 10-7-5` 제목 + 그 절 안에 `TYPE_AFFINITY_ENGINE_VERSION` |
| 인수인계서 5-2 | `execute_sql` 행 |

**절 안에 있는지**는 그 제목과 다음 제목 사이를 확인합니다.

검증 스크립트는 `$env:TEMP`에서 돌리고 지웁니다.
