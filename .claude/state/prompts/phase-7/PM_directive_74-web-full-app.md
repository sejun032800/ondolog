## 2. 만드는 방법

| 원칙 | 내용 |
|---|---|
| 서버는 그대로 | RN 앱이 부르던 **같은 RPC·테이블·Storage·Realtime**을 `@supabase/supabase-js`로. 새 마이그레이션이 필요하면 **멈춘다** |
| 로직은 정본에서 | 엔진·유틸·상수·타입은 `@/`로 루트 정본. RN 전용 훅·서비스의 **플랫폼과 무관한 부분**은 가능하면 루트로 옮겨 함께 쓰지 말고(동결 위반) `web/`에 새로 쓰되, RN 시험의 **행동 단언을 Vitest로 옮겨** 같은 행동임을 보인다 |
| 연출은 디자인에서 | 화면 모양·연출 값은 Nocturne 보드 HTML·모션 명세 v2·웹 데모를 **그대로**(디자인 결과물 우선). RN 구현에서 깎인 연출을 되살린다. 화면 전환·시트·탭 이동 연출 포함 |
| 웹 먼저(R70-0) | 웹으로 안 되는 것만 플러그인. 각 플러그인 사용 이유를 결정 기록에 한 줄 |
| 결함 재발 0 | `51b-` B1~B18 · F1~F3이 처음부터 없다 |

## 4. 진행 · 멈춤

- 메인 세션은 안에서 묶음을 나눠 돌린다(나누는 방식은 메인 세션 판단, HANDOFF에 기록). 각 묶음 끝에 **자동 관문만** 돌리고 이어 간다.
- **멈추는 조건 셋(R75-2)**: 절대 규칙에 닿는 일 · 마이그레이션 필요 · 허가 밖 의존성/네이티브 파일. 그 밖은 보수적으로 정하고 **결정 기록**(HANDOFF 한 절)에 한 줄.
- Proteur에게 묻지 않는다. Proteur가 할 일은 끝에서 빌드·설치·탐방뿐이다(커밋은 묶음마다 메인 세션이 파일 목록을 주면 Proteur가 한 번에 — 되돌릴 지점).
