## 배경 (읽고 시작할 것)

직전 시도에서 DEF의 애착 항을 `100 − 불안축`으로 바꿨다. 회피축은 의도대로
빠졌으나, **같은 변경이 불안축 가중을 2배로 키우는 부작용**이 있었다
(`−0.5·불안축` → `−1.0·불안축`). 그 결과 불안축 순계수가 `+0.10`에서
`−0.05`로 부호를 바꿔 두 축이 모두 감점이 됐다.

17-3이 다시 수정돼 **`75 − 불안축/2`** 형태가 됐다. 회피축 자리에 그
중립값을 대입한 것으로, 불안축 계수와 항의 값 범위가 모두 보존된다.

**직전 시도의 코드는 버려졌다.** 저장소는 그 이전 상태이며,
이 작업은 처음부터 다시 한다.

`#2`에서 만든 드리프트 감지 테스트가 이번에도 깨진다. **설계대로다.**

## 가장 중요한 제약 — 불안축이 원래대로 유지돼야 한다

**이번 변경으로 바뀌어야 하는 것은 회피축뿐이다.**

직전 시도가 실패한 지점이 정확히 여기다. DEF 한 칸만 보고 고치면
불안축이 함께 움직인다. 17-3에 **두 축을 열로 놓은 순계수 표**가 있으니
그것을 읽고, 구현 후 스스로 확인하라.

- 애착 항의 **불안축 계수가 −0.5로 유지**되는가
- 항의 **값 범위(평균)** 가 변경 전과 비슷한 수준인가
- EMP의 애착 항은 손대지 않았는가

## EMP는 바뀌면 안 된다

애착 안정성이 **공용 헬퍼**로 계산되어 EMP·DEF 양쪽에서 호출된다.
그 헬퍼를 고치면 EMP도 함께 바뀐다.

- **`computeAttachmentStability` 본문을 고치지 않는다.** EMP는 계속 이것을 쓴다
- DEF 전용 함수를 **분리**한다. 그 함수는 **회피축 인자를 아예 받지 않는
  형태**여야 한다 — 구조적으로 재오염을 막기 위해서다
- **EMP의 산출 결과가 한 비트도 변하지 않아야 한다**

## 2부 — 규준집단 재열거

### 새 버전 파일을 추가한다

- 출력: `src/engine/data/norm-synthetic-v3.json`, `version`은 `synthetic-v3`
- **`v1`과 `v2`를 수정하거나 삭제하지 않는다.** 과거 발행물 재현에 필요하다
- `engineVersions` 맵에 올린 `leagueStats` 버전이 반영돼야 한다

### 애착축 요약을 파일에 추가한다

`v3`부터 규준 파일에 **애착축 요약 섹션**을 넣는다. 에니어그램 코어 9종
요약과 같은 위치·같은 형식이다.

- 회피축 3수준별: 평균·표준편차·최소·최대·표본 수
- 불안축 3수준별: 동일

### 기존 열거 함수를 그대로 쓴다

공식이 바뀌었으므로 **같은 코드가 다른 결과를 낸다** — 그것이 정상이다.
**열거 로직을 다시 짜지 않는다. 채점도 재구현하지 않는다.**

### 드리프트 감지 테스트

- [ ] 대조 대상을 **v3로 갱신**한다
- [ ] **열거를 실제로 재호출**해 비교하는 형태를 유지한다.
      파일끼리 비교하거나 샘플링하는 형태로 바꾸지 않는다
