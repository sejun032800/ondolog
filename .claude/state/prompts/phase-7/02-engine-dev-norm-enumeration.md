## 목표

응답 공간 3,888개를 전수 열거해 규준집단 데이터 파일 `norm-synthetic-v1.json`을
생성하고, 엔진에 백분위 조회 함수를 추가한다.

## 배경 (읽고 시작할 것)

6각 스탯은 에니어그램·애착·빅5를 자체 공식으로 결합한 **합성 지표**라 대응하는
공개 규준이 존재하지 않는다. 대신 응답 공간이 유한하다 — Q1~Q5 각 3지선다(3⁵=243)
× MBTI 16종 = 3,888개. 채점이 전부 결정론적 룩업·산술이므로 **전수 열거로 분포를
정확히 계산할 수 있다. 추정이 아니라 열거다.**

이 작업이 만드는 것은 이후 모든 유저의 스탯이 대조될 기준 분포다.

## 가장 중요한 제약 — 채점 로직을 재구현하지 않는다

**Phase 2에서 만들어진 기존 채점·스탯 함수를 그대로 import해서 열거한다.**

열거용으로 채점을 다시 구현하면, 규준집단이 실제 유저 채점과 **다른 분포**가 된다.
유저는 함수 A로 채점되는데 백분위는 함수 B의 분포에 대고 매겨지는 상태가 되며,
양쪽 다 결정론적이라 테스트는 전부 통과한다. **런타임에 아무 에러도 나지 않고
값만 조용히 틀린다.**

작업 시작 전에 아래를 먼저 하라.

1. `src/engine/` 하위에서 5문항 채점(에니어그램 코어·빅5·애착·스턴버그)과
   6각 스탯 산출을 담당하는 기존 함수를 찾는다
2. **찾은 함수의 경로와 시그니처를 보고한다**
3. 그 함수들만 사용해 열거한다

기존 함수가 없거나, 있어도 문서(Part 10-2 / 17-3)와 어긋나 보이면
**멈추고 보고할 것.** 임의로 새로 짜지 말 것.

생성 스크립트는 `src/engine/` **밖**에 둔다. 엔진은 결과 데이터만 소비한다.

## 백분위 조회 함수는 데이터를 인자로 받는다

**엔진 함수가 `norm-synthetic-v1.json`을 정적 import하지 않는다.** 확정 규칙이다
(Part 10-8-3).

특정 버전 파일을 엔진이 직접 import하면 버전 교체가 코드 변경이 되고,
**과거 버전으로 재계산할 수단이 사라진다.** 3월호에 실린 OVR을 6월에 재현하려는데
그 버전이 코드에서 떨어져 나갔으면 끝이다. `stat_snapshots.inputs.normVersion`을
기록하는 의미가 없어진다.

계수를 `app_config`에서 읽되 호출부가 주입하는 것과 **같은 이유이자 같은 구조다**
(Part 10-7-5). 파일을 고르는 것은 호출부 책임이고, 엔진은 받은 분포로 계산만 한다.

## 규준 데이터에 반드시 포함할 것

### 메타데이터

```
version: "synthetic-v1"
engineVersion: <생성 시점의 엔진 코드 버전>
```

`engineVersion`은 **기존 엔진 버전 소스에서 가져온다.** `stat_snapshots.engine_version`에
쓰이는 값과 같은 출처여야 한다. 코드베이스에서 그 상수를 찾아 사용하고,
**어디서 가져왔는지 보고에 명시할 것.** 찾지 못하면 값을 지어내지 말고 멈추고 보고한다.

> 규준집단은 채점 로직의 산출물이므로 채점이 바뀌면 무효가 된다. 파일에
> 생성 근거가 없으면 이 규준이 어느 채점으로 만들어졌는지 알 수 없다.

### ① 합성값 분포 (주 데이터)

프로파일마다 6각 스탯의 **산술평균**을 구한 값, 3,888개.

**정렬된 배열 전체를 담는다.** 요약 통계만 담지 않는다.
평균·표준편차·분위수도 함께 담는다.

OVR 산출 순서가 아래로 확정됐다(Part 10-8-2).

```
① 6개 스탯 원점수 → ② 6개의 산술평균으로 OVR 원점수(합성값)
  → ③ 규준집단 백분위 변환 → ④ 매핑 테이블로 최종 OVR
```

**백분위를 재는 대상이 이 합성값 분포다.**

### ② 스탯별 분포 (PUS · EMP · ATT · DEF · TAC · REA 각각)

①과 **동일한 형식** — 정렬 배열 3,888개 + 평균·표준편차·분위수.

- 평균은 베이지안 수축의 **사전평균**으로 쓰인다
- 표준편차는 **수축 강도를 정하는 근거**이자 분산 지배 점검의 입력이다.
  이 열거가 그 관측을 만드는 유일한 작업이라, 빠뜨리면 전부 다시 돌려야 한다
- 기각된 스탯별 백분위 방식의 **대조 데이터**로도 남긴다

**①과 ② 둘 다 필요하다. 하나만 있으면 미완이다.**

### ③ 에니어그램 코어 9종별 합성값 요약

코어 1~9 각각의 평균·표준편차·최소·최대·표본 수.

규준집단 자체를 설명하는 데이터이므로 파일 안에 함께 둔다. `actual-v1`로
교체할 때 두 버전의 편향을 바로 대조할 수 있다.

## 원점수 기준으로 열거한다

**수축(shrinkage)을 적용하지 않은 원점수로 분포를 만든다.** 확정 사항이다.

수축의 사전평균이 이 분포에서 나오므로 열거 단계에서 수축을 적용하면 순환이 되고,
수축이 모든 유저에게 동일 강도로 걸리는 한 백분위는 수축 전후가 같다.
`leagueStats.shrinkage`는 `UNRESOLVED` 상태 그대로 두고 건드리지 않는다.

각 응답 조합은 **균등 가중**한다(Part 10-8-1).

## 드리프트 감지 테스트 (필수)

**현재 엔진 함수로 열거를 다시 돌려 `norm-synthetic-v1.json`과 대조하는 테스트를
작성한다.**

`engineVersion` 문자열만으로는 부족하다 — 채점을 고치고 버전 상수를 올리지 않으면
파일은 옛 버전을 주장한 채 조용히 무효가 된다. 이 테스트는 **버전 상수를 올리는
것을 잊어도** 깨진다.

- 열거 순수 함수를 호출해 분포를 다시 계산한다
- 파일의 분포와 비교한다
- 불일치하면 실패한다 — 그 실패가 **"규준집단을 재산출하고 버전을 올려라"**는 신호다

3,888개는 순수 룩업·산술이라 테스트에서 즉시 계산된다. 캐싱하거나 샘플링하지 않는다.

## 점검 두 가지 — 수치만 보고할 것

### ① 분산 지배 점검 (Part 10-8-2)

합성값이 산술평균이므로, 여섯 스탯의 분산이 서로 크게 다르면 **분산이 큰 스탯이
합성값을 지배한다.** 스탯 6종의 표준편차를 나란히 비교할 수 있는 형태로 보고한다.

### ② 에니어그램 코어 9종별 분포 (Part 10-8-2)

6각 스탯이 유형에서 도출되므로 특정 코어가 구조적으로 낮은 값을 받을 수 있고,
백분위 변환은 순위만 보므로 이를 교정하지 못한다. 위 ③ 메타데이터와 같은 수치를
보고에도 포함한다.

> **두 점검 모두 판단은 하지 말 것.** 수치만 보고한다. 평균 전 표준화 도입도,
> 가중치 도입도 마스터 PM 결정이다.

## 완료 기준

- **각 분포 배열의 길이가 정확히 3,888**이다 (합성값 1 + 스탯 6 = 배열 7개)
- `version`이 `synthetic-v1`, `engineVersion`이 기존 엔진 버전 소스에서 왔다
- 에니어그램 코어 9종 요약이 파일에 포함된다
- **재실행 시 바이트 단위로 동일한 파일이 생성된다**
- **드리프트 감지 테스트가 존재하고 통과한다** — 열거를 재호출해 파일과 대조
- 기존 채점·스탯 함수를 재사용했으며, 열거용 채점 재구현이 없다
- 백분위 조회 함수가 **순수 함수이며 규준 데이터를 인자로 받는다.**
  `src/engine/` 안에서 규준 JSON을 정적 import하지 않는다
- 열거 로직이 파일 쓰기와 분리돼 테스트에서 재호출 가능하다
- 기존 테스트 267개 전부 통과

- **평균 전 표준화 도입** — 분산 지배가 확인된 뒤 재검토할 사항이다

- `src/engine/` 하위에서 DB·네트워크·환경변수 접근
- 커밋·푸시, 라이브러리 의존성 추가, 설정 파일 변경
- 문서에 없는 값을 지어내는 것 — 판단이 서지 않으면 **멈추고 물어볼 것**
