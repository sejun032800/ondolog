## 무엇을 하는가

MASTER **§17-0-4의 r44 문단**을 골격에 반영한다. **코너 3종은 만들지 않는다**(3단계).

## 읽을 것 — 원본

`docs/ONDOLOG_MASTER.md` **§17-0-4** — "선언의 세 필드 (확정, r44)"부터 "'판정 로직을
넣을 자리가 없다'의 범위 (확정, r44)"까지. 규격을 옮겨 적지 않았다. 문서가 원본이다.

## 범위 — 넷 (PM)

1. **`scopedRecords`는 한 번만 부른다.** 그 결과를 호출 전 단언과 ID 해석에 같이 넘긴다
2. **`resolveRecordReferences`를 비공개로.** 테스트는 정식 입구
   `resolveDeclaredReferences`로 시험한다
3. **`kind`를 `'message'`·`'photo'`·`'date'` 유니온으로**
4. **`path` 존재 확인 함수를 골격에 둔다.** 선언된 `path`가 그 코너의 LLM 출력
   스키마에 실제로 있는 자리인지를 **선언과 스키마만으로** 판정한다. 코너 테스트는
   3단계에서 이 함수를 부른다

## 완료 기준

- **`scopedRecords`가 정확히 한 번 불리는지를 호출 횟수로 확인**한다(PM). 결과가
  같은지만 보면 두 번 불려도 순수 함수라 통과한다
- `resolveRecordReferences`가 모듈 밖에 공개되지 않는다
- `kind`에 유니온 밖 값을 넣으면 컴파일 오류다
- `path` 존재 확인 함수가 **있는 자리는 통과, 없는 자리(오타)는 실패**로 판정한다
- 기존 테스트가 계속 통과한다. 두 게이트 0 에러, jest 시작 기준선 대비 감소 없음
- `llmClient` 호출 시그니처 **그대로**(3단계 몫)

## 기존 테스트 assertion

이 변경으로 바뀌는 assertion은 고치고, **고친 것마다 이유를 보고**한다. 무관한
변경은 하지 않는다.

## 하지 말 것

- 코너 3종, `LlmRequest`·캐싱 — 3단계
- 시간대 라벨 함수, 입력 조립 — 이번 범위가 아니다
- `[]`로 끝나는 ID 배열 지원
- 테스트에서 브랜드 캐스트·비공개 함수 우회
- 상태 파일 기록 삭제·재편 — HANDOFF에 더할 때는 "열린 항목"이나 새 섹션
- 커밋·푸시, 의존성 추가, 설정 파일 변경
- 문서에 없는 값을 지어내는 것 — 판단이 서지 않으면 **멈추고 물어본다**
