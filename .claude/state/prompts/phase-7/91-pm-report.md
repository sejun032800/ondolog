## 2. PM 결정 1 — 범위 밖 시험 계정 (`test-55-*` ~ `test-70-*` · `test-u2-*`)

**메인 세션이 찾은 것**
- 검증 스크립트 12개와 `render/seed_render_tests.py`가 원격 개발 DB에 시험 계정을 만들고 지우지 않았습니다. HANDOFF에도 "지우지 않음"이라고 적혀 있습니다.
- 이름에 시각이 붙어 있어 허용 목록에 하나씩 적을 수 없습니다.
- 몇 개가 남았는지는 원격을 읽지 않아 모릅니다. 확인 질의 Q1의 `other_test_users`가 그 수입니다.

**PE 제안 — 숫자를 먼저 보고 정하기**
1. **지금 Proteur가 Q1만(읽기 · 숫자만) 돌립니다.** C3 미리 보기 전에 합니다.
2. **0이면** C3을 그대로 진행합니다. 결정할 것이 없어집니다.
3. **1 이상이면** PE는 **실제 커플 시작 전에 지우기**를 권합니다.
   - 이유: 실제 커플과 같은 DB에 남으면 운영 숫자(월요일 점검 · 사용자 수 · 앞으로의 월 생성 대상)가 시험 행으로 흐려집니다.
   - 방법: 작은 위임 `91-b`로 기존 초기화 코어에 **패턴 모드**를 하나 더합니다. 잠금은 네 겹입니다.
     - 이메일이 `test-` + 영숫자 묶음 + `@example.com`인 사용자만(카카오 계정은 example.com일 수 없음)
     - `project=` 잠금 그대로
     - 실제 커플 가입 전에 만든 계정만(만든 날짜 상한을 사람이 넣음)
     - 미리 보기가 기본, 목록 밖 하나라도 있으면 전체 거부
   - 출력은 건수만 냅니다. 시험은 원격 없이 합니다.
   - 범위: LLM 0 · 서버 0 · 마이그레이션 0.

## 4. 90- 진행 중 입력 보호 — PE가 1안으로 답함

메인 세션 확인 결과, **지금 방식은 입력을 지키지 못합니다.**
- H14를 띄우면 경로가 바뀌는데, 화면을 새로 그리는 방식(`App.tsx` `key={location.key}`) 때문에 채팅 입력칸에 친 글이 사라집니다.
- 경로가 바뀔 때 시트를 모두 닫는 규칙(`App.tsx:128` `closeAll`) 때문에 데이트 기록 시트(사진 · 메모)도 닫힙니다.
- 위임서 범위(`useDissolutionNotice` · 커플 상태 쪽)만으로는 고칠 수 없습니다.

**PE 결정: 1안 — "채팅 글 기억 + 시트가 열려 있으면 미룸"**
- 채팅 입력칸의 글을 화면을 떠날 때 **메모리에만** 둡니다(기기 저장 0). 돌아오면 다시 채웁니다.
- 시트가 열려 있으면 H14를 미루고, 시트가 닫힌 첫 순간에 한 번 띄웁니다.
- 범위 밖 파일은 1개(`platform/useChatComposer.ts`)이고 보고에 적습니다.
- **PE가 붙인 조건**
  1. 기억한 글은 **로그아웃 · 계정 전환 · 해제 완료 때 지웁니다.** 다른 계정에 앞사람 글이 보이면 안 됩니다(사생활).
  2. 커플이 바뀌면 이전 글은 버립니다.
  3. 시트뿐 아니라 **전체 화면으로 쓰는 흐름**(있다면)도 같은 규칙으로 미룹니다.
  4. 시험 6번(채팅)에 더해 데이트 기록 시트 중에 해제가 오는 경우(미룸 → 닫은 뒤 1번)를 시험으로 고정합니다.
- 2안("쓰는 중이면 모두 미룸")은 입력칸에 글을 남겨 두면 통보가 계속 미뤄질 수 있습니다. 그러면 "상대방 통보"(R153-2)의 뜻과 어긋나서 고르지 않았습니다.
- PM이 다르게 보면 90- 보고 때 되돌릴 수 있습니다. 범위가 작습니다.
