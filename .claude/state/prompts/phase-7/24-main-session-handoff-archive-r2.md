## 1. 섹션 분류 — 기준 B

HANDOFF를 **`## ` 제목 단위 섹션**으로 나눕니다.

| 분류 | 기준 |
|---|---|
| **남김** | **다른 곳에 원본이 없는 것**이 들어 있다 |
| **아카이브** | 들어 있는 것이 전부 다른 곳에 원본이 있거나, 완료돼 더 쓰일 곳이 없다 |

### "다른 곳에 원본이 있다"의 뜻

HANDOFF의 계약 서술은 대개 **원본의 사본**입니다. 원본이 바뀌면 HANDOFF만
낡은 채 남고, 사본이 두 곳에 있으면 어긋납니다.

| HANDOFF에 적힌 것 | 원본 |
|---|---|
| 모듈 경로 계약 | `__tests__/engine/cornerPipelineStaticRules.test.ts`의 `MODULE` 상수 (r21 규정) |
| 발행 시 테마 복사, 테마 잠금 | `docs/ONDOLOG_SCHEMA.md` §9-C-7 · §9-C-8 |
| 021 적용 결과 | SCHEMA §9-C + `scripts/db/verify_021_theme_trigger.sql` |
| `activityScore` · `chatDelta` | MASTER 10-7 · 17-2 + `src/engine/constants/unresolved.ts` |
| 코너 파이프라인 규격 | MASTER 17-0 |
| 인터페이스·시그니처 | **그 코드 자체** |

위는 예시입니다. **각 섹션마다 "여기에만 있는 것이 무엇인가"를 판단**하세요.
원본이 있으면 아카이브, 여기에만 있는 것이 있으면 남김입니다.

**섹션은 통째로만 옮깁니다.** 섹션 안을 잘라내거나 요약·재작성하지 않습니다.
여기에만 있는 것이 한 줄이라도 있으면 그 섹션은 남김입니다.

## 4. 검증 — 셋 전부 통과해야 합니다

**셋 중 하나라도 실패하면** HANDOFF를 스냅샷에서 복원하고, 아카이브를
지우고, 멈추고 보고하세요.

### 4-1. 손실 없음

원본(스냅샷)의 모든 섹션이 **새 HANDOFF 또는 아카이브 둘 중 정확히 한
곳에 바이트 그대로** 있어야 합니다.

```
1. 스냅샷·새 HANDOFF·아카이브를 각각 `## ` 기준으로 섹션 배열로 나눈다
2. 스냅샷의 각 섹션(머리말 포함)이 두 파일 중 정확히 한 곳에 동일한 문자열로 있는가
3. 두 파일에 스냅샷에 없던 섹션이 없는가
   — 허용되는 추가: 새 HANDOFF의 "열린 항목" 섹션, 아카이브 첫 줄
```

**"열린 항목" 섹션은 이 검증에서 제외합니다.** 새로 생긴 유일한 내용이라
"원본의 모든 섹션이 정확히 한 곳에"에 걸리지 않습니다. 다만 **제외되는
것이 정확히 그 한 섹션뿐인지**는 확인하세요.

### 4-2. 줄바꿈

두 파일 모두 **맨 LF(앞에 CR이 없는 LF)가 0개**여야 합니다.

### 4-3. 포인터 존재 — 이동 직후

"열린 항목" 표의 원본 열이 **실제로 존재하는지** 스크립트로 확인합니다.
없는 곳을 가리키는 포인터는 없는 것보다 나쁩니다 — 읽는 사람이 원본이
있다고 믿고 찾아가서 빈손으로 돌아옵니다.

| 포인터 | 확인 방법 |
|---|---|
| 파일 경로 | 파일이 존재 |
| `§9-C-7` · `§9-C-8` | SCHEMA에 `### 9-C-7` · `### 9-C-8`로 시작하는 제목이 존재 |
| MASTER `17-0` | MASTER에 `### 17-0`으로 시작하는 제목이 존재 |
| MASTER `§17-0-3` 규칙 F | MASTER에 `#### 17-0-3`으로 시작하는 제목이 존재하고, **그 절 안에 `규칙 F` 또는 `F.` 항목이 존재** |
| `MODULE` 상수 셋 | 테스트 파일에 `const LLM_CALL_MODULE` · `const APP_CONFIG_LOOKUP_MODULE` · `APPROVED_BRAND_CONSTRUCTOR_MODULES` 정의가 존재 |
| `tsconfig.json`의 `include` | 파일에 `"include"` 키가 존재 |

**하나라도 없으면 되돌리고 멈추세요.**

검증 스크립트는 **저장소에 남기지 마세요.** 임시 디렉터리에서 돌리고 지웁니다.
