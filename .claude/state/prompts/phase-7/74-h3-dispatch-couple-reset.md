## 1. 할 일 — `resetTestAccount.ts`에 커플 모드 추가

기존 단독 모드(이메일 1개)는 **동작과 시험을 그대로 둔다.** 이메일을 **2개** 주면 커플 모드로 동작한다.

| 항목 | 조건 |
|---|---|
| 입력 | 이메일 2개를 인자로. 코드 · 저장소 · 출력에 이메일 0 |
| 대상 판정 | 두 이메일의 인증 사용자가 **정확히 2명**이고, 두 사람이 **서로가 유일한 상대**인 같은 커플 행(상태 무관 — active · pending 모두)에 속할 때만 지운다 |
| 지우는 순서 | Storage({couple_id}/… 경로의 entries · messages · stories · magazine 등, avatars의 두 사용자 경로) → 커플 행(cascade로 13개 표) → 두 사용자의 개인 표(profiles cascade) → 두 인증 사용자 |
| **발행 호** | 그 커플에 발행 호(`issues` 등)가 있으면 **기본은 거부**하고 이유 한 줄만 출력한다. **`--with-issues`를 붙였을 때만** 그 커플의 호와 매거진 Storage 파일(magazine · magazine-print)까지 지운다 |
| 미리 보기 | 기본은 미리 보기(아무것도 지우지 않음). 커플 모드 미리 보기에는 **호 수와 매거진 파일 수**가 표로 나와야 한다. 실제 삭제는 `--apply` 명시 |
| 거부(아무것도 지우지 않고 이유 한 줄) | · 어느 한쪽이 **다른 상대**와 연결됨 · 이메일에 걸리는 사용자가 정확히 2명이 아님 · 개발 프로젝트가 아님 · (플래그 없이) 발행 호 있음 |
| 금지 | 서버 함수 · 마이그레이션 0 · `execute_dissolution` · `apply_retention_policy` · `run_due_dissolutions` 호출 0(R34-3) · `demo_responses` 0 · `db push` 0 |
| 출력 | "표 이름: 지운(지울) 행 수" · "Storage: 파일 수"만. 이메일 · id · 키 · 주소 0. h2에서 넣은 "서비스 키가 아니에요" 안내 유지 |
| 시험(원격 없음, 가짜 클라이언트) | 기존 단독 모드 시험 유지 + 커플 모드: 거부 조건별 각 1건 · `--with-issues` 유무에 따른 발행 호 처리 · 미리 보기가 지우지 않음 · 서로가 유일한 상대일 때만 진행 |
| HANDOFF | Proteur가 칠 명령을 짧은 한 줄씩(R71-2): 미리 보기(이메일 2개) · `--apply` · `--with-issues --apply`. 환경 변수는 h2에서 바꾼 `Read-Host -AsSecureString` 방식 그대로. **잠금 대기 목록(R76-9)에 "커플 모드 포함"을 한 줄 추가** |
