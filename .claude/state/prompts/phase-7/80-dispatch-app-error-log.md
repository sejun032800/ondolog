## 1단계 — 서버 (`80-m1`)

- **집계표 하나**(행 = 묶음, 사건 하나하나가 아님)

  - 같은 (날짜 · 화면 · 종류 · 버전 · 플랫폼)이면 건수 +1
  - **사용자 id · 커플 id · 기기 id · IP · 메시지 · 스택 · 자유 글 칸 0**
- **넣기는 RPC 하나로만**

  - 자유 글을 받지 않으므로 내용이 섞일 길 0

## 2단계 — 앱

| 잡는 곳 | 오류 종류(예) |
|---|---|
| 처리 안 된 예외 · Promise 거부(`window` 이벤트) | `uncaught` · `unhandled_rejection` |
| React 오류 경계(화면이 통째로 깨질 때 — 기존 경계가 없으면 화면 단위로 하나) | `render_crash` |
| 이미 있는 실패 처리 지점 중 **조용히 삼키는 곳**: 사진 업로드 실패 · 큐 재시도 한계 · 푸시 등록 실패 · 기기 저장 실패 · 로그인 복귀 실패 | `upload_fail` · `queue_giveup` · `push_register_fail` · `cache_fail` · `auth_return_fail` |

- 화면 이름은 **라우트 이름**(허용 목록과 같은 값) · 오류 종류는 위 고정 값 · **오류 메시지 · 스택은 보내지 않음**
- **기기당 상한**: 같은 묶음은 기기에서 **1시간에 1번만** 보냄(나머지는 기기에서 세어 다음 전송에 합침 — 건수만) · 전체 1시간 상한(예: 30)
- 오프라인이면 기기 저장에 건수만 모아 두었다가 다음 온라인 때 보냄. 새 저장 범주는 로그아웃 · 계정 전환 삭제 규칙에 포함(개인정보는 아니지만 규칙을 맞춤)
- 기록 자체가 실패해도 앱 동작에 영향 0(삼키기) · 기록 실패를 다시 기록하지 않음(무한 반복 0)
- **Vitest**:
  - 각 잡는 곳 → RPC 1회
  - 메시지 · 스택 · 이름 · id가 **보내는 값에 0**(인자 단언)
  - 1시간 상한 · 오프라인 모음 · 기록 실패 무해 · 반복 0
