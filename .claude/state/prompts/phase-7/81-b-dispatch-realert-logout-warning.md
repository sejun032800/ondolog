## 왜

1. **조용히 갈아 끼움**: 폰 확인 3차에서, 읽지 않은 온도록 알림이 서랍에 남아 있으면 새 알림이 **소리 · 팝업 없이** 내용만 바뀜(R109-2 같은 태그). 오전 알림을 안 읽고 두면 저녁 메시지도 조용히 지나감 — 커플 앱에서는 치명적(R118-4)
2. **말없이 지움**: 81-에서 보내지 못한 메시지(대기열 · 보존 원본)는 로그아웃 때 지우기로 함(R118-2). 지우는 것은 맞지만 **사용자에게 알리고** 지움(R118-3)

## 1. 다시 울림 규칙 (R118-4 · 서버 쪽)

| 규칙 | 내용 |
|---|---|
| 묶음 | **받는 사람 · 커플 · 종류**(메시지 / 변경 안내)별 |
| 10분 안 연타 | 직전 같은 묶음 알림 뒤 **10분 안**이면 지금처럼 같은 알림으로 **조용히 갈아 끼움**(R109-2 유지) |
| 10분 넘은 공백 뒤 첫 알림 | **소리 · 팝업으로 다시 울림** |
| 서랍 | 하나로 모이는 것은 그대로여도 됨(울림만 보장). 구현 방식에 따라 서랍에 둘이 되면 결정 기록에 |
| iOS | 같은 규칙이 APNs에서도 되도록 **서버가 정함**(`apns-collapse-id` · `thread-id` 등 78-에 이미 싣는 값과 맞춤) — 동작 확인은 Mac 뒤 목록에 한 줄 |
| 변경 안내 | 날짜 · 닉네임은 드물다. "직전 시각"을 기존 행에서 얻을 수 없으면 **변경 안내는 매번 울림**으로 단순화해도 됨 — 결정 기록에 |

- **구현은 메인 세션 판단**. 후보 예: 직전 시각을 기존 행(예: 메시지의 보낸 시각)에서 계산 → 공백이 10분을 넘으면 새 태그(또는 다시 울림 표시)로 보냄
- **함수 시험(가짜 FCM)**:
  - 10분 안 연타 3건 → 조용(같은 태그 · 다시 울림 표시 0)
  - 10분 1초 뒤 → 울림
  - 10분 정확히 경계 · 시계 주입(실제 시계 0 — 76-j 교훈)
  - 메시지와 변경 안내 묶음이 서로 영향 0
  - 기존 78- 시험 회귀 0(본문 규칙 · 원문 0 · 설정 끔 0 · 잘못된 토큰 정리)

## 2. 로그아웃 경고 (R118-3)

- 로그아웃 확인 창: 보내지 못한 것이 **있으면** 한 줄 더
  - **"아직 보내지 못한 메시지 {n}개가 있어요. 로그아웃하면 이 폰에서 사라져요."**(문구 그대로)
  - n = 글 대기열 + 사진 대기열 + 81- 보존 원본(사진도 "메시지"로 셈 — 다르게 세야 하면 결정 기록에)
  - 없으면 지금 문장 그대로
- **계정 전환**: 다른 경로(로그아웃 없이 다른 계정으로 들어가는 길)가 있는지 확인. 있으면 같은 확인을 거치게 하고, 없으면 "로그아웃만이 길"이라고 결정 기록에
- 탈퇴 요청 · 해제 요청은 이번 범위 밖(대기열 규칙이 다름 — 확인만 하고 보고)
- **Vitest**: n=0 → 기존 문장 · n=1 · n=3(글 2 + 사진 1) → 문장과 숫자 · 취소하면 대기열 그대로 · 확인하면 기존 삭제 규칙대로
