## 범위 A — 운영자 경로 (M2-b)

`scripts/ops/` 아래 **명령 두 개**로 나눈다.

| 명령 | 하는 일 |
|---|---|
| **생성** | P0 초안 행(`publish_mode = 'compressed'`, 기간은 운영자 인수) → P1 입력 조립(기존) → 코너 3종 → 검증(기존 골격 그대로) → 원문 채우기 → 저장 → P7 미디어 복제. 결과를 로컬 파일로 남긴다(코너별 상태·제외 건수·추정 토큰·복제 건수) |
| **발행** | `fn_publish_issue` 한 번. **정상 흐름에서는 조판(`55-`) 뒤에 부른다** — 이번에는 M2-e 실증에만 쓴다. 17-0-10-E: 미디어 복제 완료는 함수를 부르기 **전에** 확인한다(SQL 함수는 content 안의 경로를 읽지 않는다) |

### 지켜야 할 것

1. **샘플 출력 모드(R16-2)가 기본이다.**
   - 코너의 LLM 응답 자리에 **LLM 출력 스키마를 만족하는 샘플 JSON**을 넣어 **실제 검증기를 고치지 않고 통과**시킨다
   - ID 참조는 그 실행의 입력에서 와야 한다. 고정 파일이든 생성기든 방법은 내부 결정이다
   - **실제 호출 모드는 이번에 열지 않는다.** 모델 식별자가 `tbd`이면 생성이 돌지 않는 기존 fail-closed(17-0-10-H)를 그대로 둔다. `app_config`의 모델 값을 채우지 않고, 검사를 지우지 않는다. **실제 호출 경로를 부르는 인수도 만들지 않는다**
   - 샘플 모드가 그 fail-closed 검사를 지워야만 돌 수 있는 구조면 **멈추고 그 지점을 보고한다**
   - **실제 API 호출 0회**
2. **샘플 모드는 시험 커플에만 돈다.** 커플 ID를 인수로 받고, 시험 표시(R13-7 — 이름에 `test`)가 없으면 거부한다. 어느 열의 이름을 볼지는 내부 결정이다
3. **경로 함수는 하나.** `PhotoRef.path`는 입력 조립에서 정한 목적지 경로다(17-0-10-D). 입력 조립과 P7이 같은 함수를 부른다. **검증된 content를 나중에 고치지 않는다**
4. **R20-1 — 빈 문자열 본문.** `''`는 공백뿐인 본문과 같이 빼고 `trivialMessages`로 센다. 입력 조립 전체를 실패시키지 않는다(`inputAssembly.ts`의 본문 읽기). **DB 제약은 더하지 않는다.**
   시험: 빈 문자열 하나가 섞여도 입력 조립이 성공하고 `trivialMessages`가 1 늘어난다
5. **R20-2 — 안전 정지.** 기준을 넘긴 코너는 **`pending`으로 남기고**, 운영 경보 **`usage_over`**를 남긴다 — `detail`에 `stage: 'input_halt'`·코너 종류·추정 토큰·기준값(**숫자와 ID만, 원문 없음**). enum·경보 종류·마이그레이션은 늘리지 않는다.
   시험: 기준을 넘긴 코너 → 호출 0건 · `pending` · 경보 1건 · **그 호의 발행 명령이 거부됨**
6. **service_role 키는 `scripts/ops`에서만 환경변수로 읽는다.** 이름은 `ONDOLOG_SUPABASE_URL`·`ONDOLOG_SUPABASE_SERVICE_ROLE_KEY`(개발 프로젝트 `ondolog`의 값). `src/`·`app/`에서 import되지 않는다(절대 규칙 7). **값은 화면·파일·로그·보고 어디에도 쓰지 않는다.** 접속 대상이 개발 프로젝트가 아니면 멈추는 확인을 둔다(방법은 내부 결정)
7. **앱 채팅 전송이 빈 본문·공백뿐인 본문을 막는지 읽고 보고만 한다**(파일·행). 고치지 않는다(막지 않으면 U4에서 막는다)

### 시험 데이터

- 원격 개발 DB·스토리지에 쓰는 시험 데이터(커플·계정·채팅·데이트·사진 원본)는 **이름에 `test`를 넣는다**(R13-7)
- **실제 사람의 대화를 쓰지 않는다.** `50-` 합성 데이터셋을 쓸 수 있다
