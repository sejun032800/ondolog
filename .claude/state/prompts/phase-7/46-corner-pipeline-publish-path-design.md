## 이번 작업은 설계 보고까지다

**코드를 쓰지 않는다.** 조사하고 설계를 보고한 뒤 **멈춘다.** 구현은 설계가 승인된 뒤 별도 지시로 한다.

**PM이 설계부터 받는 이유**
- 항목이 11개이고, 마이그레이션(테마 복사 트리거, `skip_reason` CHECK)과 사람 작업(Deno import map, 비밀값)이 섞여 있다
- 처음으로 **실제 DB와 외부 API(배치)**를 만나는 단계라, 잘못 짰을 때 되돌리는 비용이 크다
- 호 전체 중단, `last_featured_at` 갱신, 미디어 복제가 모두 **"발행이 언제 성공한 것인가"**라는 하나의 상태 정의에 걸려 있다. 이것을 먼저 정해야 나머지가 맞물린다

## 보고할 것 — PM 요구 그대로

1. **호 하나의 발행 흐름과 상태 전이.** 생성 → 배치 제출 → 결과 수신 → 검증·저장 → 미디어 복제·테마 복사
   → 발행 확정. 각 단계가 실패하면 **어디로 되돌아가는지, 무엇이 남는지**
2. **"발행 성공"의 정의 한 줄.** `last_featured_at` 갱신과 r48의 중단 처리가 이 정의에 매달린다
3. **ROADMAP r10의 발행 경로 항목 각각이 1의 어느 단계에 붙는지.** Phase 7 행에 적힌 항목 전부
4. **마이그레이션이 필요한 것과 그 SCHEMA 절**(§9-C-7 테마 복사, `skip_reason` CHECK)
5. **사람 작업 목록.** import map, 비밀값, 배치 API 키 등
6. **문서에 없는 값 목록.** **채팅 입력량 상한은 실측 방법만 제안하고 값은 정하지 않는다**

**확인 하나 (PM 지시, 읽기만):** 17-4 코너가 대화의 출처 표기로 **첫 턴 메시지의 것**을 실제로 고르는지
(MASTER §17-0-8, r51 §17-0-9-F). 고르는 코드의 위치와 그것을 시험하는 테스트가 있는지 보고한다.
고르지 않으면 고치지 말고 그대로 보고한다.
