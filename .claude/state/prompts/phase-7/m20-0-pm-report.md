## 2. 가장 큰 사실 두 가지

### (1) 기획서가 전제한 "이미 계산되는 채팅 지표"가 없습니다

- 기획서 2절은 `chatDelta` v0를 "이미 결정론으로 계산되는 값(다정한 발화 비율 · 왕복 리듬 · 티키타카 성공률)"으로 만든다고 했습니다. **셋 다 함수로 존재하지 않습니다.**
- `messages.warmth_score`는 늘 비어 있습니다. 채팅 태깅에 LLM 코드가 없기 때문입니다(R124-2).
- 결정론 채팅 계산은 **사람별 하루 메시지 수뿐**입니다. MASTER 17-2는 양(volume)을 `chatDelta` 입력으로 쓰는 것을 금지합니다.
- 같은 지표에 기대는 것: DNA v0 · 리그 실측 항목 · 어림짐작 4~7번.
- `shrinkage`: 사전 평균 · 분산은 규준 파일(3,888 프로파일)에 있습니다. 관측 쪽(채팅으로 갱신되는 스탯)은 없습니다 → 반쯤 준비.

**PE 의견**
- 2.0-A 맨 앞에 **공용 "채팅 지표" 엔진**을 둡니다. LLM 0 · 결정론입니다.
- 메시지의 보낸 사람 · 시각 · 이모지만으로 셀 수 있는 것부터 만듭니다.
  - 답장 간격 분포(왕복 리듬)
  - 주고받기 비율(티키타카 — 같은 사람이 연속으로 보내지 않고 번갈아 오가는 비율)
  - 먼저 말 거는 쪽
  - 이모지 비율
  - 가장 말이 많았던 날
- 이것들은 "양"이 아니라 **모양**이라서 MASTER 17-2 금지에 걸리지 않는다고 봅니다. 해석은 PM이 확인해 주세요.
- **다정한 발화 비율**은 태깅(LLM)이 있어야 하므로 v0에서 뺍니다.
  - **`chatDelta` v0 = 결정론 지표 2개(왕복 리듬 · 주고받기 비율)로만** 만듭니다.
  - 다정 비율은 태깅이 생길 때 v1로 넣습니다.
  - v0 숫자는 메인 세션이 2.0-A에서 안을 내고, PM이 숫자를 보고 승인합니다(R156-6).
- 지표 엔진 하나로 DNA · 리그 실측 · 어림짐작 4~7번이 함께 풀립니다.

### (2) iOS 푸시가 지금 연결 방식으로는 동작하지 않습니다

- iOS에서 `@capacitor/push-notifications`는 **APNs 토큰**을 돌려줍니다. 그런데 서버는 **FCM V1**로 보냅니다(`pushSend.ts`).
- 그래서 iOS에는 APNs 토큰을 FCM 토큰으로 바꾸는 단계가 필요합니다. 길은 둘입니다.
  - (가) AppDelegate 코드 + Firebase iOS SDK(네이티브)
  - (나) Firebase Capacitor 플러그인(새 npm 의존성)
- 어느 쪽이든 **새 의존성 승인이 필요**합니다.

**PE 의견**
- **(가) Capacitor 공식 안내 길**을 권합니다. 앱 JS 쪽 푸시 플러그인과 서버는 그대로 두고, 네이티브 쪽에만 Firebase Messaging을 붙입니다.
- 결정과 승인은 Mac이 온 뒤의 iOS 위임 때 합니다. Proteur가 지금 할 F 준비(가입 · APNs 키 · `GoogleService-Info.plist`)는 바뀌지 않습니다.
- 그 밖의 iOS 항목은 좋은 소식입니다.
  - 카카오 로그인은 Supabase 웹 OAuth 리디렉트라서 iOS에는 URL 스킴만 필요합니다.
  - 센서 권한은 이미 처리되어 있습니다(`useSkyOrientation.ts:70-86`).
  - HEIC · 위치 지우기는 같은 JS 길을 씁니다.

## 3. 현황 요약

- **완성된 새 코너 0.** DNA · 리그는 엔진만 있습니다. 발행 노트는 지금 지면만 있고, 새 재료 줄은 없습니다. 나머지 10개(코너 7 · 부속 3)는 없습니다.
- 코너 생성 · 저장 스키마 · 지면 제목 · 렌더러가 모두 기존 3코너만 다룹니다(`generateIssue.ts:72` · `cornerTitles.ts:18` · `compose.py:39`). 새 지면 제목은 enum 밖 어디에도 없습니다.
- **가장 큰 빈 곳 셋**
  1. 참여형 입력 전부: 인터뷰 · 게스트 표 · 셋로그 enum · 게스트 웹 · 제작 탭
  2. 채팅 지표(위 §2-1)
  3. 렌더러: 새 틀 · 측정 표 · 쪽 수 규칙(4의 배수 · 36쪽) · 리그 별지
- **제작 탭 없음.** 매거진 탭은 서재뿐이고, "제작 현황 →" 링크는 일부러 빼 두었습니다(`LibraryView.tsx:6`). 디자인 시안은 있습니다: D02 · D03 제작 현황 · G01~G04 인터뷰 · G05~G06 셋로그 · G07~G11 게스트(`docs/design/nocturne/screens/`).
- **스키마**
  - 없음: 인터뷰 3표 · 게스트 2표 · `sponsor_slots` · 열람실 집계 표 · DNA 계수 키
  - 다름: 셋로그 — `entry_type`에 `setlog`가 없습니다(`002_enums.sql:10`). 필요한 열은 있습니다
  - 같음: `dna_scores` · `stat_snapshots` · `match_reports` · `daily_temperature`(읽기 전용 RLS)
- **`UNRESOLVED`**: 3키(`unresolved.ts:50-63`) = MASTER 16-2. `chatDelta`는 throw하고 시험 3곳이 그것을 기대합니다. `shrinkage`는 등록만 되어 있고 부르는 코드가 없습니다.
