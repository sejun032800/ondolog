## 왜 (Proteur 녹화 판독, PE)

- 채팅 시험 화면에 들어가려고 첫 화면 왼쪽 위를 길게 누르자, **앱 글자가 웹 페이지처럼 선택되고 Android 텍스트 메뉴**(복사 · 모두 선택 · 공유 · 웹 검색 · 앱 관리)가 떴습니다. 녹화 0:33~0:35입니다. 채팅 시험 화면은 열리지 않았습니다.
- 앱은 이렇게 동작하지 않습니다. **"웹뷰라서 티가 나는" 동작은 관문 G1("앱다운 손맛")을 떨어뜨리는 결함**입니다. 이 화면 하나가 아니라 앱 전체에 해당합니다.

## 할 일

| # | 할 일 | 조건 |
|---|---|---|
| ① | **글자 선택 · 길게 누르기 메뉴 끄기(앱 전체)** | · 앱 루트에 `user-select: none`(`-webkit-` 포함) · `-webkit-touch-callout: none` · `-webkit-tap-highlight-color: transparent`<br>· **입력 칸(`input` · `textarea` · `[contenteditable]`)은 예외**로, 선택 · 붙여넣기가 그대로 되어야 한다<br>· 입력 칸 밖에서 `contextmenu`를 막는다<br>· 이미지 · 링크는 끌기(drag)와 길게 눌러 저장하는 메뉴가 뜨지 않게 한다 |
| ② | **확대 · 튕김 끄기** | · 두 손가락 확대와 두 번 눌러 확대가 안 되게 한다(`viewport` · `touch-action`)<br>· 화면 끝에서 당겼을 때 웹 특유의 튕김이나 당겨서 새로고침 효과가 나지 않게 한다(`overscroll-behavior`). 단, **의도한 스크롤 영역(채팅 목록 등)의 스크롤은 그대로** 되어야 한다 |
| ③ | **채팅 시험 화면 들어가는 길 바꾸기** | 보이지 않는 칸을 길게 누르는 방식은 ①과 부딪히고 찾기도 어렵다. **`build:trial` 빌드에서만** 첫 화면에 작게 보이는 "채팅 시험" 버튼으로 바꾼다. 운영 빌드에는 버튼이 없어야 한다(시험으로 확인) |
| ④ | **같은 종류를 더 찾아 목록으로** | 웹뷰라서 티가 날 수 있는 동작을 더 찾아 **고친 것 / 고칠 수 없는 것**으로 나눠 보고한다. 예: 버튼을 누를 때 생기는 파란 테두리 · 포커스 링, 스크롤바, 시스템 글자 크기를 키웠을 때 레이아웃이 깨지는지, 가로 회전. 웹만으로 안 되고 네이티브 설정이 필요한 것(R70-0)은 **고치지 말고 이유와 함께 목록에만** 넣는다<br>· **목록에 반드시 넣을 두 줄(PM)**:<br>  (가) "채팅 메시지 길게 눌러 복사 → `75-` 정식 채팅에서 앱이 직접 그리는 메뉴로." 1b에서는 만들지 않는다<br>  (나) **시스템 글자 크기 최대일 때 깨지는 화면 목록**(화면 · 깨지는 모양). 정책은 "시스템 크기를 따르되 상한을 둔다"이고 상한 값은 디자인이 정하므로, 1b에서는 **고치지 않고 목록만** 낸다. 확인 방법(실기기 설정 경로 또는 웹뷰 글자 배율 흉내)도 함께 적는다 |

## 지켜야 할 것

- 웹 데모의 연출 값(이징 · 시간 · 블러)은 바꾸지 않는다
- 입력 칸의 동작(커서 · 선택 · 붙여넣기 · 한글 조합)은 지금과 같아야 한다
- 시험 파일은 `*.vitest.ts(x)`로만 짓는다(R70-3)
- 커밋 · 빌드 · 설치는 사람이 한다

## 시험 (행동으로)

- 운영 빌드 설정에서 "채팅 시험" 버튼 0 · 시험 빌드 설정에서 1
- 입력 칸 밖에서 `contextmenu` 이벤트가 막힘 · 입력 칸 안에서는 막히지 않음
