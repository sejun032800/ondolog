## 목표

기존 열거 순수 함수를 호출해 **애착 회피축 원점수의 실제 분포를 집계하는
진단 스크립트**를 만들고, 결과를 보고한다.

## 이 작업은 아무것도 바꾸지 않는다

**`src/engine/` 아래 어떤 파일도 만들거나 고치지 않는다.**
공식도, 규준집단 파일도, 축 정의도 건드리지 않는다.

만드는 것은 **조회 전용 스크립트 하나와 그 출력**뿐이다.
기존 `scripts/norm/attachment-diagnostic.ts`와 같은 성격의 작업이다.

## 스크립트는 커밋 대상이다

원인이 밝혀져 축 정의를 정정하면 **같은 스크립트로 전후를 비교**해야 한다.
재실행 가능한 형태로 남긴다. 실행 방법을 보고에 명시할 것.

## 배경 (읽고 시작할 것)

문서는 회피축을 `Q5 응답 → {A: 20, B: 50, C: 85}`로 정의한다. 세 수준이
같은 수로 나오는 전수 열거라면 평균은 `51.666667`이어야 한다.

그런데 실측에서 두 가지가 어긋난다.

```
평균 초과 : 역산된 실제 평균이 약 52.96 (공칭 51.667보다 +1.30)
폭   초과 : 역산된 유효 폭이 약 66.22 (공칭 65보다 +1.22)
```

**두 초과의 크기가 비슷하다는 점이 중요하다.** 단일 상수가 모든 값에
균등하게 더해지면 평균은 오르지만 **폭은 변하지 않는다.** 폭까지 커졌다는
것은 보정이 수준별로 다르게 걸린다는 뜻이다.

빅5는 이미 다른 문항의 교차 보정을 받는 것이 확인돼 있어, 회피축에도
같은 형태가 있을 개연성이 있다.

**이 진단은 그 여부와 형태를 확정하기 위한 것이다.**

## 입력

- 개발 환경: Windows / PowerShell
- `scripts/norm/` 이하에 열거 순수 함수와 기존 애착축 진단 스크립트가 있다

## 가장 중요한 제약 — 채점을 재구현하지 않는다

**`#2`·`#6`에서 쓴 열거 순수 함수와 기존 채점 함수를 그대로 호출한다.**

집계용으로 축 판정이나 채점을 다시 짜면, 진단 수치가 실제 규준집단과 다른
계산에서 나온다. **그러면 이 진단이 찾으려는 바로 그 차이가 사라진다** —
문서 정의대로 다시 구현하면 당연히 문서와 일치하는 값이 나오기 때문이다.

착수 전에 **재사용할 함수의 경로와 시그니처를 보고할 것.**

## 산출할 집계 — 둘

전수 열거 3,888개 전부를 대상으로 한다.

### ① `attachAvoidance` 전체 평균

3,888개의 산술평균. **소수점 6자리 이상**으로 보고한다.

### ② Q5 응답별 `attachAvoidance` 값 빈도표

Q5 = A / B / C 각각(각 1,296개)에 대해, **실제로 나타나는 서로 다른 값과
각각의 빈도**를 값 오름차순으로 낸다.

```
Q5=A: { <값>: <빈도>, <값>: <빈도>, ... }
Q5=B: { ... }
Q5=C: { ... }
```

- 각 수준의 빈도 합이 **1,296**이어야 한다
- 전체 합이 **3,888**이어야 한다
- 값을 반올림하지 말 것. 보정이 소수라면 그것도 정보다

> **빈도가 핵심이다.** 최소·최대만으로는 폭만 보이고 **몇 개가 보정을
> 받았는지**가 안 보인다. 보정 대상 수 × 보정 크기가 원인 특정을 가른다.
>
> 어떤 수준의 값이 하나뿐이면 그 수준은 보정을 받지 않은 것이다.
> **셋 다 값이 하나면** 축은 문서 정의대로이고 잔차 원인은 다른 곳에 있다.

## 판단하지 말 것

**수치만 보고한다.** 보정이 있다/없다, 원인이 무엇이다, 축 정의를 고쳐야
한다는 판단을 하지 않는다.

**축 정의나 채점 코드를 "고치지" 말 것.** 문서와 코드가 어긋나 보여도
그것이 이 진단이 찾는 대상이며, 발견 자체가 산출물이다.
