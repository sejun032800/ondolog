## 왜

관문 G4(채팅 손맛)를 Proteur 체감으로 "나쁨" 판정받았습니다. PE 판독 결과 원인은 웹뷰의 한계가 아니라 **시험 화면에 아직 넣지 않은 처리**였습니다(500개 스크롤과 입력창 위치는 이미 통과).

- 보낼 때마다 키보드가 내려감 → 보내기 버튼이 입력 칸의 포커스를 가져감
- 새 말풍선이 연출 없이 나타나고 목록이 순간 이동함 → "뚝뚝 끊김"

여기서 정하는 처리 방식은 **`75-` 정식 채팅의 기준**이 됩니다. 시험 화면만의 임시 처리가 아니라, 그대로 옮겨 쓸 수 있는 구조로 만듭니다.

**원본**: ROADMAP **R70-0 · R70-3 · R72-1 · R72-2** · `73-1b` 산출(`web/src/platform/webFeel.ts`) · 디자인 보드 **U4(채팅) · F계열**(연출 값 — HANDOFF의 보드 경로)

## 통과 기준 (R72-2 — 녹화로 판정)

| | 기준 |
|---|---|
| (a) | 연속 세 번 보내는 동안 **키보드가 한 번도 내려가지 않음** |
| (b) | 새 말풍선에 **등장 연출**이 있고, 목록이 끝으로 **부드럽게** 이동함 |
| (c) | 키보드를 열고 닫을 때 **마지막 메시지가 화면에 남음** |
| (d) | **한글 조합 중 보내기**: "안녕"을 치고 바로 보내도 마지막 글자가 빠지지 않고("안녀" 0), 보낸 뒤 입력 칸에 글자가 남지 않음("ㅇ" · "녕" 잔여 0) |
| (e) | Proteur 체감 "보통 이상" |

## 할 일

| # | 할 일 | 조건 |
|---|---|---|
| ① | **보낸 뒤에도 키보드 유지** (a) | 보내기 버튼이 눌릴 때 입력 칸의 포커스를 가져가지 않게 한다(누름 시작 단계에서 막는 방식 등). 보낸 뒤 입력 칸 포커스는 그대로이다. 입력 칸 밖(목록)을 누르거나 뒤로 가기를 하면 키보드가 내려가는 것은 정상이다 |
| ② | **한글 조합 처리** (d) | · 조합 상태(`compositionstart` · `compositionend` · `isComposing`)를 다룬다<br>· **알려진 함정(Android)**: 웹뷰 입력 칸의 값에는 아직 확정되지 않은 조합 글자가 이미 들어 있을 수 있고, 조합 중에 값을 비우면 키보드 앱이 조합 글자를 다시 넣어 **"ㅇ" · "녕"이 남는** 일이 생긴다. ①로 포커스를 유지하면 키보드 앱이 조합을 스스로 끝내지 않으므로 이 함정이 더 잘 드러난다<br>· 보낼 때 **보낼 문자열을 확정하는 방법**과 **입력 칸을 비우는 방법**이 이 두 경우를 모두 막아야 한다. 고른 방식과 근거를 보고한다<br>· 엔터(키보드의 보내기 키)로 보낼 때도 같은 규칙. 조합 중의 엔터가 두 번 보내거나 빈 말풍선을 만들지 않는다<br>· 공백만 있는 입력은 보내지 않는다 |
| ③ | **말풍선 등장 · 부드러운 이동** (b) | · 새 말풍선 등장 연출과 목록 끝으로의 이동을 **보드 U4 · F계열의 값**(시간 · 이징 · 이동 거리)으로 넣는다. 보드에 값이 없으면 웹 데모의 시트 · 글자 등장과 같은 계열로 두고 고른 값을 보고한다<br>· 연출 중에 다음 메시지를 보내도 겹치거나 순서가 바뀌지 않는다<br>· 사용자가 위로 올려 예전 메시지를 보고 있을 때 새 메시지가 오면 강제로 끌어내리지 않는다(내가 보낸 메시지는 끝으로 간다) — 방식을 보고한다<br>· 애니메이션은 CSS 우선, 라이브러리 0 |
| ④ | **키보드 열고 닫을 때 마지막 메시지 유지** (c) | 창 높이가 바뀔 때(Capacitor 8 SystemBars `insetsHandling: native`) 목록이 끝에 붙어 있었다면 끝을 유지한다. 키보드가 열리는 순간 마지막 메시지가 키보드 뒤로 숨지 않는다. 순간 이동 대신 자연스럽게 따라간다 |
| ⑤ | **구조** | 처리(포커스 유지 · 조합 · 끝에 붙기)를 **화면 코드와 나눈 훅이나 모듈로** 둔다. `75-`에서 정식 채팅이 그대로 가져다 쓸 수 있게 하고, 위치를 보고한다 |

## 시험 (행동으로 · `*.vitest.ts(x)`)

- (a) 보내기 버튼의 누름 시작 이벤트가 입력 칸의 포커스를 빼앗지 않음 · 세 번 연속 보내도 입력 칸이 포커스를 유지함
- (d) **조합 이벤트 순서를 그대로 흉내 내는 시험**:
  - `compositionstart` → 입력(값 "안녀" + 조합 중 "ㅇ") → 조합이 끝나기 전 보내기 → 보낸 문자열이 "안녕"이고 입력 칸이 빈 값
  - 조합 중 엔터 → 한 번만 보냄 · 빈 말풍선 0
  - 조합이 끝난 뒤 보내기 → 정상
- (b) 새 메시지가 목록 끝에 추가되고 등장 연출 클래스가 붙음 · 위로 스크롤한 상태에서 상대 메시지가 와도 위치 유지(시험 화면에 "상대 메시지 흉내" 버튼이 필요하면 시험 빌드에서만 둔다)
- 정적 검사 시험 0(R32-3). 손맛 · 실제 키보드 동작은 **실기기 확인 항목**으로 보고한다
