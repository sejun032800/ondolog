## 허가 — 설정 파일 1회 (R38-5)

- `npx expo install expo-file-system` **한 번**. 바뀌어도 되는 파일은 `package.json` · `package-lock.json`뿐
- 설치 출력이나 문서가 `app.json` 플러그인 등록을 요구하면 **멈추고 보고**
- SDK의 현재 API(`File` · `Directory` · `Paths` 등)를 쓴다. **`expo-file-system/legacy`는 쓰지 않는다**
- 그 밖의 의존성 추가 없음

## ② 기존 계정 (R38-3, MASTER 6-5 r70 표)

| # | 할 일 |
|---|---|
| a | **A02 "이미 계정이 있어요"를 되살린다** → A11로 바로(동의 조건 없이). 이 길로 왔다는 표시는 **메모리에만**(sessionStore) |
| b | **로그인 직후 `profiles`를 조회한다.** 있으면 **저장 경로를 부르지 않고**, 메모리의 답 · 동의를 버린 뒤 서버의 `onboarding_step`(세이브포인트)으로 라우팅한다 |
| c | **`profiles`가 없으면** — 메모리에 동의와 답이 있으면 저장. 없으면(이미 계정 길 · 카카오 왕복 중 앱 종료) **로그인한 채 A03부터** → A04~A08 → A10 → 저장. **A11은 건너뛴다.** `/auth`의 동의 조건 가드(`canEnterLogin`)는 **로그인 안 된 상태에만** 적용한다 |
| d | **저장 경로는 "없을 때만 넣기"** — `profiles`는 이미 있으면 **덮어쓰지 않는다**(upsert의 덮어쓰기를 쓰지 않는다). `personality_assessments`의 `23505`는 **성공**으로 본다. 일부만 들어간 상태(프로필만 있고 검사는 없음 등)에서 다시 불러도 끝까지 간다. **마이그레이션 없이 클라이언트에서.** DB 쪽 변경이 필요해지면 멈추고 보고 |
| e | **`onboarding_step`을 클라이언트가 더 작은 값으로 쓰지 않는다.** 쓰는 곳을 단어 경계로 **모두** 찾아(`'\bonboarding_step\b'`) 파일 · 줄과 각 곳의 처리를 보고한다. 방법은 내부 결정(예: 갱신 조건에 "지금 값보다 작을 때만") |

**규칙 11은 계속 지킨다** — 로그인 전 서버 호출 0 · 온보딩 답 AsyncStorage 0. 기존 시험이 그대로 통과해야 한다. a의 "이미 계정 길" 표시도 영속 저장소에 두지 않는다.

## ③ 사진 영속 큐 (R37-2 — `63-` §0 a 그대로)

| # | 할 일 |
|---|---|
| 1 | 사진 메시지 · 스토리 둘 다. ① 고른 사진을 앱 문서 폴더에 복사 ② 큐 항목(클라이언트 id · 종류 · 복사본 경로)을 기기에 저장 ③ 성공하면 큐 항목과 복사본을 지운다 ④ 앱을 다시 열면 남은 항목을 이어서 보낸다 |
| 2 | **다시 보내도 Storage 객체 · DB 행이 각 하나.** 업로드 경로는 이미 `client_msg_id`로 정해진다 — 업로드가 "이미 있음"으로 실패하면 성공으로 본다. 행은 기존 중복 방지(텍스트 큐와 같은 방식)를 쓴다 |
| 3 | **스토리** — 클라이언트 id가 없으면 더하는 방법을 보고한다. 업로드 경로를 클라이언트 id에서 정하고, **같은 경로를 가진 행이 이미 있으면 넣지 않는** 방식이면 마이그레이션이 필요 없다. 그래도 DB 변경이 필요하면 **멈추고 보고** |
| 4 | 표시는 텍스트 큐와 같은 F05(스피너 없음). 복사본이 사라진 항목(사용자가 저장공간을 비움 등)은 실패 상태로 보여 주고 큐에서 뺀다 — 보고 |

사진 큐의 기기 저장은 채팅용이라 규칙 11(온보딩 답)과 무관하다.
