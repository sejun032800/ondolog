## 목표

`norm-synthetic-v2.json`의 DEF 데이터가 요약 필드만 틀렸는지, 데이터
자체가 틀렸는지 가른다. 조회 전용이며 숫자 몇 개만 낸다.

## 이 작업은 아무것도 바꾸지 않는다

**`src/` 아래 어떤 파일도 만들거나 고치지 않는다.** 규준집단 파일도
건드리지 않는다. 조회 전용 스크립트 하나와 그 출력이 전부다.

**잘못된 값을 발견해도 고치지 말 것.** 발견이 산출물이다.

## 배경 (읽고 시작할 것)

직전 진단에서 `v2` 파일의 DEF 평균이 이론값과 어긋난다는 것이 확인됐다.

- 두 애착 항의 전수 평균은 문서 정의와 정확히 일치했다
- `v3` 파일은 현재 코드와 일치했다
- `v2`에 저장된 DEF 평균만 역산값과 `0.194444` 어긋난다

**이 작업은 그 어긋남이 요약 필드에 있는지 원자료에 있는지를 가른다.**

## 산출할 것 — 셋

### ① `v2` 파일 내부 정합성

`norm-synthetic-v2.json`의 **DEF 정렬 배열 3,888개를 직접 읽어** 산술평균을
계산하고, 같은 파일에 저장된 DEF 평균 필드와 비교한다.

```
computedMean = mean(v2.stats.def.sorted)
storedMean   = v2.stats.def.mean
차            = computedMean − storedMean
```

배열 길이가 3,888인지도 함께 확인한다.

**소수점 12자리 이상**으로 보고한다.

### ② `v2` 시절 DEF의 프로파일별 역산

`v2`와 `v3`의 DEF는 애착 항만 다르므로, 현재 코드에서 `v2` 시절 값을
프로파일별로 복원할 수 있다.

```
v2DEF_i = v3DEF_i + 0.3 × (25 − V_i / 2)
```

- `v3DEF_i` : 현재 코드 `computeSixStats(...)`가 내는 DEF
- `V_i`     : `inferLoveType(...)`이 내는 `attachAvoidance`

**`V_i`를 프로파일마다 실제로 얻어서 계산할 것.** 회피축이 몇 개의 값만
갖는다는 사실을 이용해 보정량을 미리 적어 넣지 말 것 — **값을 손으로
옮겨 적는 순간이 오류가 들어오는 자리다.** 식과 `V_i`만으로 계산한다.

복원한 3,888개를 **`v2` 파일의 DEF 정렬 배열과 같은 방식으로 정렬**해
원소별로 비교한다.

> 이 복원은 `v2` 시절 코드의 애착 항이 `100 − (A + V) / 2`였다는 것을
> 전제한다. 그 전제는 위임 전에 확인됐다.

### ③ 비교 결과

불린 하나가 아니라 아래를 전부 낸다.

```
maxAbsDiff        원소별 절대 차의 최댓값
mismatchCount     |차| > 1e-9 인 원소의 개수
meanDiff          (복원값 − 저장값)의 평균
reconstructedMean 복원값 3,888개의 평균
```

> `meanDiff`가 모든 원소에서 같은 값이면 **일정한 이동**이고, 흩어져
> 있으면 **원소별로 다른 오류**다. 이 구분이 원인을 가른다.

저장 배열은 소수 10자리로 반올림돼 있으므로, `1e-9` 이하 차이는 반올림
최말단으로 본다.

## 판단하지 말 것

**수치만 보고한다.** 요약 필드가 틀렸는지 데이터가 틀렸는지, `v2`를
재산출해야 하는지 판단하지 않는다.

## 가장 중요한 제약 — 재구현하지 않는다

- DEF 계산은 **현재 `computeSixStats`를 그대로 호출**한다
- 축 값은 **`inferLoveType`에서 얻는다**
- 파일 값은 **그대로 읽는다.** 재계산·반올림하지 않는다

식을 다시 적거나 값을 하드코딩하면 이 진단이 찾으려는 차이가 사라진다.

착수 전에 **재사용할 함수의 경로와 시그니처를 보고할 것.**

## 완료 기준

- 진단 스크립트가 존재하고 **재실행 가능**하다
- `computeSixStats`·`inferLoveType`을 import해 호출했으며 재구현이 없다
- **회피축 보정량을 하드코딩하지 않고 `V_i`에서 계산했다**
