## 범위 — PM 결정 그대로

1. **한 커플의 한 기간**에 속한 **채팅·사진·데이트**를 조회하고, **17-1 재소환 대상**도 함께 가져온다.
2. 레코드마다 **`occurredAt`·`recalled`·`kind`·`source`**를 채운다. **시간대 라벨은 이미 있는 공용 함수
   하나로만** 만든다.
3. **커플 분리는 조회 단계에서 보장한다.** 골격의 호출 전 단언은 마지막 방어선일 뿐, 조회 단계 검사를
   대신하지 못한다.
4. **계약은 문서 문장이 아니라 코드 타입**(3단계에서 생긴 입력 레코드 모양)을 가리킨다.
5. 기간 판정은 **`isRecordInPeriod`**, 기간 라벨은 **`periodLabelOf`**를 그대로 쓴다. **새로 만들지 않는다.**

**범위 밖** — 발행 경로 전체: 배치 API, 미디어 복제, 테마 복사, `skip_reason` CHECK, Deno import map,
캐시 적중 확인, 호 전체 중단과 운영 경보. 다음 단계에서 한다.

## 착수 전 보고

구현 전에 아래를 보고한다.

1. 입력 레코드 타입의 **정의 위치와 필드** — 코드 그대로
2. `isRecordInPeriod`·`periodLabelOf`·시간대 라벨 함수의 **위치와 공개 여부**
3. 조회할 **테이블·컬럼과 RLS** — SCHEMA·마이그레이션의 위치를 함께
4. 입력 조립 **모듈의 위치와 DB 접근 방식**(어떤 권한으로 조회하는지), 그것이 정적 규칙 A·G와 맞는 근거
5. 커플 분리를 **조회 단계에서 어떻게 보장하고 무엇으로 시험하는지**
6. 테스트를 **실제 DB 없이** 하는 방법
7. 17-1 재소환을 만드는 데 필요한 값 중 **문서에 없는 것**

**아래에 하나라도 해당하면 구현하지 않고 보고에서 멈춘다.**

- 2번의 함수를 입력 조립에서 부를 수 없는 상태다(공개되지 않음 등) — 공개 범위를 바꾸기 전에 묻는다
- 4번의 DB 접근 권한을 문서가 정하지 않았다
- 7번에 하나라도 있다
- 그 밖에 문서와 코드로 정해지지 않아 **값을 지어내야** 하는 자리가 있다

해당이 없으면 보고에 그렇게 적고 구현으로 넘어간다.

## 완료 기준 — PM 범위별

| PM 범위 | 확인 |
|---|---|
| 1. 조회 + 재소환 | 채팅·사진·데이트가 각각 레코드로 나오는 테스트. 재소환 레코드가 함께 나오는 테스트 |
| 2. 네 필드 | 레코드가 **기존 입력 레코드 타입**으로 만들어진다(타입 검사로 강제). 시간대 라벨은 **기존 공용 함수 호출로만** — 시각 경계를 비교하는 코드가 새로 생기지 않는다 |
| 3. 조회 단계의 커플 분리 | **골격의 호출 전 단언을 거치지 않고도** 다른 커플의 레코드가 조립 결과에 없다는 것을 보이는 테스트 |
| 4. 계약 = 코드 타입 | 입력 레코드 모양을 새로 정의하지 않는다. MASTER에 옮겨 적지 않는다 |
| 5. 기존 함수 재사용 | 기간 판정은 `isRecordInPeriod`, 기간 라벨은 `periodLabelOf` 호출. **기간을 비교하거나 기간 표기를 만드는 코드가 새로 생기지 않는다** |
| 게이트 | `npx tsc --noEmit -p .` 0, `npx tsc --noEmit -p supabase/functions/tsconfig.json` 0, jest 925 대비 감소 없음 |
