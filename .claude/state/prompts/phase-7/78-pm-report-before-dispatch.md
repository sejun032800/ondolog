## 2. R108-4 ④ 실제 커플 폰 기종 — **답 도착: iPhone 14 Pro · iPhone 15 Pro (두 사람 모두 iOS)**

- 시험 커플: Galaxy S21 · LG V40 (Android)
- **Proteur 뜻: Android로 먼저 완성하고, 그다음 iPhone으로 넘어감**

PE 사실 정리 — **iOS가 실제 커플 시작의 임계 경로가 됩니다.** 지금 남은 실제 커플 조건(폰 확인 · 51- · 시험 계정 정리)이 모두 Android에서 끝나도 실제 커플은 시작할 수 없습니다. 아래가 더 필요합니다.

| 필요 | 내용 | 누가 · 무엇이 막나 |
|---|---|---|
| **Mac + Xcode** | Capacitor iOS 빌드 · 서명은 macOS에서만 됩니다 | Proteur 장비. 없으면 클라우드 Mac 빌드 서비스가 대안이지만 새 외부 서비스라 PM 결정이 필요합니다 |
| **Apple Developer Program** | 유료 연간 회원 · 실기기 배포 · TestFlight | Proteur 가입. 승인까지 며칠 걸릴 수 있습니다 |
| **배포 경로** | TestFlight(내부 · 외부 테스터) 권장. 외부 테스터는 베타 앱 심사가 필요합니다 | PM |
| **카카오 로그인 iOS** | 카카오 개발자 콘솔에 iOS 번들 ID 등록 · 앱 링크(유니버설 링크 또는 URL 스킴) 재확인 | R69-4 왕복 흐름을 iOS에서 다시 검증해야 합니다 |
| **푸시 iOS** | APNs 인증 키(.p8)를 Firebase에 등록 · iOS 권한 문구 | 78-를 iOS로 확장할 때 |

| **웹뷰 차이** | iOS WKWebView의 스크롤 · 키보드 · 안전 영역 · 오프라인 저장(76- 기기 저장) 동작이 Android와 다름 | 51- 핵심 항목을 iOS에서 한 바퀴 |
| **법무** | 앱 스토어 개인정보 표시(TestFlight 외부 배포 시) | PM |

**PE 제안**:
1. 실제 커플 조건에 **⑤ iOS 빌드 + iOS에서 51- 핵심 항목 한 바퀴**를 추가해 주세요.
2. Proteur에게 Mac 유무와 Apple Developer 가입부터 확인해 주세요. 승인 대기가 길 수 있으니 **가입은 지금 시작**하기를 권합니다.
3. 순서 원칙: Android 완성 → iOS. 이 원칙은 유지하되, 위의 장비 · 계정 준비는 지금 나란히 진행합니다.
4. 78-는 Android만 구현하되, **설계는 iOS 확장이 쉽게** 둡니다. 서버는 FCM V1 하나로 Android · iOS를 모두 보낼 수 있고, iOS는 APNs 키 등록만 더하면 됩니다.

## 3. `78-` 사전 허가 요청

R100-4가 허가한 것: `@capacitor/push-notifications` · `google-services.json`(사람이 넣음) · 새 Edge Function(배포는 사람) · 본문에 대화 원문 0.

**R100-4에 없던 것 — 사전 허가 요청**:

| # | 요청 | 이유 |
|---|---|---|
| ① | **마이그레이션 1개 `78-m1`** — 기기 토큰 테이블(사람 · 기기 · 토큰 · 플랫폼 · 마지막 확인 시각, 본인만 읽기 · 쓰기) + 알림 설정 칸(H10: 메시지 · 변경 안내, 기본 켬) + **새 메시지 → 발송 함수 호출 트리거**(`pg_net` 사용. 확장이 꺼져 있으면 켜는 문장 포함) | 토큰 · 설정을 둘 곳이 없으면 발송 대상을 알 수 없고, H10 토글은 R42-5가 말한 "거짓 화면"이 됩니다. 앱이 직접 발송을 부르면 남에게 알림을 보낼 수 있는 구멍이 생기므로, 트리거는 서버에 둡니다 |
| ② | **Android 네이티브 설정 파일 수정**: `google-services` Gradle 플러그인 · 알림 아이콘 · 알림 채널(`AndroidManifest` · `build.gradle`) | Capacitor 푸시 플러그인의 표준 설치 단계라 손수정이 필요합니다(지금까지 위임서는 "네이티브 손수정 0") |
| ③ | **`google-services.json`은 커밋하지 않음**(`.gitignore`) · Proteur가 `web/android/app/`에 직접 넣음 | 비밀은 아니지만 키 문자열이 들어 있습니다. "파일에 키 0" 원칙에 맞춥니다 |
| ④ | **Edge Function 비밀**: 서비스 계정 키를 Supabase 함수 비밀로 넣는 명령. 값이 화면에 찍히지 않는 방식이어야 합니다 | 키 회전 때와 같은 원칙 |

**범위(PE안)**:
- 알림 종류: **새 메시지**("{상대}님이 메시지를 보냈어요" · 사진이면 "사진을 보냈어요") · **사귄 날짜 변경 · 커플 닉네임 변경**(R101-5 · 앱 안 닉네임 안내 포함)
- 매거진 발행 알림은 렌더를 건드리므로 **다음**으로 둡니다
- 화면: H10 알림 설정 · I07 알림 미리보기(앱이 앞에 있을 때 위에 뜨는 띠) · I08 권한 안내(OS 권한 창 **전에** 이유를 먼저 보여 줌)

PM이 ①~④를 허가하면 PE 위임서(`78-dispatch-push.md`, 함께 보냄)를 그대로 넣습니다. 허가 범위가 다르면 PE가 고쳐서 다시 보냅니다.
