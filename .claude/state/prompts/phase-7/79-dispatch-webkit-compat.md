## 왜

실제 커플은 iPhone(14 Pro · 15 Pro)입니다. iOS 앱의 화면은 **WebKit**(WKWebView)이 그립니다. 지금 시험은 모두 Chromium 계열(Android 웹뷰 · jsdom)이라, iPhone에서만 깨지는 것을 Mac 없이 미리 잡는 장치가 없습니다.

Playwright의 WebKit으로 **iPhone 14 Pro 화면 크기**에서 핵심 화면을 자동으로 돌려, 걸리는 것을 **공통 코드에서** 고칩니다.

> **결정 기록에 반드시**: Playwright WebKit(특히 Windows · Linux 빌드)은 iOS Safari · WKWebView와 같은 엔진 계열이지만 **같은 것이 아님**. 키보드 · 안전 영역 실제 값 · 사진 선택기 · 푸시 · 앱 링크 · 스크롤 관성은 확인 못 함 → Mac 도착 뒤 실기기 한 바퀴(R114-6)가 대체 불가

## 2단계 — 걸린 것을 공통 코드에서 수정

먼저 볼 후보(R114-3) — 실제로 걸린 것만 고침:

- `env(safe-area-inset-*)` · `viewport-fit=cover` · 아래 탭 · 고정 버튼 여백
- `100vh` → `100dvh`(+ 대체값) · 키보드가 올라올 때 입력창 위치(WebKit에서 확인 가능한 범위)
- 날짜 입력(`<input type="date">` 모양 · 값 형식) · 시간대(KST) 계산이 WebKit `Date` · `Intl`에서 같은지
- 파일 입력 `accept`(`image/*` · HEIC 받기) — 동작은 Mac 뒤 실기기, 여기서는 속성 · 분기만
- 저장소 API: `localStorage` · IndexedDB 예외(사용 불가 · 할당량) 때 앱이 멈추지 않음
- 스크롤: `overscroll-behavior` · `-webkit-overflow-scrolling` 잔재 · 76- R99-3 "기기 기본 스크롤" 회귀 0
- `Intl` · 정규식(lookbehind 등) · 최신 API 사용처가 0-3 기준 버전에서 지원되는지(정적 검색 + 스모크)
- CSS: `backdrop-filter`(`-webkit-` 접두) · `gap` · `aspect-ratio` · 폰트 로딩

규칙:
- **Android 회귀 0**: 기존 Vitest · 법무 · 빌드 · cap sync 통과 + 고친 화면은 Android 폰 확인 목록에 올림
- iOS에서만 다르게 해야 하는 것은 공통 분기(플랫폼 감지)로 · 네이티브 설정 · 플러그인은 **"Mac 뒤" 목록**
