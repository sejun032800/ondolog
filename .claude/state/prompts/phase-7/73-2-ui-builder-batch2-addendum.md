## 3. 카카오 왕복 — 구현 조건 보충

- **앱 링크 등록**: `ondolog://auth/callback`을 받으려면 `web/android`의 매니페스트에 `ondolog` scheme intent-filter가 필요하다. **이 한 가지 변경은 허가한다**(PM 지시서 §3-⑤). 다른 네이티브 파일 변경은 0. 바꾼 뒤에는 `cap sync` 결과에서 intent-filter가 들어갔는지 확인해 보고한다(R68-3)
- **환경 변수**: 웹 앱은 `VITE_SUPABASE_URL` · `VITE_SUPABASE_ANON_KEY` 두 이름만 읽는다. **`web/.env`는 Proteur가 만든다**(루트 `.env`의 같은 값). 코드 · 로그 · 보고에 값 0. 변수가 없으면 앱이 원격으로 가지 않고, 로그인 화면에 "설정이 비어 있어요" 류 개발용 안내만 뜬다(운영 빌드에서는 빌드를 실패시킨다 — 방식 보고)
- PKCE s256 · `@capacitor/preferences` 세션 저장소 · 콜백 전용 화면 · `PGRST303` 1회 재시도 · 코드 두 번 교환 0 · 화면 · 로그에 코드 · 주소 0 — 본문 §3-⑤ 그대로

## 4. 빌드 경로 (HANDOFF 갱신)

한글 경로 때문에 두 도구의 요구가 다르다. HANDOFF의 `web/` 명령 절을 아래 순서로 고친다(명령은 **한 줄씩**, `;` · `&&` · 파이프 0 — R71-2).

1. **빌드 · 동기화는 원래 경로에서**: `cd` 저장소의 `web` → `npm run build:trial`(또는 `build`) → `npx cap sync android`. subst 드라이브에서 Vite를 돌리면 `html-proxy` 오류가 난다
2. **Android Studio는 ASCII 경로에서**: `subst O: "<저장소 경로>"` → `cd O:\web` → `npx cap open android` → ▶ Run. 원래 경로로 열면 Gradle이 "non-ASCII characters"로 실패한다
3. subst는 PC를 다시 켜면 사라진다는 한 줄
