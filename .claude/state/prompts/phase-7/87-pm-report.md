Q1 결과: pg_cron 1.6.4, pg_net 0.20.4. Q2 결과: 예약 작업 2개(`execute-dissolutions` · `expire-stories`, 둘 다 켜짐). 배포 뒤에는 3개가 됩니다.

**PE 의견 (작은 것, 막지 않음)**

1. **`push_net_pending`이 자라는 경우**: 예약 작업이 오래 멈추면 대기 번호가 쌓입니다. 하지만 다음 실행이 6시간 넘은 번호를 `lost`로 세고 지웁니다. 그래서 표가 끝없이 커지지는 않습니다. 그 대신 **`lost` 줄이 많이 나오면 "예약 작업이 멈췄었다"는 신호**로 읽으면 됩니다. 월요일 질의에서 다른 줄과 함께 보입니다. 별도 조치는 필요 없습니다.
2. **월요일 이상 기준**: 메인 세션은 `sent` · `http_200` · `no_tokens` · `ring` · `collapse` 말고 다른 줄이 있으면 알리게 했습니다. 이 기준에서 `dropped`(지워진 기기 토큰 정리)도 알리는 대상이 됩니다. 앱을 다시 설치하면 정상적으로도 생기는 값입니다. PE는 **"알리기는 하되, 이상은 아니다"**로 안내했습니다(Proteur 안내서 끝). PM이 정상 줄에 넣기를 원하면 HANDOFF 한 줄만 바꾸면 되고, 다음 위임에 붙일 수 있습니다.

## 3. ② 웹 업로드 실패 17건 — 판정: 시험이 쓴 것

**메인 세션 조사**
- 기록 길: `feedSave.ts:28·:33` / `photoQueueHub.ts:119` → `reportAppError` → 2초 뒤 보내기(`errorLog.ts:91-94`) → `log_app_error`.
- 화면 이름은 `App.tsx:195` 한 곳에서만 붙습니다. 그래서 **App 없이 부품만 그리는 시험에서는 화면이 `unknown`으로 남습니다.** 17건이 모두 `unknown`이었으므로 이 조건과 맞습니다.
- Vitest가 `web/.env`의 실제 접속 값을 읽고 있었습니다. 시험 정리 단계에서 클라이언트를 비우면 다음 호출 때 **실제 클라이언트가 다시 만들어지는** 길이 열려 있었습니다.
- 11/18 하루에 게이트를 5번 돌렸고, 그중 4번이 시간 초과였습니다(CPU 1.2GHz에 묶였던 날). 시험이 2초를 넘기면 보내기 타이머가 실제로 돌 수 있습니다.
- 웹 건수는 11/18 하루 17건뿐이고, 다른 날은 0입니다(Q3).

**PE 추가 확인 (Proteur가 "없을 것"이라고 한 브라우저 개발 서버 가능성)**

아래 두 근거로 **브라우저 개발 서버가 원인일 가능성은 없다고 봅니다.**
- 브라우저로 개발 서버를 열면 앱 전체(App)가 그려집니다. 그러면 오류에 실제 화면 이름이 붙고 `unknown`이 되지 않습니다(`App.tsx:195`).
- HANDOFF에 "브라우저에서는 카카오 앱 링크가 안 돌아오므로 로그인 왕복은 실기기에서 본다"라고 적혀 있습니다. 로그인 없이는 커플 피드에 사진을 올릴 수 없어서 업로드 실패가 생길 자리가 없습니다.

원격 로그가 1일만 남아서 직접 증거는 없습니다. 하지만 정황 네 가지(화면 unknown · 플랫폼 web · 그날만 · 그날 게이트 부하)가 모두 시험 쪽을 가리킵니다. **PE는 "시험이 쓴 것"으로 닫기를 권합니다.**

**막은 곳**
- `vitestSetup.ts`
  - 시험마다 접속 값 두 개를 빈 값으로 둡니다.
  - 전역 fetch 그물을 둡니다. `data:` · `blob:`만 통과하고, 막힌 요청은 수만 셉니다.
- 고정 시험 3건을 더했습니다. 전체 Vitest에서 그물에 걸린 요청은 그물 시험이 일부러 보낸 1건뿐입니다.
- 스모크는 원래 가짜 클라이언트를 쓰고 바깥 요청 0을 단언하고 있어서 처음부터 닫혀 있었습니다(`screens.smoke.ts:71`).

**덤으로 찾은 실제 결함**: `feedCache76.vitest.tsx`는 "클라이언트 없음"이라고 적혀 있었지만, 실제로는 원격으로 읽기 요청을 보내고 있었습니다. 가짜 오프라인 클라이언트로 바꿨고 단언은 그대로입니다.
- PE 의견: 시험이 원격 0이라는 원칙이 그동안 말로만 지켜지고 있었다는 뜻입니다. 이제는 그물이 시험으로 고정되어서 앞으로 새 시험이 원격을 부르면 바로 드러납니다. 실제 커플 기간에 오류 표가 시험 기록으로 더러워지지 않게 되었으니 **이번 위임에서 가장 값진 결과**로 봅니다.

## 5. 사람 단계 (Proteur, 안내서 `87-human-guide-for-proteur.md`)
