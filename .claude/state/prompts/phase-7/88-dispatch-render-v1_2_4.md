### ③ 높이 여유 1줄 판정 (R149-5) — 칸 종류별로 데이터로

디자인 검증은 고정 시드 하나에 견본이 타임라인 40개, 인용 30개뿐이고, 기사 표(`article.*`)는 검증하지 않습니다. 이 크기로는 "여유 없이 과소 0"을 믿기 어렵습니다. 그래서 아래처럼 넓혀서 잽니다.

| 항목 | 규칙 |
|---|---|
| 비교 두 벌 | (가) **여유 있음** = 표의 `lines` · (나) **여유 없음** = 같은 측정의 `sampledLines`. 다시 재지 말고 ②의 측정 하나에서 두 열을 씁니다 |
| 견본 | 디자인 `validate`와 같은 방식(실제 틀을 채워 Chromium 높이 vs 식 예측)으로 하되, **시드 3개 이상 · 칸 종류마다 200개 이상**. 칸 종류는 다음 9개입니다: `timeline.memoLines` · `timeline.captionLines` · `timeline.placeLines` · `quotes.turnLines.odd` · `quotes.turnLines.even` · `quotes.contextLines` · `article.stopMemoLines` · `article.photoCaption.{1,2,3}.memoLines`. 문장은 시험 데이터(fixtures) 문장 + 낱말 길이를 섞은 합성 문장 + 줄바꿈이 섞인 문장입니다. 실제 사용자 원문은 쓰지 않습니다 |
| 판정 | 칸 종류마다: **(나)에서 과소(예측 < 실제 − 0.5px)가 0이면 그 칸은 여유를 뺍니다.** 1건이라도 있으면 여유를 남깁니다 |
| 적용 방법 | **디자인 도구 · `measure.json` 모양은 그대로** 둡니다. 렌더러가 표를 읽을 때 **칸 종류별로 `lines` / `sampledLines` 중 무엇을 쓸지 정하는 설정 한 곳**(렌더러 쪽 상수, 근거 주석에 이 판정 표 경로)을 둡니다. 다음에 다시 재도 설정이 그대로 적용되게 합니다 |
| 시험 | 설정의 칸 이름이 `measure.json`에 모두 있는지 · 여유를 뺀 칸은 `sampledLines`를, 남긴 칸은 `lines`를 읽는지 |
| 보고 표 | 칸 종류 × [견본 수 · (가) 과소 · (가) 최대 과대 px · (나) 과소 · (나) 최대 과소 px · 판정(뺌/남김)] |
