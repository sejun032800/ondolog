## 1부 — 착수 조건 둘 (실패하면 구현하지 말고 보고)

### ① Edge Function 코드가 타입 체크 대상인가

**이것이 성립하지 않으면 타입 층이 통째로 작동하지 않는다.**
`ValidatedContent`도 `CoeffBundle`도 컴파일 시점에 막는 장치인데,
`supabase/functions/` 아래가 `tsc` 범위 밖이면 아무것도 막지 못하고
정적 규칙 C·D·E만 남는다. **세 층 중 하나가 빠진다.**

- `tsconfig.json`의 `include`/`exclude`가 `supabase/functions/`를
  포함하는지 확인한다
- `npx tsc --noEmit -p .`가 그 아래 파일을 실제로 검사하는지 확인한다

**범위 밖이면 파이프라인을 만들지 말고 멈추고 보고할 것.**
해소가 선행이며, `tsconfig.json` 수정은 절대 규칙 8에 걸려 별도
지시가 필요하다.

### ② 필드 매핑이 Part 17-0-5-B와 일치하는가

`corners` 테이블이 이미 존재하며 필요한 컬럼이 전부 있다. **마이그레이션은
이번 범위가 아니고, 필요하지도 않다.**

`docs/ONDOLOG_SCHEMA.md`의 `corners` 컬럼 구성이 Part 17-0-5-B의 매핑과
일치하는지 확인해 **보고한다.**

- 일치하면 그대로 진행한다
- **어긋나면 보고하되, 구현을 멈추는 사유는 아니다.** 어긋난 내용을
  적고 진행한다

> `skip_reason`이 자유 텍스트라 DB가 4값을 강제하지 못한다.
> **TypeScript 유니온으로 강제한다** — 저장 함수가 그 밖의 값을
> 받지 못하게. `CHECK` 제약은 마이그레이션이라 폰 복귀 후 재빌드
> 묶음으로 미뤄져 있다.

**①이 실패하면 구현하지 않는다. ②는 확인 후 진행한다.**
두 결과를 보고한 뒤 구현에 들어간다.

## 2부 — 규칙 C 판정 기준 교정

현재 규칙 C의 판정 기준을 **아래 둘로 확정한다**(Part 17-0-3, r19).

| 검사 | 대상 |
|---|---|
| **LLM SDK 모듈 import** | 지정 모듈 밖 |
| **LLM 엔드포인트 호스트 문자열** | 지정 모듈 밖 |

**`fetch` 전반을 잡지 않는다.** `fetch`는 앱의 정상 동작이고,
`src/services/referencePhotoApi.ts`가 참조 사진 업로드에 이미 쓰고 있다.
전반을 잡으면 정당한 네트워크 계층이 매번 걸리고, 그러면 사람이 규칙을
건너뛰게 된다.

엔진의 네트워크 금지는 **규칙 B가 이미 담당한다.** C가 지켜야 할 것은
`fetch`의 유무가 아니라 **LLM 호출 경로가 하나뿐인가**이다.

**두 번째 검사가 SDK 없이 `fetch`로 직접 부르는 우회를 막는다.**
엔드포인트 상수는 `llmClient.ts` 안에만 존재해야 한다.

### 합성 입력 테스트를 보강한다

기존 테스트에 더해 아래를 추가한다.

- SDK import가 지정 모듈 밖에 있는 소스 → **걸린다**
- 엔드포인트 호스트 문자열이 지정 모듈 밖에 있는 소스 → **걸린다**
- `fetch`만 있고 LLM과 무관한 소스 → **안 걸린다**

## 3부 — 브랜드 생성 함수

`src/engine/corners/brandedTypes.ts` **안에** 추가한다. 심볼이
비공개이므로 모듈 밖에서는 만들 수 없고, 밖에서의 캐스트는 규칙 E에
걸린다.

| 함수 | 반환 |
|---|---|
| 파싱·검증 함수 | `ValidatedContent<T>` |
| 계수 조립 함수 | `CoeffBundle` |

**`ValidatedContent`는 Zod 파싱과 `FORBIDDEN_KEYS` 검사를 모두 통과한
경우에만 반환한다**(Part 17-0-4). 하나라도 실패하면 반환하지 않고
실패 사유를 낸다.

**`CoeffBundle`은 `coeffLookup.ts`가 조회한 값으로만 조립된다.**
리터럴 객체로 만들 수 없어야 한다.

정의 모듈 안의 캐스트는 규칙 E의 예외이며, **캐스트가 일어나는 자리는
이 모듈 한 곳뿐이어야 한다.**

## 4부 — 두 허용 모듈

### `coeffLookup.ts`

- `app_config`에서 계수를 조회한다
- **`CoeffBundle`을 반환한다** — `version`이 붙어 분리 불가능하다
- 이 모듈 밖에서 `app_config`에 접근하지 않는다 (규칙 D)

### `llmClient.ts`

- LLM 호출을 담당한다. **엔드포인트 상수가 이 모듈 안에만 있다**
- 호출 실패·타임아웃을 호출자에게 구분 가능한 형태로 알린다

#### 재시도는 두 층으로 나뉜다 (Part 17-0-5-A, r20)

| 주체 | 소유 |
|---|---|
| **`llmClient.ts`** | 코너 1건당 **호출 예산(3회)**, 전송 오류 지수 백오프 |
| **파이프라인** | **검증 결과에 따른 재호출 결정** (`schema_invalid` 1회, `forbidden_content` 0회) |

**층이 섞이지 않는다.** `llmClient`는 Zod도 `FORBIDDEN_KEYS`도 모른다 —
HTTP 수준 실패만 안다. 파이프라인은 HTTP를 모른다 — 검증 결과만 안다.

**상한은 `llmClient`가 강제한다.** 파이프라인이 몇 번을 다시 부르든
**예산을 소진한 요청은 `llmClient`가 거부한다.** 파이프라인의 재시도
정책이 잘못돼도 비용 상한은 깨지지 않는다.

> ⚠️ **예산을 인자로 흘려보내는 형태는 금지한다.** 호출부가 예산
> 객체를 새로 만들어 우회할 수 있다. **코너 1건마다 예산을 가진
> 클라이언트를 받아 쓰는 형태**여야 한다.

## 5부 — 파이프라인 골격

### 순서

```
① 선행 검사      → 미달이면 insufficient_input, LLM 호출하지 않음
② 계수 조회      → CoeffBundle
③ LLM 호출       → 실패 시 generation_failed
④ Zod 파싱       → 실패 시 schema_invalid
⑤ FORBIDDEN_KEYS → 위반 시 forbidden_content
⑥ ValidatedContent 반환 → 저장
```

**①이 LLM 호출 앞에 있는 것이 핵심이다**(Part 17-0-5). 미달이면
호출하지 않으므로 사유가 추론이 아니라 사실이 되고 비용도 들지 않는다.

### 코너별 부분은 주입받는다

골격은 코너마다 다음 셋을 **인자로 받는다.**

- 선행 검사 조건
- 프롬프트 생성 함수
- Zod 스키마

**이번 작업에서 그 셋의 내용을 만들지 않는다.** `#14`가 얹는다.

### 실패 사유 4값

Part 17-0-5의 네 값을 그대로 쓴다. **이름을 바꾸거나 합치지 않는다.**

**TypeScript 유니온으로 강제한다.** `skip_reason`이 DB에서 자유 텍스트라
그 밖의 값이 들어갈 수 있고, **저장 함수가 그것을 타입에서 막아야 한다.**

상태 매핑도 Part 17-0-5-B를 따른다 — `insufficient_input`은 `skipped`,
나머지 셋은 `failed`. **`skipped`는 정상 동작이다**(재료가 없으면 안
만드는 것이 원칙 ②).

`forbidden_content`를 `schema_invalid`와 분리하는 것이 특히 중요하다 —
**`FORBIDDEN_KEYS` 위반율은 원칙 ①이 지켜지는지를 재는 유일한 지표**이고,
형식 오류와 섞으면 그 신호를 측정할 수 없다.

### 재시도

Part 17-0-5-A의 표를 그대로 구현한다.

- `insufficient_input` · `forbidden_content` — **재시도하지 않는다**
- `generation_failed` — 최대 2회, 지수 백오프
- `schema_invalid` — 1회
- **한 코너당 LLM 호출 총 3회 상한.** `schema_invalid` 재시도는 그 안에서
  소모된다

**상한은 `llmClient`의 예산이 강제한다.** 파이프라인이 재시도를 잘못
결정해도 예산이 소진되면 거부된다.

**테스트로 확인할 것** — 파이프라인이 상한을 넘겨 요청해도 `llmClient`가
거부하는지.

### 저장

- **저장 함수는 `ValidatedContent<T>`만 받는다.** 검증을 건너뛴 값은
  타입에서 막힌다
- 실패 사유도 저장한다. 토글이 "숨김"이어도 **부재 사실과 사유는
  저장한다**(Part 3-7-B)
- `coeffVersion`을 함께 기록한다

**발행 판정·부재 지면 렌더링은 이번 범위가 아니다.** Phase 7은
**산출·저장까지**이며, 조판은 Phase 8이다.
