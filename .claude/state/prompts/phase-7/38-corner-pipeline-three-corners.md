## 범위 (PM)

### 1. 코너 셋

코너마다:

- **요청 만들기·응답 처리** — 코너 코드는 전송 방식을 모른다(§17-0-5-F, 규칙 G)
- **LLM 출력 스키마와 저장 스키마를 분리** — 저장 스키마는 CORNER_CONTENT가 원본
- **명시적 빈 결과** — §17-0-5-D
- **선언형 ID 매핑** — §17-0-4(r43·r44). 판정 규칙을 코너가 짜지 않는다
- **§17-0-7의 결정**을 따른다 — 코너 이름·지면 제목, 개수, 근거 형태, 수치는
  파이프라인이 계산, 질문 문구·지도·기사 순서 등

### 2. `LlmRequest` 시그니처와 프롬프트 캐싱

- `llmClient`의 호출 시그니처를 1부 설계대로 바꾼다
- 코너가 캐시 지점을 표시하고 **`llmClient`만** 그것을 전송 형식으로 옮긴다
- `llmClient`만 SDK·엔드포인트를 안다(규칙 C), 층 분리는 그대로(§17-0-5-C)

### 3. 지면 제목 상수 셋

- §17-0-7(r41)의 값 그대로 — 함께한 하루 · 다정한 말들 · 이달의 우리
- 코너 이름도 §17-0-7·r45의 값 그대로
- **지면 제목 상수가 `^[가-힣 ]{1,7}$`에 맞는지 테스트**

### 4. 시간대 라벨 함수 (§17-0-7, r45)

- **함수 하나**, 위치는 **`supabase/functions/_shared/`**
- **한국 시간은 고정 오프셋 +09:00으로 계산한다. 실행 환경의 시간대에 기대지 않는다**
- 라벨과 경계는 §17-0-7 표 그대로
- 다정한 말들 픽스처가 이 함수로 표기값을 만든다

### 5. 코너마다 `findMissingReferencePaths` 호출 (r44)

각 코너의 선언된 `path`가 그 코너의 LLM 출력 스키마에 있는지 테스트에서 확인한다.

### 6. Zod 카나리아 (r45)

경로를 알고 있는 기준 스키마에서 **모든 경로가 있다고 판정되는지** 보는 테스트.
실패 메시지가 **"Zod 내부 구조가 바뀌었다"**를 가리켜야 한다. Zod의 공개 변환으로
같은 판정이 되면 그쪽으로 옮기는 것을 검토하고, 검토 결과를 보고한다.
