### ① 패턴 모드 — 네 겹 잠금 (R154-7 · PE 제안 그대로)

| 겹 | 규칙 |
|---|---|
| 1. 이메일 모양 | 대상은 **`test-` + [영숫자 · `-` · `_` · `.`] + `@example.com`** 인 인증 사용자만입니다. 정규식으로 정확히 판정하고 대소문자는 무시합니다. 카카오 계정은 `example.com`일 수 없습니다. `test-m2b-*`(시드)도 모양은 맞지만, C3 뒤라 0명이어야 합니다. 남아 있으면 미리 보기에 따로 건수를 보이고 함께 지웁니다 |
| 2. 개발 프로젝트 | 허용 목록 파일의 **`project=` 잠금을 그대로** 씁니다. 접속 전에 판정합니다. 이메일 줄은 이 모드에서 쓰지 않습니다(C3 6부 뒤 이메일 줄 0이어도 동작) |
| 3. 만든 날짜 상한 | 사람이 `--created-before YYYY-MM-DD`(KST 그날 0시)를 **반드시** 넣습니다. 그 뒤에 만든 계정은 대상이 아닙니다. 값은 **C3을 한 다음 날 `2026-11-25`**입니다(11/24 안에 만든 시험 계정까지 포함) · 실제 커플 가입보다 앞입니다. 인자가 없거나 모양이 틀리면 거부합니다 |
| 4. 미리 보기 기본 · 전체 거부 | `--apply`가 없으면 미리 보기만 합니다. 아래 **전체 거부 조건** 중 하나라도 맞으면 아무것도 지우지 않고 거부 문장 한 줄만 냅니다 |

**전체 거부 조건** (미리 보기 · apply 둘 다)
- 대상 사용자가 속한 커플(active · dissolving · pending 초대 포함)에 **패턴 밖 사용자가 한 명이라도** 있음. 시험 계정이 실제 사람과 연결돼 있으면 안 됩니다.
- 대상 사용자가 받은 대상이 아닌 쪽과 엮인 다른 행이 있음(예: 상대가 패턴 밖인 메시지). 코어가 cascade로 지우는 범위를 넘으면 거부합니다.
- 패턴 밖 사용자 수가 실행 전후로 바뀌는 쿼리가 하나라도 있음. 이것은 시험으로 고정합니다.

**apply 이중 확인**
- apply 때 사람이 **미리 보기에서 본 대상 사용자 수**를 `--expect-users N`으로 넣습니다.
- 다시 센 수가 N과 다르면 거부합니다(미리 보기와 apply 사이에 바뀐 것을 막음).

**출력**
- **종류별 건수만** 냅니다: 대상 사용자 · 그중 시드 · 커플 · 호 · 메시지 · 기록 · Storage 파일 등.
- id · 이메일 · ref · 별명 0.
- 거부 문구에도 값 0.

**지우는 순서**
- 커플 단위(두 사람 모두 패턴 안) → 커플 없는 사용자 단위로 합니다.
- 중간에 끊겨도 같은 명령을 다시 치면 남은 것만 지웁니다. 지금 코어와 같습니다.
