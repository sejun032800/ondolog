## 할 일

### ① 렌더 되받기 (R150-3)

| 항목 | 규칙 |
|---|---|
| 언제 | 지면을 그린 뒤 지면 검사가 **넘친 지면**을 찾았을 때 |
| 무엇을 찾나 | 넘친 지면 안에서 **넘친 항목 하나 이상**을 그린 결과(DOM 높이)로 찾습니다. 항목은 타임라인 구간 · 인용 대화 · 글만 있는 기사 구간 · 사진 아래 메모 칸 등입니다. 지면 이름만이 아니라 **항목 단위**로 찾습니다 |
| 어떻게 | 그 항목의 높이를 **예측 대신 실제로 잰 높이**로 바꿔 끼우고, 지면 나누기를 다시 해서 다시 그립니다. 다시 나눈 결과는 다음 면으로 넘기는 것입니다. 그 섹션의 면 상한(타임라인 2면 등) 안에 넣을 면이 없으면, **지금 규칙대로 싣지 않고 발행 노트 "싣지 않은 것"에 적습니다** |
| 횟수 | **최대 2번** 다시 그립니다. 2번 뒤에도 넘치면 지금처럼 렌더 실패로 끝냅니다. 실패 이유 한 줄에 항목 종류와 되받기 횟수를 적고, 원문은 적지 않습니다. 끝없이 돌지 않게 합니다 |
| 원문 | **자르지 않습니다(R29-3).** 글자 수 · 줄바꿈 · 덩어리를 바꾸지 않습니다. 들어간 원문과 지면에 그려진 원문이 같은지 시험합니다 |
| 결정론 | 같은 입력이면 같은 결과가 나와야 합니다. 두 번 돌려 쪽 수 · 배치 · 요약 숫자가 같은지 확인합니다 |
| 렌더 요약에 남길 숫자 | 되받기 횟수 · 옮긴 항목 수(종류별) · 되받기로 싣지 않게 된 항목 수(종류별). 원문 · id는 남기지 않습니다 |
| **옮길 수 없는 칸** | 사진 아래 메모 칸(`article.photoCaption.*` · 칸 104~106px)처럼 **틀에서 자리가 정해진 칸**은 다음 면으로 넘길 수 없습니다. 지금 렌더러에 이런 칸이 넘칠 때 쓰는 기존 길이 있으면(다른 변형으로 바꾸기, 메모를 기사 구간으로 옮기기 등) 그 길을 쓰고 근거(파일:줄)를 댑니다. **기존 길이 없으면 새 모양을 만들지 말고**, 지금처럼 실패로 두고 보고 §"PM에게 올릴 것"에 적습니다. 모양은 디자인이 정합니다 |
| 한 항목이 한 면보다 큰 경우 | 실제 높이로 재도 한 면의 가용 높이보다 큰 대화 · 구간은 지금 규칙대로 처리합니다(README §12 — 렌더 실패 또는 싣지 않음 · 섹션마다 지금 하는 그대로). 규칙을 바꾸지 말고 어느 쪽인지 보고합니다 |

**시험 — 띄어쓰기 없는 긴 덩어리 견본**
- 견본 문장: "ㅋ" 20~40자 덩어리 · "ㅠ" 10~20자 · 붙여 쓴 주소(예: `https://example.com/very/long/path/...` 꼴 · 지도 주소 꼴 · 실제 주소 0) · 붙여 쓴 긴 한글 말 · 일반 문장을 섞습니다. **실제 사용자 원문은 쓰지 않습니다.**
- 이 견본을 넣는 칸: 타임라인 메모 · 인용 턴(홀수 · 짝수) · 글만 있는 기사 메모 · 사진 아래 메모 3종.
- 확인할 것:
  - (a) **되받기 경로가 실제로 도는지**: 예측이 작게 나오는 견본(88-의 과소 23건 꼴)이나 시험 전용 낮춘 예측으로 확인합니다. 넘침 → 되받기 1회 → 넘침 0 · 요약 숫자를 봅니다.
  - (b) 2번 뒤에도 넘치면 실패로 끝나는지(끝없이 돌지 않음).
  - (c) 면이 없을 때 "싣지 않은 것"에 적히는지.
  - (d) 원문이 같은지.
  - (e) 결정론.
  - (f) 넘침이 없으면 되받기가 0이고, 결과가 88-과 바이트까지 같은지(시드 9권 · `edge` — PDF가 아니라 지면 HTML 또는 배치 요약 기준).
- 88-의 칸 종류별 과소 견본 측정을 **되받기를 켠 상태로 다시 돌립니다.** 최종 넘침 · 렌더 실패 건수를 칸 종류별 표로 보고합니다.

### ② 읽기 전용 로컬 렌더 (R150-4)

| 항목 | 규칙 |
|---|---|
| 모양 | 지금 CLI에 **읽기 전용 모드**를 하나 더합니다. 예: `render_issue.py --local-only --issue-id … --out …`. 이름은 메인 세션이 정하고 근거를 댑니다 |
| 받는 호 | **발행된 호도 받습니다.** 이 모드에서만 `:757` 거부를 건너뜁니다. 다른 모드의 거부는 그대로 둡니다 |
| 쓰기 | **업로드 0 · 행 변경 0 · 쓰는 RPC 호출 0.** 이 모드에서는 버킷 업로드 · issues 갱신(:814 · :821) 경로에 **들어가지 않게** 코드에서 갈라 둡니다. 읽기 함수만 가진 좁은 클라이언트 감싸개를 권합니다 |
| 출력 | **저장소 밖 폴더만** 받습니다. `--out`이 저장소 안(또는 저장소 자체)이면 거부합니다. 사진 원본 · PDF · PNG 모두 그 폴더에 둡니다 |
| 화면 출력 | 호 id · 사용자 · 커플 · 주소 · 키 · 서명 URL을 화면에 찍지 않습니다. 쪽 수 · 되받기 숫자 · 넘침 0 여부 · 걸린 시간만 찍습니다 |
| **원격 쓰기 0을 시험으로 고정** | 가짜 클라이언트에서 쓰기 메서드(insert · update · upsert · delete · storage upload/remove · 쓰는 RPC)가 **한 번이라도 불리면 시험 실패**. 로컬 전용 모드로 발행된 호 · 안 된 호를 각각 그려 봅니다. 저장소 안 `--out` 거부 시험도 넣습니다 |
| 키 | 사람이 운영 키로 한 번 실행합니다. 키 넣는 방법은 HANDOFF의 기존 운영 절차를 그대로 씁니다(`Read-Host -AsSecureString` · `StartsWith` 확인 · 창 닫기 · 새 창에서 False). 새 키는 만들지 않습니다 |
| 대상 | **G 1호**(`test-m2b-G`) · **두 폰 커플 11월호** — 두 번 실행 |
| 비교 | Proteur가 휴지통에서 옛 `render/out`을 찾으면 그 PDF와 비교합니다. 없으면 issues 행의 쪽 수(읽기)와 비교합니다. 비교 항목: 쪽 수 · 타임라인 면 · 실린/빠진 대화 · 되받기 횟수 · 표지(이 달의 말 줄) · 0인 조각. 원문은 보고에 넣지 않습니다 |
