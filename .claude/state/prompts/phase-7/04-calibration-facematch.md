## 왜 이 문서가 위임 대상이 아닌가

실기기 디버깅과 네이티브 모듈 연동은 메인 세션 몫이고, **관측 자체는 사람이
기기 앞에서 해야 합니다.** 서브에이전트는 폰 화면을 볼 수 없습니다.

메인 세션이 하는 것은 0단계(측정 도구 준비)뿐이고, 1단계부터는 대표님이
직접 수행합니다.

---

## 절대 원칙 두 줄 (모든 단계에 적용)

> **타인 표본은 이미 기기에 있는 사진만 사용한다. 측정을 위해 새로 수집하지 않는다.**
>
> **임계값은 타인 표본 관측 최댓값 + 여유로 정한다. 표본이 적을수록 여유를 크게 잡는다.**

그리고 규칙 1 — **얼굴 데이터는 기기 밖으로 나가지 않습니다.** 유사도 수치를
기록할 때 사진·특징 벡터를 함께 옮기지 않습니다. 옮기는 것은 **숫자뿐**입니다.

---

## 왜 표본 요구량이 비대칭인가 (읽고 시작할 것)

오탐 회피가 우선으로 확정됐습니다(Part 9-4). 그래서 두 오류의 측정 요건이 다릅니다.

| | 필요한 것 | 표본 |
|---|---|---|
| **오탐** (남이 우리 앨범에 들어옴) | 타인 얼굴 유사도의 **관측 최댓값** | 적어도 됨 |
| **미탐** (우리 사진이 안 잡힘) | 본인 얼굴 유사도의 **하위 분포** | 변형으로 충분히 확보 |

임계값을 타인 관측 최댓값 위에 두므로, **표본이 적으면 참 최댓값을 과소추정**하고
그만큼 여유를 더 얹게 됩니다. 결과적으로 임계값이 더 보수적인 쪽 — 오탐이 적고
미탐이 많은 쪽 — 으로 밀립니다. **그게 확정된 우선순위와 같은 방향이라, 표본
부족이 이 절차를 무효로 만들지 않습니다.**

미탐은 본인·연인 사진의 각도·조명·거리 변형으로 기기 안에서 얼마든지 만들 수
있으므로 여기서 제대로 잽니다.

## 0단계 — 측정 도구 준비 (메인 세션 작업, 폰 복귀 후)

**현재 유사도 숫자를 볼 방법이 없습니다.** `isMatch(similarity, threshold)`는
불리언만 반환합니다. 측정하려면 원시 유사도가 화면에 떠야 합니다.

메인 세션에 요청할 것.

- 사진 한 장과 참조 얼굴의 **원시 유사도 값을 화면에 표시**하는 임시 디버그 화면
- 값은 반올림하지 않고 그대로 표시 (소수점 이하가 판단에 필요합니다)
- **온디바이스에서만 계산하고 어디에도 전송하지 않습니다**
- 프로덕션 화면이 아니라 개발 빌드 전용 임시 화면입니다

> 이 화면은 캘리브레이션 종료 후 제거하거나 개발 빌드에만 남깁니다.
> 유사도 노출은 정식 기능이 아닙니다.

- [ ] 디버그 화면 동작 확인

---

## 1단계 — 척도의 방향 확인 (가장 먼저)

**반환값이 유사도인지 거리인지 확인합니다.** 방향이 반대면 이 절차 전체가
뒤집힙니다("최댓값 + 여유" → "최솟값 − 여유").

- [ ] 같은 사람의 사진 두 장을 비교했을 때 값이 **큰가 작은가**
- [ ] 명백히 다른 사람의 사진을 비교했을 때 값이 **작은가 큰가**

| 관측 | 척도 | 임계값 규칙 |
|---|---|---|
| 같은 사람 = 큰 값 | 유사도 | 임계값 **이상**이면 매칭. 타인 최댓값 **+** 여유 |
| 같은 사람 = 작은 값 | 거리 | 임계값 **이하**면 매칭. 타인 최솟값 **−** 여유 |

**기록:** 척도 = ______________ / 관측 예시 값 ______ , ______

> 이하 이 문서는 **유사도(큰 값 = 닮음)** 기준으로 씁니다. 거리로 확인되면
> 부등호와 최대/최소를 전부 뒤집어 읽으십시오.

- [ ] 값의 범위 확인 (예: 0~1인지, 0~100인지) — 기록: ______

---

## 2단계 — 참조 얼굴 등록

**모든 유사도의 기준선이 여기서 정해집니다.** 참조를 어떤 사진으로 잡느냐에
따라 이후 모든 숫자가 달라집니다.

- [ ] **실제 온보딩과 동일한 방식**으로 참조 얼굴을 등록한다
      (개발자용 별도 경로로 등록하면 실사용 값과 어긋납니다)
- [ ] 본인 참조 등록
- [ ] 연인 참조 등록

**기록:** 참조 등록에 쓴 사진의 조건(정면/실내조명/마스크 없음 등)

- 본인: ______________________________
- 연인: ______________________________

## 3단계 — 타인 표본 확보 (오탐 측정용)

> **이미 기기에 있는 사진만 사용합니다. 새로 수집하지 않습니다.**

- [ ] 갤러리에서 **본인·연인이 아닌 얼굴**이 나오는 사진을 고른다
      (단체 사진, 친구가 찍힌 사진, 배경에 사람이 들어간 사진 등)
- [ ] 한 사진에 여러 얼굴이 있으면 각각을 별개 표본으로 센다
- [ ] **얼굴이 알아볼 수 있게 나온 것만** 포함한다. 뒷모습·심한 흐림은 제외

**표본 수를 반드시 기록하십시오.** 유저가 쌓여 재캘리브레이션할 때, 초기
임계값이 몇 장을 근거로 나온 값인지 알아야 얼마나 신뢰할지 판단할 수 있습니다.
규준집단에 `normVersion`을 붙인 것과 같은 이유입니다.

**기록:** 타인 표본 수 = ______ 개 (서로 다른 인물 수 = ______ 명)

- [ ] 표본이 10개 미만이면 그 사실을 기록에 명시 (여유를 크게 잡아야 합니다)

---

## 4단계 — 오탐 측정

각 타인 표본을 **본인 참조**와 **연인 참조** 양쪽에 대고 잽니다.
두 참조 중 **더 높은 쪽**이 그 표본의 값입니다.

- [ ] 모든 타인 표본에 대해 유사도 측정
- [ ] 값을 하나도 빠뜨리지 않고 아래에 기록

```
표본  vs본인   vs연인   높은쪽
 1    ______  ______  ______
 2    ______  ______  ______
 3    ______  ______  ______
 ...
```

**타인 관측 최댓값 = ______**  ← 임계값의 하한선입니다

- [ ] 최댓값이 나온 표본이 무엇이었는지 메모 (조명·각도·유사한 인상 등)

> 이 값이 예상보다 높으면 그 자체가 중요한 정보입니다. 특정 조건(어두움,
> 측면, 저화질)에서 타인 유사도가 치솟는다면 임계값만으로는 못 막고
> 별도 조건이 필요할 수 있습니다. 8단계에서 다룹니다.

## 5단계 — 본인 표본 확보 (미탐 측정용)

여기는 표본 수 제약이 없습니다. **어려운 조건을 일부러 만듭니다.**
쉬운 사진만 재면 미탐을 과소평가하게 됩니다.

아래 조건을 조합해 촬영하거나 갤러리에서 고릅니다. 본인·연인 각각.

- [ ] 정면 / 밝은 실내 (기준 조건)
- [ ] 측면 45도
- [ ] 역광 또는 어두운 조명
- [ ] 멀리서 찍혀 얼굴이 작게 나온 것
- [ ] 안경 착용 / 미착용 (해당되면)
- [ ] 마스크 착용 (해당되면)
- [ ] 모자·앞머리로 일부 가려진 것
- [ ] 웃는 표정 / 무표정
- [ ] 야외 / 저녁

**기록:** 본인 표본 수 = ______ 개 / 연인 표본 수 = ______ 개


**본인 관측 최솟값 = ______** (어느 조건에서 나왔는지: ____________)

- [ ] 조건별로 값이 얼마나 떨어지는지 확인 — 어느 조건이 가장 취약한지 기록

## 7단계 — 두 분포가 겹치는지 확인

```
타인 최댓값 (4단계) = ______
본인 최솟값 (6단계) = ______
```

- [ ] **본인 최솟값 > 타인 최댓값** → 분리됨. 8단계로
- [ ] **본인 최솟값 ≤ 타인 최댓값** → **겹침. 아래를 읽으십시오**

### 겹칠 경우

임계값 하나로 두 오류를 동시에 막을 수 없다는 뜻입니다. 오탐 회피가 우선이므로
**타인 최댓값 위에 두고, 겹치는 구간의 본인 사진은 놓칩니다.**

- [ ] 겹치는 구간에 들어간 본인 표본이 **어떤 조건**이었는지 기록
- [ ] 그 조건이 실사용에서 흔한지 판단 (마스크가 겹친다면 큰 문제이고,
      극단적 역광만 겹친다면 감수 가능합니다)
- [ ] **이 판단은 마스터 PM에게 올립니다.** 여기서 결정하지 마십시오

## 8단계 — 임계값 결정

**타인 관측 최댓값 + 여유**로 정합니다.

여유를 얼마로 잡을지는 아래 재료를 놓고 결정합니다. **표에 미리 숫자를 넣지
않은 것은 의도적입니다** — 실측 분포를 보기 전에 정하면 근거 없는 값이 됩니다.

판단 재료:

| 요소 | 방향 |
|---|---|
| 타인 표본 수가 적다 | 참 최댓값을 과소추정했을 가능성 → **여유를 크게** |
| 타인 표본의 인물이 다양하다 | 최댓값이 신뢰할 만함 → 여유를 작게 |
| 타인 값들이 최댓값 근처에 몰려 있다 | 더 높은 값이 존재할 여지 → **여유를 크게** |
| 본인 최솟값과 간격이 넓다 | 여유를 키워도 미탐이 안 늘어남 → **크게 잡아도 손해 없음** |
| 본인 최솟값과 간격이 좁다 | 여유를 키우면 미탐 증가 → 7단계 겹침 판단과 함께 봄 |

- [ ] 여유 = ______ 로 결정. 근거: ______________________________
- [ ] **임계값 = ______**

### 애매 구간 (Part 9-4)

> "애매 구간은 매칭하지 않는다"가 확정돼 있습니다.

- [ ] 이중 임계값 도입은 **Phase 10 재검토 사항**입니다. 지금은 단일
      임계값으로 두고, 애매한 값은 임계값 미만이므로 자동으로 미매칭됩니다
- [ ] 측정 중 "애매하다"고 느낀 구간의 값 범위를 기록해 두십시오 —
      Phase 10 이중 임계값 설계의 입력이 됩니다: ______ ~ ______

## 9단계 — 기록과 반영

### 기록할 것 (`.claude/state/DECISIONS.md`)

```
faceMatch.threshold 캘리브레이션 (날짜)

척도: {유사도/거리}, 범위 {}
참조 등록 조건: 본인 {}, 연인 {}
타인 표본: {N}개 / {M}명 — 관측 최댓값 {}
본인 표본: {N}개 — 관측 최솟값 {} ({조건})
분포 겹침: {없음 / 있음 — 겹친 조건}
여유: {} — 근거 {}
확정 임계값: {}
애매 구간 관측 범위: {} ~ {}

재캘리브레이션 조건: 타인 표본이 늘어나거나, 얼굴 인식 SDK 버전이
바뀌거나, 참조 등록 방식이 바뀌면 이 값은 무효다.
```

**표본 수를 반드시 남기십시오.** 이 값이 몇 개를 근거로 나왔는지가
재캘리브레이션 시점의 판단 근거입니다.

### 반영

- [ ] `UNRESOLVED` 레지스트리에서 `faceMatch.threshold` 제거
- [ ] 값을 **호출부에서 주입**한다 — `isMatch`의 시그니처는 그대로 두고
      호출부가 넘긴다 (`src/engine/faceMatch.ts`를 고치지 않습니다)
- [ ] throw를 기대하던 테스트가 깨진다 — **정상 신호입니다.** 값 검증
      테스트로 교체합니다
- [ ] 이 교체는 "기존 테스트 수정 금지"의 예외임을 커밋 메시지에 명시

> 반영 작업은 별도 위임 프롬프트로 만듭니다. 이 체크리스트는 **값을 얻는
> 것까지**입니다.

## 하지 말 것

- 측정을 위해 **타인 사진을 새로 수집하는 것**
- 유사도 로그·특징 벡터·사진을 **기기 밖으로 내보내는 것** (규칙 1)
- 쉬운 조건만 측정하고 미탐을 과소평가하는 것
- 표본 수를 기록하지 않는 것
- 겹침이 발생했을 때 **혼자 판단하는 것** — 마스터 PM에게 올립니다
- 이 문서의 빈칸을 **추정값으로 채우는 것** — 측정하지 못한 항목은
  빈칸으로 두고 그 사실을 기록합니다
