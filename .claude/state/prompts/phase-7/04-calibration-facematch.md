## 왜 이 문서가 위임 대상이 아닌가

실기기 디버깅과 네이티브 모듈 연동은 메인 세션 몫이고, **관측 자체는 사람이
기기 앞에서 해야 합니다.** 서브에이전트는 폰 화면을 볼 수 없습니다.

메인 세션이 하는 것은 0단계(측정 도구 준비)뿐이고, 1단계부터는 대표님이
직접 수행합니다.

---

## 절대 원칙 (모든 단계에 적용)

> **타인 표본은 이미 기기에 있는 사진만 사용한다. 측정을 위해 새로 수집하지 않는다.**
>
> **임계값은 타인 표본 관측 최댓값 + 여유로 정한다. 표본이 적을수록 여유를 크게 잡는다.**

그리고 규칙 1 — **얼굴 데이터는 기기 밖으로 나가지 않습니다.** 유사도 수치를
기록할 때 사진·특징 벡터를 함께 옮기지 않습니다. 옮기는 것은 **숫자뿐**입니다.

> 규칙 1은 **반출** 금지이지 반입 금지가 아닙니다. 공개 얼굴 데이터셋을
> 쓰지 않는 이유는 규칙이 아니라 **분포 불일치** 때문입니다 — 조명·각도·화질이
> 실사용과 달라 임계값 근거로 쓸 수 없습니다.

## 왜 표본 요구량이 비대칭인가 (읽고 시작할 것)

오탐 회피가 우선으로 확정됐습니다(Part 9-4). 그래서 두 오류의 측정 요건이 다릅니다.

| | 필요한 것 | 표본 |
|---|---|---|
| **오탐** (남이 우리 앨범에 들어옴) | 타인 얼굴 유사도의 **관측 최댓값** | 적어도 됨 |
| **미탐** (우리 사진이 안 잡힘) | 본인 얼굴 유사도의 **하위 분포** | 변형으로 충분히 확보 |

임계값을 타인 관측 최댓값 위에 두므로, **표본이 적으면 참 최댓값을 과소추정**하고
그만큼 여유를 더 얹게 됩니다. 결과적으로 임계값이 더 보수적인 쪽 — 오탐이 적고
미탐이 많은 쪽 — 으로 밀립니다. **그게 확정된 우선순위와 같은 방향이라, 표본
부족이 이 절차를 무효로 만들지 않습니다.**

다만 **표본의 구성은 다릅니다.** 수가 적은 것은 괜찮지만, 닮은 사람이 빠지면
관측 최댓값 자체가 틀립니다 (3단계 참조).

## 0단계 — 측정 도구 준비 (메인 세션 작업, 폰 복귀 후)

**현재 유사도 숫자를 볼 방법이 없습니다.** `isMatch(similarity, threshold)`는
불리언만 반환합니다. 측정하려면 원시 유사도가 화면에 떠야 합니다.

메인 세션에 요청할 것.

- 사진 한 장과 참조 얼굴의 **원시 유사도 값을 화면에 표시**하는 임시 디버그 화면
- 값은 반올림하지 않고 그대로 표시 (소수점 이하가 판단에 필요합니다)
- **온디바이스에서만 계산하고 어디에도 전송하지 않습니다**
- 프로덕션 화면이 아니라 개발 빌드 전용 임시 화면입니다

> 이 화면은 캘리브레이션 종료 후 제거하거나 개발 빌드에만 남깁니다.
> 유사도 노출은 정식 기능이 아닙니다.

- [ ] 디버그 화면 동작 확인

## 1단계 — 척도의 방향 확인 (가장 먼저)

**반환값이 유사도인지 거리인지 확인합니다.** 방향이 반대면 이 절차 전체가
뒤집힙니다("최댓값 + 여유" → "최솟값 − 여유").

- [ ] 같은 사람의 사진 두 장을 비교했을 때 값이 **큰가 작은가**
- [ ] 명백히 다른 사람의 사진을 비교했을 때 값이 **작은가 큰가**

| 관측 | 척도 | 임계값 규칙 |
|---|---|---|
| 같은 사람 = 큰 값 | 유사도 | 임계값 **이상**이면 매칭. 타인 최댓값 **+** 여유 |
| 같은 사람 = 작은 값 | 거리 | 임계값 **이하**면 매칭. 타인 최솟값 **−** 여유 |

**기록:** 척도 = ______________ / 관측 예시 값 ______ , ______

> 이하 이 문서는 **유사도(큰 값 = 닮음)** 기준으로 씁니다. 거리로 확인되면
> 부등호와 최대/최소를 전부 뒤집어 읽으십시오.

- [ ] 값의 범위 확인 (예: 0~1인지, 0~100인지) — 기록: ______
- [ ] SDK 이름과 버전 기록: ______________ (재캘리브레이션 조건입니다)

## 3단계 — 타인 표본 확보 (오탐 측정용)

> **이미 기기에 있는 사진만 사용합니다. 새로 수집하지 않습니다.**

### 혈연을 우선 포함할 것 (필수 요건)

**오탐의 최악은 무작위 타인이 아니라 닮은 사람입니다.** 그리고 커플 앨범에
가장 자주 등장하는 타인이 가족입니다. 부모·형제 사진은 거의 확실히 갤러리에
있고, 형제자매 유사도는 친구보다 구조적으로 높습니다.

**친구·행인만으로 잰 관측 최댓값은 실사용 위험을 체계적으로 과소추정합니다.**
그러면 임계값이 실제보다 낮게 잡히고, 오탐 회피 우선이라는 확정 사항이
숫자에서 배신당합니다.

- [ ] **혈연(부모·형제자매)이 찍힌 사진을 우선 포함한다**
- [ ] 본인 쪽 혈연과 연인 쪽 혈연 **양쪽** 모두 시도한다
- [ ] 구할 수 없으면 **그 사실 자체를 기록하고 8단계에서 여유를 크게 잡는다**

### 나머지 표본

- [ ] 갤러리에서 **본인·연인이 아닌 얼굴**이 나오는 사진을 고른다
      (단체 사진, 친구가 찍힌 사진, 배경에 사람이 들어간 사진 등)
- [ ] 한 사진에 여러 얼굴이 있으면 각각을 별개 표본으로 센다
- [ ] **얼굴이 알아볼 수 있게 나온 것만** 포함한다. 뒷모습·심한 흐림은 제외

### 표본 수와 구성을 반드시 기록하십시오

유저가 쌓여 재캘리브레이션할 때, 초기 임계값이 몇 장을 근거로 나온 값인지
알아야 얼마나 신뢰할지 판단할 수 있습니다. 규준집단에 `normVersion`을 붙인
것과 같은 이유입니다.

```
혈연 (본인 쪽)   ______ 개 / ______ 명
혈연 (연인 쪽)   ______ 개 / ______ 명
친구·지인        ______ 개 / ______ 명
행인·배경        ______ 개 / ______ 명
합계             ______ 개 / ______ 명
```

- [ ] 혈연 표본이 0이면 그 사실을 굵게 기록
- [ ] 전체 표본이 10개 미만이면 그 사실을 기록

### 겹칠 경우

임계값 하나로 두 오류를 동시에 막을 수 없다는 뜻입니다. 오탐 회피가 우선이므로
**타인 최댓값 위에 두고, 겹치는 구간의 본인 사진은 놓칩니다.**

- [ ] 겹치는 구간에 들어간 본인 표본이 **어떤 조건**이었는지 기록
- [ ] 그 조건이 실사용에서 흔한지 판단

### EXIF 보완을 감안할 것

**미탐은 얼굴 매칭만으로 결정되지 않습니다.** Phase 6-7단계의 EXIF 클러스터링이
같은 날·같은 장소 사진을 시공간으로 묶으므로, 얼굴이 안 잡혀도 완전히
사라지지는 않습니다(Part 9-4 판정 정책의 근거).

**다만 EXIF가 건지는 것과 얼굴이 건지는 것은 다릅니다.**

| EXIF가 건지는 것 | EXIF가 못 건지는 것 |
|---|---|
| 데이트 당일 같은 장소에서 찍힌 여러 장 | 단독 셀카 한 장 |
| 시간·위치가 이어지는 묶음 | 카톡으로 전달받아 EXIF가 벗겨진 사진 |
| 위치 권한이 켜진 상태의 촬영 | 스크린샷·저장 이미지 |

- [ ] 겹친 조건의 사진이 **EXIF로 건질 수 있는 종류인지** 판단해 기록
- [ ] 건질 수 있다면 감수 가능성이 올라갑니다. **없다면 EXIF는 위안이 안 됩니다**
- [ ] **최종 판단은 마스터 PM에게 올립니다.** 여기서 결정하지 마십시오

## 8단계 — 임계값 결정

**타인 관측 최댓값 + 여유**로 정합니다.

여유를 얼마로 잡을지는 아래 재료를 놓고 결정합니다. **표에 미리 숫자를 넣지
않은 것은 의도적입니다** — 실측 분포를 보기 전에 정하면 근거 없는 값이 됩니다.

| 요소 | 방향 |
|---|---|
| **혈연 표본이 없다** | 참 최댓값을 크게 과소추정 → **여유를 많이** |
| 혈연 최댓값이 비혈연과 비슷하다 | 표본 부족 신호 → **여유를 크게** |
| 타인 표본 수가 적다 | 과소추정 가능성 → **여유를 크게** |
| 타인 표본의 인물이 다양하다 | 최댓값이 신뢰할 만함 → 여유를 작게 |
| 타인 값들이 최댓값 근처에 몰려 있다 | 더 높은 값이 존재할 여지 → **여유를 크게** |
| 본인 최솟값과 간격이 넓다 | 여유를 키워도 미탐이 안 늘어남 → **크게 잡아도 손해 없음** |
| 본인 최솟값과 간격이 좁다 | 여유를 키우면 미탐 증가 → 7단계 판단과 함께 봄 |

## 9단계 — 기록과 반영

### 임계값의 거처 — 코드 상수 (확정)

**`app_config`가 아니라 호출부의 코드 상수입니다.** 계수 일반 규칙(10-7-5)의
예외입니다.

이 값은 SDK가 반환하는 척도에 종속되므로 **SDK 버전과 운명을 같이 합니다.**
`app_config`에 두면 재빌드 없이 값만 바뀌어 SDK와 어긋날 수 있고, 그건
조용히 틀리는 종류의 어긋남입니다. SDK 교체는 재빌드를 수반하므로, 상수로
두면 같은 배포 단위에서 함께 움직입니다.

### 반영

- [ ] `UNRESOLVED` 레지스트리에서 `faceMatch.threshold` 제거
- [ ] 값을 **호출부의 코드 상수**로 두고 `isMatch`에 인자로 넘긴다.
      `src/engine/faceMatch.ts`의 시그니처는 고치지 않습니다
- [ ] throw를 기대하던 테스트가 깨진다 — **정상 신호입니다.** 값 검증
      테스트로 교체합니다
- [ ] 이 교체는 "기존 테스트 수정 금지"의 예외임을 커밋 메시지에 명시

## 하지 말 것

- 측정을 위해 **타인 사진을 새로 수집하는 것**
- 유사도 로그·특징 벡터·사진을 **기기 밖으로 내보내는 것** (규칙 1)
- **혈연 표본을 빼고 친구·행인만으로 재는 것** — 최댓값 자체가 틀립니다
- 쉬운 조건만 측정하고 미탐을 과소평가하는 것
- 표본 수와 구성을 기록하지 않는 것
- 겹침이 발생했을 때 **혼자 판단하는 것** — 마스터 PM에게 올립니다
- 임계값을 `app_config`에 두는 것 — SDK와 어긋납니다
- 이 문서의 빈칸을 **추정값으로 채우는 것** — 측정하지 못한 항목은
  빈칸으로 두고 그 사실을 기록합니다
