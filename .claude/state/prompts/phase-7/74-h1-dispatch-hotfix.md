## 1. 먼저 확인 — 읽기만 (중간 보고 1회 후 계속)

| # | 확인 | 방법 |
|---|---|---|
| **a** | **혼자인 사용자의 기록이 어디에 저장됐나 · 웹 앱이 커플 행을 만들었나** | ① 웹 코드: 연결 전 사용자가 기록을 저장할 때의 경로를 읽는다. 어떤 RPC · 테이블에 쓰는지, `couples`에 insert하거나 커플 행을 만드는 RPC를 부르는지를 **파일:줄**로 적는다<br>② 데이터: 시험 계정의 행을 **표 이름 · 행 수 · `couple_id` 유무**로 정리한다(아래 "읽는 방법") |
| | 커플 행이 생겼다면 | `fn_connect_couple`이 "이미 커플 행이 있는 사용자"를 어떻게 다루는지(마이그레이션 · 함수 정의, 로컬 파일)와 초기화 스크립트의 거부 조건에 걸리는지를 적는다 |
| **b** | **초기화 스크립트가 왜 지우지 않았나** | Proteur의 미리 보기 출력(숫자)과 거부 이유 한 줄. a에서 커플 행이 생겼다면 "커플로 연결된 계정"으로 잘못 거부했을 가능성을 판정한다. **"연결됨"의 판정이 상대 사용자가 있는 커플인지, 커플 행이 있기만 하면인지**를 코드에서 확인한다 |
| **c** | **탈퇴 요청이 서버에 들어갔나** | 유예 행(또는 유예 표시 컬럼)이 있는지 읽기만 한다. 들어갔다면 요청 시각 + 7일 = **취소 시험 기한**을 적는다(PM 추정 11/16) |

**읽는 방법**(원격 쓰기 0, 키가 대화나 로그에 찍히지 않게):
- 초기화 스크립트의 **미리 보기 출력에 아래 줄을 더하는 것을 허가한다.** 지우는 동작은 바꾸지 않는다.
  - `couples` 행 수와 상대 사용자 유무(예/아니오)
  - 탈퇴 유예 여부(예/아니오)와 유예 시작일(날짜만)
- Proteur가 미리 보기를 돌려 **숫자와 예/아니오만** 붙인다.
- 메인 세션이 원격을 직접 읽어야 한다면 기존 운영 스크립트 방식(R53-6)만 쓰고, 그 방법을 보고한다.

**중간 보고**: a · b · c 표를 보고하고 **§2로 계속 간다.** 단 아래 경우에는 **멈춘다.**
- a에서 웹 앱이 커플 행을 만들었고, 그 행 때문에 `fn_connect_couple`이 실패하거나 잘못 연결할 수 있는 경우. 데이터 정리 방법은 PM이 정한다
- 정리에 마이그레이션이나 원격 쓰기가 필요한 경우

이미 생긴 데이터는 **지우지 않는다.** 정리는 PM 판단으로 초기화 스크립트를 써서 한다.
