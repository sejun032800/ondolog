## 범위 — 넷

### A. `buildCoeffBundle`을 비공개로 (r40)

- `coeffLookup.ts`의 `buildCoeffBundle`에서 `export`를 뗀다. 공개는
  `lookupCoeffBundle` 하나뿐이다
- **이 함수를 쓰던 테스트**를 정식 경로(`AppConfigQueryClient` 가짜 →
  `lookupCoeffBundle`)로 바꾼다. 1단계 보고에 따르면:
  - `coeffLookup.test.ts` — `buildCoeffBundle` 자체를 시험하던 블록들
  - `saveCornerResult.test.ts` — 픽스처 두 곳

  **착수 전에 직접 전부 찾아 목록을 보고**하고 시작한다. 위 목록이 전부라고
  가정하지 않는다

### B. `validateCornerContent` 제거, 정식 경로 `validateCornerResponse` (r38·r40)

- `validateCornerContent`를 지운다
- 공개 정식 경로 `validateCornerResponse`가 **§17-0-4의 순서 전체**를 따른다
  (`JSON.parse` → **`FORBIDDEN_KEYS`를 원본 객체에, 중첩까지 재귀** → Zod →
  명시적 빈 결과 → ID 해석 → 원문 채우기 → 저장 스키마)
- 4~6(빈 결과·ID 해석·원문 채우기)의 **코너별 내용은 3단계**다. 이번에는 그것을
  받는 자리와 순서만 만들고, 테스트는 **합성 스키마·합성 훅**으로 한다
- 브랜드를 붙이는 함수는 **비공개**. 캐스트는 승인 모듈 안 한 곳

### C. 호출 전 소속 단언 (r38, §17-0-5-E)

- 골격이 LLM을 부르기 **전에**, 입력 레코드의 커플이 **호출자 맥락의 커플**과
  같은지 확인한다. 맥락은 입력이 아니라 호출자에게서 온다
- 다르면 **전용 오류로 멈춘다.** 실패 사유를 기록하지 않고, 저장하지 않으며,
  오류를 **삼키지 않고 위로 전파**한다(호 전체 중단은 호출자의 일이다)
- 입력 레코드에서 커플을 어떻게 읽는지는 1부 설계를 따른다. 설계에 없으면
  **멈추고 보고**한다

### D. 규칙 E 확장 — 공개 여부 (r40)

- 승인 모듈 안에서 **브랜드 캐스트를 품은 함수가 `export`되어 있으면** 걸린다
- **판정은 TypeScript 컴파일러 API로 한다**(`typescript` 패키지로 소스를 파싱해
  함수·변수 선언과 `export` 여부를 본다). 문자열 검색으로 판정하지 않는다 —
  `export` 키워드의 위치, 화살표 함수, 재-export를 문자열로는 정확히 못 본다
- 함수 선언, `const` + 화살표 함수, `export { name }` 재-export를 모두 다룬다
- 기존의 위치 검사(승인 모듈 밖 캐스트 금지)는 그대로 둔다

## 기존 테스트 assertion — 고쳐도 된다, 사유와 함께

A·B·C 때문에 바뀌는 assertion은 고친다. **고친 assertion마다** 사유를 하나로
분류해 보고한다.

| 사유 | 뜻 |
|---|---|
| ① 금지 키 위치 | r38 순서 변경 |
| ② 함수 제거 | `validateCornerContent` |
| ③ 공개 해제 | `buildCoeffBundle` → 정식 경로 |
| ④ 소속 단언 | 새 동작 |

**이 넷에 들지 않는 assertion 변경은 하지 않는다.** 필요해 보이면 멈추고 보고한다.

옮긴 테스트들의 **머리 주석**(“왜 `require(경로변수)`인가” 등)은 이제 사실과
다르다. 지우거나 지금 사실에 맞게 고친다.
