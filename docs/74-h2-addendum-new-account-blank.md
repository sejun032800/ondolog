## 증상 (Proteur 녹화 11/10 18:33, 1분 13초 — PE 판독)

- 초기화 스크립트 `--apply`로 시험 계정을 지운 뒤, 같은 카카오 계정으로 **처음 가입하는 사람** 흐름을 시험했다.
- 온보딩 → 5문항 → 결과(KEELFROST · ISTJ) → 공유 → 동의(전체 동의) → 카카오(크롬 자동 로그인)까지는 정상이다.
- 앱으로 돌아와 "로그인하는 중이에요"(0:53.5)가 뜬 직후부터 **바탕색만 있는 빈 화면**이 계속된다(0:54 ~ 1:00).
- 앱을 최근 앱에서 지우고 다시 켜면 스플래시(1:08.5) 뒤 **다시 빈 화면**이다(1:09.5 ~ 끝).
- 즉 **세션은 저장됐지만, 새 계정 상태에 맞는 화면이 없다.** 부팅해도 같은 상태로 들어간다.
- 이 경로(G3 새 계정)는 `73-` 묶음 2부터 **한 번도 폰에서 확인되지 않았다**(시험할 새 계정이 없었음). 첫 사용자는 모두 여기서 막힌다.

## 할 일

| # | 할 일 |

| a | **원인 판정**: 새 계정이 로그인한 직후 서버에 무엇이 있고 무엇이 없는지를 코드와 마이그레이션(로컬)으로 따라간다. 예: 인증 사용자는 있음 / `profiles` 행 생성 주체(트리거인지 앱인지) / 결과 저장(`personality_*`) / 동의 기록 / 커플 행 없음. 앱의 계정 마무리(`finalize`)와 부팅 라우팅이 이 상태를 어떻게 다루는지 본다. **어느 단계에서 멈추거나 오류가 나고, 왜 아무 화면도 그리지 않는지**를 적는다. Proteur 로그(`%USERPROFILE%\Downloads\blank-log.txt`)가 있으면 읽기만 한다(h2 §0과 같은 규칙) |
| b | **고치기**: 새 계정이 첫 로그인하면 방금 본 결과가 계정에 저장되고(R65-2), 로그인 뒤 정해진 흐름(초대 · 연결 또는 메인 — 74- 구현대로)으로 간다. 재실행해도 같은 화면으로 간다 |
| c | **빈 화면 0 원칙**: 부팅 · 로그인 뒤 라우팅이 **모르는 상태를 만나면 빈 화면 대신** 안내 화면(다시 시도 · 로그아웃)을 보인다. 오류는 h2 ①-c 진단 표시(시험 빌드 전용)에 단계 이름으로 나온다 |
| d | **시험(상태표)**: 세션이 있을 때 서버 상태 조합마다 어느 화면으로 가는지 고정한다. 조합: 프로필 없음 · 프로필만 · 프로필 + 성격 · pending 커플 · active 커플 · 탈퇴 유예 · 조회 오류. **각 조합에서 빈 화면 0**. "로그인 직후"와 "재실행"을 둘 다 |
| e | 서버 쪽(트리거 · RPC · 정책)을 바꿔야만 고쳐지면 **멈춘다**(마이그레이션). 그때는 원인과 필요한 변경만 보고한다 |

## Proteur 폰 확인 (h2 확인 순서 맨 앞에 넣는다)

1. 초기화 스크립트 미리 보기 → `--apply`로 시험 계정을 다시 지운다(지난번 시험으로 생긴 반쪽 계정 정리)
2. 앱 삭제 → 재설치 → 처음 가입하는 사람 흐름 → 카카오 → **빈 화면 없이 다음 화면**
3. 앱 완전 종료 → 재실행 → 같은 화면
4. 성격 프로필에 방금 고른 결과가 저장돼 있음

보고에는 a의 원인 판정과 d의 상태표를 맨 앞에 둔다.
