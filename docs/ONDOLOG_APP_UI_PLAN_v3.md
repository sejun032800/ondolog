## 0. 기존 디자인 시스템과의 관계 — 확정

`docs/ONDOLOG_DESIGN.md`의 앱 관련 규칙 다섯 개를 이 문서가 대체한다. **UI 파트는 이 문서가 우선한다**(PM 확정).
`ui-builder`는 앱 화면 작업 시 이 문서를, 발행물 조판 작업 시 DESIGN.md를 읽는다. 두 문서를 동시에 참조하지 않는다.

DESIGN.md §17의 검증 grep 5종 중 **앱 디렉터리(`app/`, `src/components/`)에 대한 그라디언트·그림자·라운드 검사는 폐기**한다. 하드코딩 색 검사와 `fontWeight` 검사는 유지한다.

| DESIGN.md 규칙 | v2에서 |
|---|---|
| 그라디언트 금지 (표지 사진 제외) | **깬다.** 밤하늘 그라디언트가 이 방향의 정체성 |
| 아이콘을 쓰지 않는다 | **부분적으로 깬다.** 탭바는 여전히 텍스트, 리스트 행에만 `→` 유지 |
| 그림자·elevation 0건 | **깬다.** 글로우로 대체 (그림자가 아니라 발광) |
| `borderRadius ≤ 2` | **깬다.** 카드 20, 버튼 16 |
| 종이색 + 세리프 중심 | **깬다.** 심야 보라 + Pretendard 중심 |

### 0-1. 그럼에도 절대 안 깨는 것

| 지켜야 하는 것 | 이유 |
|---|---|
| **잉크 위계 (`ink('metric'/'narrative'/'verbatim')`)** | 제품 윤리의 시각화. 매체만 바뀌고 의미는 그대로 (§2-3) |
| **토큰 밖 하드코딩 금지** | `palette.ts` 단일 원본 유지 |
| **스피너·카운트업 금지** | 관측값을 성과로 보이게 하면 안 된다 |
| **발행물 6테마의 조판 규칙** | 발행물은 건드리지 않는다 |

### 0-2. 해결 — 선을 다시 긋는다

섞지 않는다. **역할로 나눈다.**

```
앱            = 밤.  재료를 넣고 기다리는 곳.        심야 보라 · 산세리프 · 글로우
발행물(PDF)    = 낮.  완성품을 읽는 곳.              종이 · 세리프 · 6테마
```

**두 세계의 대비가 제품 경험이 된다.** 한 달간 어두운 앱에서 재료를 모으다가, 발행일에 매거진을 열면 종이가 펼쳐진다. 이 전환이 "발행됐다"는 감각을 만든다. 둘을 같게 만들면 이 순간이 사라진다.

그래서 **매거진 뷰어 진입 지점에 전환 연출**을 둔다(§5-4).

## 1. 레퍼런스에서 가져온 것

세 레퍼런스에서 각각 무엇을 가져왔는지 명시한다. 나중에 "왜 이렇게 했나"를 되물을 때 근거가 된다.

### 1-1. 코끼리 — 감각과 몰입

| 가져옴 | 버림 |
|---|---|
| 심야 보라 그라디언트 배경 | 캐릭터 일러스트 |
| 별·유성 같은 미세 앰비언트 | 판타지 세계관 |
| 발광하는 숫자·오브젝트 | 명상 콘텐츠 문법 |
| 화면 상단을 비우고 아래에서 올라오는 구조 | |

> 일러스트를 버리는 이유: 온도록의 주인공은 **두 사람의 사진**이다. 일러스트가 들어오면 사진과 경쟁한다. 코끼리에서 가져올 것은 그림이 아니라 **밤의 공기**다.

### 1-2. 토스 — 명료함

| 가져옴 |
|---|
| **한 화면 한 가지 일.** 스크롤 없이 끝나는 화면을 지향 |
| 숫자를 크게, 단위를 작게 — 이미 온도록 `74.2` 처리와 같다 |
| 리스트 행 + 우측 `→`. 카드를 남발하지 않음 |
| 문장형 카피 (`~했어요` / `~해요`) |
| 하단 고정 전폭 버튼 |
| 로딩을 스피너가 아니라 **뼈대(skeleton)** 로 |

### 1-3. 모니모 — 부드러움과 수집감

| 가져옴 | 버림 |
|---|---|
| 큰 라운드, 말랑한 카드 | 마스코트 캐릭터 |
| **쌓이는 감각** — 서재에 호가 늘어나는 것 | 포인트·리워드 게임화 |
| 파스텔 톤의 보조색 | 출석 체크 메커닉 |

> 마스코트를 버리는 이유: 로드맵에서 "AI 매거진 메이커 캐릭터"가 이미 **폐기**로 결정됐다. 그 결정을 뒤집지 않는다. 대신 수집감은 **호가 쌓이는 서재**로 구현한다.

### 1-4. 커플 앱 색감

핑크·코랄 계열을 액센트로 쓴다. 단, **배경으로 쓰지 않는다.** 전면 핑크는 유치해지고, 두 사람의 사진 톤과 충돌한다. 심야 보라 위의 따뜻한 액센트로만 등장시킨다.

## 2. 시각 언어

### 2-1. 색 — 심야 보라 + 따뜻한 액센트

배경 `#14102E` 기준 대비를 전부 실측했다.

| 토큰 | 값 | 대비 | 용도 |
|---|---|---|---|
| `night` | `#14102E` | — | 기본 배경 |
| `night-deep` | `#0C0920` | — | 하단 그라디언트 끝 |
| `night-lift` | `#1F1A3D` | — | 카드 표면 |
| `night-lift-2` | `#2A2350` | — | 눌림·선택 상태 |
| `text` | `#F3EFFA` | **16.2** | 본문, 제목 |
| `text-sub` | `#B9B2D8` | **9.1** | 보조 설명 |
| `text-mute` | `#8A83AE` | **5.2** | 캡션, 메타 |
| `text-faint` | `#5C5680` | 2.7 | 비활성 **(텍스트 금지, 선·아이콘 전용)** |
| `coral` | `#FF8E7F` | **8.3** | 온도, 수치 — **가장 중요한 액센트** |
| `pink` | `#F7A8C8` | **10.0** | 두 사람, 관계 |
| `peri` | `#9AA2F7` | **7.8** | 정보, 링크 |
| `rule` | `#2C2650` | — | 구분선 |

**대비 3.0 미만은 텍스트에 쓰지 않는다.** `text-faint`는 선과 비활성 요소 전용이다.

#### 그라디언트 — 네 개만 정의하고 그 밖은 만들지 않는다

| 이름 | 값 | 용도 |
|---|---|---|
| `sky` | `#1B1440` → `#14102E` → `#0C0920` (180deg) | 화면 배경 |
| `warm` | `#FF8E7F` → `#F7A8C8` (135deg) | 온도 숫자, 주요 버튼 |
| `dawn` | `#F7A8C8` → `#9AA2F7` (135deg) | 두 사람 연결 표현 |
| `veil` | `rgba(31,26,61,0)` → `#1F1A3D` (180deg) | 사진 위 텍스트 바닥 |

#### 글로우 — 그림자가 아니다

```
glow-soft   0 0 32px rgba(255,142,127,0.18)    온도 숫자
glow-card   0 8px 32px rgba(8,5,20,0.45)       카드 부양
```

그림자는 **물체가 빛을 막는 것**이고, 글로우는 **물체가 빛나는 것**이다. 이 화면에서는 후자만 쓴다.

### 2-2. 타이포 — Pretendard 중심, 세리프는 인용 전용

| 토큰 | 서체 | 크기/행간 | 용도 |
|---|---|---|---|
| `hero` | Pretendard Black | 72 / 76 | 온도 정수부 |
| `hero-unit` | Pretendard Bold | 30 / 34 | 온도 소수·단위 (정수부의 42%) |
| `display` | Pretendard Bold | 28 / 38 | 화면 제목 |
| `title` | Pretendard Bold | 19 / 28 | 섹션·카드 제목 |
| `body` | Pretendard Regular | 16 / 26 | 본문 |
| `sub` | Pretendard Regular | 14 / 22 | 보조 설명 |
| `caption` | Pretendard Medium | 12 / 18 | 메타, 라벨 |
| `kicker` | Pretendard Bold | 11 / 14, 자간 0.18em | 섹션 라벨 |
| **`quote`** | **MaruBuri Regular** | 17 / 30 | **두 사람의 말 인용 전용** |

> **세리프를 한 곳만 남긴 게 핵심이다.** 앱 전체가 산세리프인데 두 사람의 원문만 세리프로 뜨면, 그 문장이 **다른 재질**로 보인다. 발행물과의 연결고리이자 "이건 우리가 쓴 말"이라는 신호다. 잉크 위계의 `verbatim`을 서체로 구현한 것이다.

### 2-3. 잉크 위계의 번역 — 농도에서 광도로

DESIGN.md §0의 시그니처를 버리지 않고 **매체에 맞게 번역**한다.

| 개입도 | 인쇄에서 | 앱에서 | API |
|---|---|---|---|
| 높음 — 온도록이 계산한 값 | 세이지 액센트 | **코랄 + 글로우** (가장 빛남) | `ink('metric')` |
| 중간 — 온도록이 쓴 문장 | 먹 | `text` 크림, 산세리프 | `ink('narrative')` |
| 낮음 — 두 사람의 말 그대로 | 담묵 (가장 옅음) | `text-sub` + **MaruBuri 세리프** | `ink('verbatim')` |

인쇄에서는 "먹을 덜 묻혔다"가 은유였다. 화면에서는 **"온도록이 손댄 것일수록 빛난다"**가 은유다. 의미는 같다 — 개입도가 시각적으로 드러난다.

`inkHierarchy.ts`의 함수 시그니처는 그대로 두고 반환값만 바꾼다. 화면 코드는 수정이 없다.

## 3. 아이콘 정책 — 부분 해제

DESIGN.md는 아이콘 전면 금지였다. 이유 셋 중 하나(의존성)는 여전히 유효하므로 **라이브러리는 쓰지 않는다.**

| 대상 | 처리 |
|---|---|
| 탭바 | **텍스트 유지.** 이게 이 앱의 차별점이다 |
| 리스트 행 이동 | `→` 문자 |
| 증감·정렬 | `▲ ▼ ▾` 문자 |
| 닫기·뒤로 | `✕ ←` 문자 |
| 그 외 | **인라인 SVG 직접 작성.** `react-native-svg` 미사용, 필요 시 View 조합 |

라이브러리를 안 쓰면 재빌드가 없고, 아이콘 수가 자연히 억제된다.

## 4. 모션 — 절제하되 죽지는 않게

v1은 모션을 거의 전부 금지했다. 감각형 방향에서는 그러면 앱이 죽는다. **무엇이 움직여도 되고 무엇이 안 되는지**를 나눈다.

| 대상 | 모션 | 이유 |
|---|---|---|
| 배경 별 | 아주 느린 명멸 (8~12초 주기, 투명도 0.3↔0.7) | 밤의 공기. 정지하면 배경이 죽는다 |
| 화면 진입 | 아래에서 12px 올라오며 페이드 (220ms) | 코끼리의 상승 구조 |
| 카드 탭 | `scale 0.98` (120ms) | 토스의 촉감 |
| 하단 시트 | 스프링 (damping 0.8) | |
| 매거진 전환 | **§5-4 전용 연출** | 밤 → 종이 |
| **온도 숫자** | **없음** | 관측값이지 성과가 아니다 |
| **진행률 바** | **없음** | 유저 행동에 따라 멈춰 있을 수 있다 |
| **로딩** | 스켈레톤 펄스만 | 스피너 금지 |

## 5. 화면 기획

### 5-1. 메인 탭 — 온도 히어로

```
                                          (상단 비움, 별 앰비언트)

        O U R   T E M P E R A T U R E        ← kicker, text-mute

                 38.2°                       ← hero, warm 그라디언트 + glow
                                                소수부 42%

              어제보다 0.3 높아요              ← sub, text-sub

     ╭──────────────────────────────╮
     │  세준            ·            서영  │   ← 카드, night-lift
     │  KEELEMBER        MUSEFLARE     │      pink / peri
     │  온돌 같은        열대야 같은      │
     │  원칙주의자       낭만주의자       │
     ╰──────────────────────────────╯

     ╭──────────────────────────────╮
     │  I S S U E  0 1                 │
     │  첫 호를 만들고 있어요      41%   │   ← title + coral 수치
     │  ▬▬▬▬▬▬▬▬░░░░░░░░░░░░░       │
     │  대화 412 · 사진 18 · 데이트 1   │   ← caption
     │                    제작 현황 →   │
     ╰──────────────────────────────╯
```

| 상태 | 처리 |
|---|---|
| 첫날 | 증감 줄 미표시 |
| 하강 | `어제보다 0.2 낮아요`. **화살표·빨강 금지.** 관측이지 평가가 아니다 |
| 미연결 | 온도 `36.5°` 회색, 두 사람 카드는 좌측만, 하단은 초대 CTA |
| 발행 완료 | 제작 카드가 **표지 썸네일 + 읽기 버튼**으로 교체 |

```
우리 사이 인터뷰               3문항 남음  →   ← 행동 필요는 text(밝음)
  9월 7일까지 답하면 이번 호에 실려요
──────────────────────────────────
오프라인 셋로그                  기록 없음  →
  만난 날 기록을 남기면 실려요

발행 예정                        10월 1일
테마                                 기본  →
```

| 규칙 |
|---|
| 준비됨 = `text-mute` / 행동 필요 = `text`. **색으로 강조하지 않는다** |
| 액센트(코랄)는 수치 전용 |
| "기록 없음"을 실패로 쓰지 않는다. 주어를 유저의 부족이 아니라 기능 안내로 |
| 진행률 바 애니메이션 없음 |

### 5-3. 발행물 테마 선택 — 신규

6테마를 만들었는데 앱에 고르는 곳이 없다. **DB 컬럼도 없다.**

#### 색 스와치로 고르게 하지 않는다

테마는 색이 아니라 **편집 문법**이다. 러블리는 아치 크롭, 온돌은 세로쓰기와 광곽, 네온핑크는 그라디언트 바다. 동그라미 6개로는 전달되지 않는다.

**같은 지면을 6개 버전으로 보여주고 고르게 한다.**

```
발행물 테마                                  ← display

같은 지면을 여섯 가지로 조판해봤어요.
두 사람의 8월 대화가 들어가 있습니다.           ← sub

      ╭──────────────────╮
      │                  │
      │  [다정한 말들 1면]  │                 ← 1:1.414, 가로 페이징
      │                  │                    실제 렌더링 이미지
      │                  │
      ╰──────────────────╯
         ▬ ▭ ▭ ▭ ▭ ▭                      ← 막대 인디케이터 (원형 금지)

기본                                         ← title
여백이 콘텐츠가 되는 조판.
사진이 적어도 성립합니다.                      ← sub

  활자      세리프 라이트 · 넓은 자간
  사진      원본 톤 유지
  강한 코너  다정한 말들                      ← caption 3행 고정

╭──────────────────────────────────╮
│      이 테마로 발행하기               │      ← 하단 고정, warm 그라디언트
╰──────────────────────────────────╯
```

미리보기 지면으로 **다정한 말들 1면**을 쓰는 이유: 사진 의존도가 낮아 데이터가 적어도 성립하고, 테마별 활자·여백 차이가 가장 선명하며, 실제 두 사람 대화가 들어가 "내 잡지"라는 감각이 즉시 생긴다.

#### 언제 고르는가

**온보딩에 넣지 않는다.** 이미 8화면이라 이탈 위험이 크고, 그 시점에는 보여줄 대화가 없어 미리보기가 샘플이 된다.

→ **첫 호 제작 현황 화면의 `테마` 행**에서 진입한다. 미선택으로 발행일이 오면 기본 테마로 발행하고, 다음 호부터 변경 가능함을 안내한다. **선택을 강제해 발행을 막지 않는다.**

#### 변경 규칙

| 대상 | 변경 |
|---|---|
| 제작 중인 호 | 가능 |
| **발행된 호** | **불가** |
| 다음 호 | 가능 (`9월호부터 적용됩니다`) |

발행된 호의 테마가 바뀌면 잡지가 아니라 뷰어 설정이 된다.

#### 스키마 변경 필요

| 테이블 | 컬럼 | 이유 |
|---|---|---|
| `couples` | `magazine_theme` | 다음 호 적용값. 기본 `'basic'` |
| `issues` | `theme` | **발행 시점 고정값.** 불변 |

**두 컬럼을 나누는 게 핵심이다.** 하나로 두면 테마를 바꾸는 순간 과거 호 표지가 전부 바뀐다.

#### 5-3-6. 무료/구독 — 잠금은 선택에 걸고 열람에 걸지 않는다

PM 확정 [3]: **무료 티어는 기본 1종만. 단 6테마 미리보기는 무료 유저도 전부 볼 수 있다.**

| 동작 | 무료 | 구독 |
|---|---|---|
| 6테마 미리보기 넘겨보기 | **가능** | 가능 |
| 미리보기 화질·내용 | **동일** | 동일 |
| 기본 테마 선택 | 가능 | 가능 |
| 나머지 5종 선택 | 불가 | 가능 |

**미리보기를 흐리거나 워터마크를 씌우지 않는다.** 막힌 것을 제대로 보여주지 않으면 전환 동기가 생기지 않는다. 오히려 가장 좋은 상태로 보여줘야 한다.

##### 잠금 표현

| 요소 | 규격 |
|---|---|
| 배지 | 테마 이름 옆 `구독` — **텍스트 배지.** 자물쇠 아이콘 금지(아이콘 정책) |
| 배지 색 | 테두리 `rgba(255,142,127,.55)`, 글자 `#FFD6C8`, 라운드 999 |
| 미리보기 | **아무 처리도 하지 않는다.** 흐림·어둡게·워터마크 전부 금지 |
| 설명 3행 | 동일하게 노출 |
| 하단 버튼 | `구독하고 <테마>로 발행하기` |
| 버튼 위 한 줄 | `기본 테마는 지금 바로 쓸 수 있어요` — 막다른 길이 아님을 알린다 |

**버튼 위 한 줄이 중요하다.** 잠긴 테마를 보다가 나가려는 유저에게 **지금 당장 할 수 있는 일**을 남겨둔다. 이게 없으면 "구독 아니면 아무것도 못 한다"로 읽힌다.

##### 구독 만료 시 (v3.5 정정)

**기준은 "해지 시점"이 아니라 "구독 기간 만료 시점"이다.** 해지해도 기간이 남아 있으면 그 기간의 구독료는 이미 지불된 것이고, 그 기간에 발행되는 호는 선택한 테마로 나가야 한다. 해지 즉시 되돌리면 **제작 현황에서 한 달 내내 본 미리보기와 결과가 달라진다.**

| 대상 | 처리 |
|---|---|
| `couples.magazine_theme` | **구독 기간 만료 시점**에 `'basic'` |
| `issues.theme` | 불변 |

> `issues.theme`가 여기서 두 번째 일을 한다 — 과거 호를 지키는 것(결정 2)과, **구독 상태 변화로부터 발행물을 격리하는 것.**

#### 5-3-7. 만료 예고 — 표지가 말없이 바뀌면 안 된다

**예고 없이 표지가 바뀌면 유저는 오류로 읽는다.** 만료 후 첫 발행 전까지 제작 현황 화면에 예고를 띄운다. (목업 21)

##### 배치

**진행률 바 바로 아래.** 근거:

| 후보 | 판단 |
|---|---|
| 화면 최상단 | 진행률보다 위에 두면 이 화면의 주인공이 바뀐다. 제작 현황은 재료를 보는 곳이다 |
| **진행률 아래 (채택)** | 화면을 열면 바로 보이면서, 수치보다는 아래다 |
| 하단 `테마` 행 옆 | 스크롤해야 보인다. 놓치면 예고가 아니다 |

##### 문구

```
이번 호는 기본 테마로 발행돼요
구독 기간이 8월 31일에 끝났어요. 러블리로 발행하려면
10월 1일 전에 구독을 이어가면 돼요.
[ 구독 이어가기 ]  [ 테마 다시 보기 ]
```

| 원칙 | 적용 |
|---|---|
| **결과를 먼저 말한다** | 제목이 "구독이 끝났어요"가 아니라 **"이번 호는 기본 테마로 발행돼요"**. 유저가 알아야 할 건 과금 상태가 아니라 **발행물이 어떻게 나가는가**다 |
| **되돌릴 방법과 기한을 함께 준다** | `10월 1일 전에` — 마감이 있으면 행동이 가능해진다 |
| **막다른 길을 만들지 않는다** | 버튼 두 개. `테마 다시 보기`는 구독 없이도 열린다(§5-3-6 열람 개방) |
| **실패로 표현하지 않는다** | 경고색·느낌표·에러 아이콘 금지. 일반 카드와 같은 `night-lift` |

##### 하단 `테마` 행

```
테마        기본 · 러블리에서 변경됨  →
```

무엇이 무엇으로 바뀌었는지 남긴다. 예고 카드를 닫거나 놓쳤을 때의 **두 번째 기록**이다.

##### 해제 시점

구독을 이어가면 예고 카드가 즉시 사라지고 `테마` 행이 `러블리`로 돌아온다. 발행 후에는 카드를 띄우지 않는다 — 이미 지난 일이다.

### 5-4. 밤에서 종이로 — 전환 연출

이 방향의 하이라이트다. 앱은 어둡고 발행물은 밝다. 그 낙차를 **연출로 쓴다.**

```
[표지 탭]
  ↓  배경이 night → paper 로 400ms 크로스페이드
  ↓  동시에 표지가 화면 전체로 확대 (scale 1.0 → 1.08, 320ms)
  ↓  상단바 아이콘 색 반전
[속표지 화면 — 밝은 종이 배경]
```

속표지는 **발행물 팔레트**를 쓴다. 앱 안에서 유일하게 밝은 화면이다.

```
        [표지 이미지 전폭]

V O L . 0 2                                  ← kicker
8월호                                         ← 세리프 display
2026년 9월 1일 발행 · 코너 5편 · 19면

수 록  코 너
데이트 아카이브 · 우리의 연애 DNA
다정한 말들 · 이달의 우리 · 연애리그            ← MaruBuri

[ 읽 기 ]                                     ← 발행물 잉크색 버튼
[ 공유 카드 만들기 ]
```

PDF 뷰어를 바로 열지 않고 속표지를 두는 이유: 뷰어는 로딩이 있고 되돌아오기 번거롭다. 속표지가 **완충**이 되고, 동시에 "이 호에 무엇이 실렸는지"를 읽게 한다. 잡지 속표지와 같은 기능이다.

### 5-5. 피드 탭

```
피드                              피드 ▾ / 지도

╭──────────────────────────────────╮
│  [사진 16:9, 라운드 16]              │
│  ▔▔▔▔▔ veil 그라디언트 ▔▔▔▔▔       │
│  2026.08.19  연남동                  │
│  스파이더맨과 케이크 사이               │   ← 사진 위 텍스트
╰──────────────────────────────────╯
  사진 11 · 메모 2              사진 추가 →
```

v1의 헤어라인 구분 대신 **카드**를 쓴다. 감각형 방향에서는 사진이 주인공이므로 사진을 띄운다.

#### 미탐 복구 창구는 피드에 둔다

얼굴 인식이 놓친 사진을 사람이 되살리는 경로다. 로드맵은 Phase 10(제작 탭)으로 두었는데 **피드가 맞다.** 제작 탭에서 추가하면 "어느 데이트에 속하는지"를 유저가 다시 골라야 하지만, 피드의 데이트 카드에서 추가하면 **소속이 자동으로 정해진다.**

#### 빈 상태 3종

| 상태 | 문구 |
|---|---|
| 미연동 | 기존 동의 카드 유지 |
| 연동했으나 인식 0 | `아직 두 사람이 함께 있는 사진을 찾지 못했어요` + `직접 추가하기` |
| 미연결 | 내 기록만. 통합 영역은 초대 유도 |

### 5-6. 채팅 탭

말풍선을 쓰되 라운드를 20으로 키운다.

| 항목 | 규격 |
|---|---|
| 내 메시지 | `warm` 그라디언트 배경, `#14102E` 글자, 우측 |
| 상대 메시지 | `night-lift` 배경, `text` 글자, 좌측 |
| 최대 폭 | 76% |
| 라운드 | 20 (말꼬리 방향만 6) |
| 시각 | `caption`, `text-mute`, 말풍선 밖 |
| 입력창 | `night-lift`, 라운드 999, 하단 고정 |

#### 인용 예고는 하지 않는다

다정한 말들에 실릴 후보를 채팅에 표시하면, 유저가 "실리는 말"을 의식해서 쓰기 시작한다. **그 순간 원문의 가치가 사라진다.** 발행물은 사후에 발견되어야 한다.

대신 매거진에서 인용을 탭하면 채팅의 그 시점으로 이동하는 **역방향 연결**만 만든다.

### 5-7. 설정 탭 (구 버전 — §5-9로 대체)

"테마"가 두 개가 되는 문제를 정리한다.

| 항목 | 이름 | 위치 |
|---|---|---|
| 앱 화면 | **화면 모드** | 설정 |
| 발행물 조판 | **발행물 테마** | 매거진 (설정에서도 진입) |

> **v2에서 앱은 다크 단일이다.** 심야 보라가 정체성인데 라이트 모드를 만들면 두 개의 앱이 된다. `화면 모드` 행은 **제거**하거나, 남긴다면 "시스템 설정 따름" 없이 다크 고정임을 표시한다. → §8 PM 결정 1번.

### 5-8. 우리의 하늘 — 신설

메인 탭을 **강하게 끌어내리면** 화면 위쪽에서 밤하늘이 내려와 전체 화면으로 펼쳐진다. 두 사람의 기록이 하늘이 된다.

| 하늘의 요소 | 무엇으로 만드는가 | 누르면 |
|---|---|---|
| **별** | 함께한 하루 하나 = 별 하나. **색은 그날 대표 사진에서 뽑는다** | 그날의 사진과 메모가 열린다 |
| **별자리** | 같은 달의 별들이 한 구역에 흩어진다 = **그 달의 호**. 선은 긋지 않는다 (v3.1) | — |
| **유성** | 채팅에서 오간 **다정한 말** 하나. 간헐적으로 떨어진다 | 그 말이 원문 그대로 뜬다 |
| **지평선** | 사귄 날부터 오늘까지 (`D+298`) | — |

#### 왜 이 구조인가

온도록은 **월간지**다. 한 달 동안 뜬 별들이 선으로 이어지면 **"8월자리"**가 되고, 그게 곧 8월호다. 하늘을 위로 올려다볼수록 지난 달의 별자리가 나온다. 매거진 서재가 **책장**이라면 하늘은 **같은 기록의 다른 모양**이다. 새 데이터가 필요 없다 — 데이트 기록과 다정한 말들 코너가 이미 만드는 재료다.

#### 5-8-1. 여는 동작 — 끌어내리기

일반적인 당겨서 새로고침과 구분해야 한다. **메인 탭은 실시간 갱신이라 새로고침이 필요 없으므로** 이 제스처를 하늘에 쓴다.

| 당긴 거리 | 반응 | 목업 |
|---|---|---|
| 0 – 60pt | 일반 오버스크롤. 아무 일 없음 | 01 |
| 60 – 140pt | 위에서 하늘이 스며든다 (불투명도 0 → 0.6). 지난 별자리가 흐리게 보임. `더 당기면 하늘이 열려요` + 짧은 게이지 | **02** |
| **140pt 도달** | **가벼운 햅틱 1회.** 문구가 `놓으면 하늘이 열려요`로 바뀌고 게이지가 코랄로 참 | **03** |
| 140pt 이상에서 놓음 | 하늘이 전체 화면으로 열림 (480ms). 탭바가 아래로 사라짐 | 04 |
| 140pt 미만에서 놓음 | 스프링으로 원위치 | — |

| 규칙 |
|---|
| 스크롤이 **맨 위일 때만** 동작한다. 중간에서 당기면 일반 스크롤 |
| 햅틱은 임계 통과 시 **한 번만**. 오가며 여러 번 울리지 않는다 |
| 닫기: 우상단 `✕`, 또는 지평선에서 위로 쓸어올리기 |

**발견성** — 첫 진입 시 온도 위에 `✦ 끌어내리면 우리의 하늘이 있어요`를 한 번 띄운다(**01**). 하늘을 한 번 열면 사라진다. 그 뒤에는 `✦` 하나만 남아 반짝인다.

#### 5-8-2. 별 — 함께한 하루

| 속성 | 결정 요소 |
|---|---|
| **색** | 그날 대표 사진의 평균색 → 명도 0.80, 채도 ≥0.62로 끌어올려 발광색으로 |
| **크기** | 그날의 기록량 (사진 수 + 메모 여부). **코어 2.2 – 4.2pt** + 사진색 후광 (v3.1) |
| **분홍 고리** | 두 사람이 **직접 메모를 남긴 날**. 원문 우선 원칙을 하늘에서도 드러낸다 |
| **점선 고리** | 기념일 (100일 단위, 1주년 등) |
| **위치** | 같은 달끼리 한 무리. 달이 지날수록 위로 올라간다 |
| **날짜 라벨** | 별 아래 10pt, 옅게 |

> **사진을 별 자체로 쓰지 않는다.** 작은 사진 썸네일 수십 개가 하늘에 뜨면 앨범이 된다. 별은 **빛**이고, 사진은 **눌렀을 때** 열린다. 그러면서도 별의 색이 그 사진에서 왔기 때문에 "사진으로 만든 별"이라는 기획이 지켜진다.

**배경 별과 데이터 별은 확실히 달라야 한다.** 배경 별(장식)은 1 – 2pt에 글로우 없음, 터치 불가. 데이터 별은 6pt 이상에 이중 글로우. 헷갈리면 유저가 아무 점이나 누르다 실망한다.

**별을 누르면** (**07**): 별이 원형 사진으로 커지며 테두리가 그 별의 색으로 빛난다. 아래 카드에 날짜·장소·제목·기록량, 그리고 **메모는 MaruBuri 세리프로 원문 그대로**.

| 버튼 | 이동 |
|---|---|
| 사진 모두 보기 | 사진 뷰어 (**08**) |
| 8월호에서 읽기 | 발행된 호의 해당 기사 — 아직 발행 전이면 버튼 숨김 |

**기념일 별** (**11**): 카드 상단에 `기 념 일 별` 키커. 테두리는 분홍 대신 **옅은 금빛**.

#### 5-8-3. 유성 — 다정한 말

| 항목 | 규격 |
|---|---|
| 출처 | **다정한 말들 코너의 후보 풀.** 새 로직을 만들지 않는다 |
| 첫 유성 | 하늘을 연 뒤 3 – 5초 안에 한 번 (발견용) |
| 이후 | 12 – 25초 간격, 무작위 |
| 동시 개수 | **최대 1개** |
| 궤적 | 우상단 → 좌하단, 약 33도. 비행 2.4초 |
| 터치 영역 | 머리 기준 반경 32pt + 꼬리 따라 64pt. **빠른 물체라 넉넉하게** |

**누르면** (**06**): 유성이 그 자리에 멈추고 하늘이 어두워지며 카드가 뜬다.

```
떨 어 진  말                        ← 키커, 분홍
기다릴게                            ← MaruBuri 25pt, 원문 그대로
야근이 길어진 밤                     ← 정황 (AI가 쓴 한 줄 — 먹)
서영 · 2026.08.14 23:12             ← 출처
───────────────
이 말이 실린 호 · 8월호     채팅에서 보기 →
```

`채팅에서 보기`는 채팅방의 **그 시점으로 이동**한다. v2 §5-6의 역방향 연결이 여기서 실현된다.

첫 진입 시 한 번 `떨어지는 별을 눌러보세요` 칩을 띄운다(**05**).

#### 5-8-4. 이 기능이 부딪히는 원칙 — 먼저 적는다

**v2 §5-6에서 "채팅에 인용 예고를 하지 않는다"고 정했다.** 유저가 "실리는 말"을 의식하면 원문이 연출되기 때문이다. 유성은 같은 위험을 갖는다 — "다정한 말은 유성이 된다"는 걸 알면 유성을 만들려고 말을 고를 수 있다.

대응:

| 장치 | 효과 |
|---|---|
| **7일 지연** | 보낸 지 7일이 지난 말만 유성이 된다. 방금 한 말이 바로 떨어지지 않는다 |
| **채팅에 아무 표시도 하지 않는다** | 어떤 말이 후보인지 채팅 화면에서는 알 수 없다 |
| **무작위 간격** | 특정 말을 기다려 볼 수 없다 |
| **편집 불가** | 유성의 말은 원문 그대로. 다듬거나 요약하지 않는다 |

이 네 가지로 **발견은 사후에 일어나고, 조작의 여지는 줄인다.**

#### 5-8-5. 지난 하늘 (**09**)

하늘을 **위로 스크롤**하면 지난 달로 올라간다. 좌측 가장자리에 세로 눈금과 `2026.07`, `2026.06` 표기. 하단에 `↓ 8월로 내려가기`.

현재 달은 항상 **지평선 가까이**에 있다. 가장 최근이 가장 가깝다.

#### 5-8-6. 빈 하늘 (**10**)

| 상황 | 화면 |
|---|---|
| 데이트 기록 0 | 배경 별만. 가운데 점선 원 = 첫 별이 뜰 자리. `첫 데이트를 기록하면 이 자리에 첫 별이 떠요` + `데이트 기록하기` |
| 다정한 말 후보 0 | 유성 없음. 하단에 `다정한 대화가 쌓이면 유성이 떨어지기 시작해요` |
| 미연결 | 하늘을 열 수 없다. 끌어내려도 `연인과 연결되면 하늘이 열려요` 후 원위치 |

**가짜 별을 만들지 않는다.** 기록이 없으면 하늘은 비어 있다. 비어 있는 하늘이 채워지는 과정이 이 기능의 재미다.

#### 5-8-10. v3.1 — 사실적인 하늘로 재조정

PM 요청: 별이 **무작위로 흩어진 실제 밤하늘**이어야 하고, 점은 더 작고 사실적이어야 한다.

| 항목 | v3 | v3.1 |
|---|---|---|
| 배경 | CSS 그라디언트 + 점 150개 | **절차 생성 이미지** — 은하수·먼지띠·성운·별 약 4만 개·산 능선 |
| 데이터 별 | 6 – 15pt 발광 원 | **코어 2.2 – 4.2pt** + 사진색 후광 + 회절 십자광 |
| 별자리 선 | 같은 달 별을 선으로 연결 | **제거** |
| 달 표기 | 별무리 옆 `8 월 자 리` | 좌측 가장자리에 `8 월` — 성도(星圖)의 주석처럼 |
| 유성 | 굵은 분홍 꼬리 | 1.4px 흰 머리 + 푸른빛→분홍 꼬리, 236px |
| 지평선 | 분홍 타원 빛 | 라벤더 지평선 빛 + 완만한 산 능선 두 겹 |

**선을 지운 이유** — 선을 그으면 하늘이 도표가 된다. 실제 하늘에서 별자리는 **보는 사람이 찾아내는 것**이지 그려져 있는 게 아니다. 같은 달의 별이 한 구역에 모여 있고 좌측에 달이 적혀 있으면, 유저가 스스로 "이게 8월이구나"를 찾는다. 그 발견이 더 감각적이다.

**데이터 별이 작아져도 구분되는 이유** — 배경 별 약 4만 개 사이에서 데이터 별을 찾을 수 있어야 한다. 크기 대신 세 가지로 구분한다.

| 신호 | 배경 별 | 데이터 별 |
|---|---|---|
| 회절 십자광 | 없음 | **있음** — 망원경 사진의 밝은 별처럼 |
| 후광 색 | 흰색·청백색 | **그날 사진의 색** |
| 터치 | 불가 | 가능 (터치 영역 44pt — 점은 작아도 누르기 쉽게) |

**배경 이미지 생성** — 스톡 이미지를 쓰지 않는다(레퍼런스는 워터마크가 있는 스톡). `gen_sky.py`가 두 장을 만든다.

| 파일 | 용도 | 구성 |
|---|---|---|
| `sky_world.jpg` | **전 화면 공용** (v3.3) | 390×2000pt 하나의 세계. 아래는 지평선·산, 위로 갈수록 깊은 우주 |

**v3.2 — 배경 별 밀도 조정** (PM: 상호작용 안 되는 별이 너무 많다)

| 층 | v3.1 | v3.2 | 감소 |
|---|---|---|---|
| 미세 별 (1px) | 62,000 | 38,000 | -39% |
| 작은 별 (번짐) | 4,200 | 2,300 | -45% |
| **밝은 별 (후광)** | **190** | **75** | **-61%** |
| 은하수 반짝임 결 | 0.55 | 0.42 | -24% |

**밝은 별을 가장 많이 줄인 이유** — 후광이 있는 밝은 배경 별이 데이터 별과 가장 헷갈린다. 1px 미세 별은 폰 화면에서 은하수의 질감으로 읽히지 개별 별로 읽히지 않으므로 덜 줄였다. 은하수의 결은 남기고 **눈에 걸리는 점**만 걷어낸 것이다.

> 원칙: **하늘에서 눈에 띄는 점은 대부분 누를 수 있어야 한다.** 배경은 질감이고, 점은 기록이다.

생성 규칙:
- 하늘 바탕 4단 그라디언트 — 심청 `#06081F` → 남보라 `#1A1A68` → 보라 `#5230A8` → 라벤더 `#A87CEE`
- 은하수는 다중 스케일 노이즈 × 대각선 띠 마스크, 청색↔보라 혼색
- 먼지띠는 은하수 중심부에서 밝기를 최대 55% 깎는 별도 노이즈
- 별은 **멱법칙 밝기 분포** — 대부분 1px로 희미하고, 드물게 밝다. 은하수 쪽일수록 조밀
- 별 색은 청백 60% · 백 25% · 청 10% · 미황 5%
- 노이즈는 **실수(float)로 확대**한다. 정수로 양자화한 뒤 키우면 미세한 격자 무늬가 생긴다 (실제로 발생했다)

앱에서는 이 이미지를 한 장 깔고 그 위에 데이터 별만 그린다. 배경 별 수만 개를 View로 그리지 않는다 — 성능 문제가 없다.

#### 5-8-11. v3.3 — 하나의 연속된 세계

PM 정의: **메인 탭에서 끌어내리는 동작 = 현실에서 고개를 들어 밤하늘을 올려다보는 동작.**

그렇다면 메인 화면과 하늘은 **서로 다른 두 화면이 아니라 같은 세계의 다른 높이**여야 한다. v3.2까지는 메인 배경과 하늘 배경이 각각 다른 그림이어서, 여는 순간 장면이 '바뀌었다'. 연속성이 없으면 올려다보는 느낌이 나지 않는다.

**세계는 이미지 한 장이다.** `sky_world.jpg` — 390 × 2000pt (1170 × 6000px), 화면 높이의 약 2.4배.

```
세계 y        내용                          어느 화면이 비추나
────────────────────────────────────────────────────
1880 ~ 2000   땅 · 산 능선 두 겹              메인 탭 하단
1780          지평선 빛 (라벤더)              메인 탭
1156 ~ 2000   지평선 부근 하늘                메인 탭 (장막 72%)
 900 ~ 1464   이번 달 · 지난달 별             우리의 하늘
  60 ~  904   더 지난 달 별                   지난 하늘
   0 ~   60   깊은 우주                       (더 위)
```

**카메라는 세계를 위아래로 훑는다.** 화면이 바뀌는 게 아니라 시점이 올라간다.

| 상태 | 시점 오프셋 | 장막 | 비추는 구간 |
|---|---|---|---|
| 메인 (스크롤 0) | **1156** | 0.72 | 1156 – 2000 (지평선·땅) |
| 끌어내리는 중 | 1040 | 0.50 | 1040 – 1884 |
| 놓기 직전 | 900 | 0.20 | 900 – 1744 |
| 우리의 하늘 | 620 | 0 | 620 – 1464 |
| 지난 하늘 | 60 | 0 | 60 – 904 |

> 화면 y = **세계 y − 시점 오프셋**

**장막(veil)** — 메인에서는 UI가 읽혀야 하므로 하늘 위에 `rgba(9,7,26,.72)`를 덮는다. 당길수록 이 장막이 걷힌다. 대비 문제를 해결하면서 동시에 **"올려다볼수록 하늘이 또렷해진다"**는 감각을 만든다. 장막은 기능이자 연출이다.

**별도 세계 좌표를 갖는다.** 화면마다 따로 배치하지 않는다.

| 달 | 세계 y | 근거 |
|---|---|---|
| 9월 (이번 달) | 1240 | 가장 가깝다. 메인에서도 흐릿하게 보인다 |
| 8월 | 900 – 1100 | 하늘을 열면 정면 |
| 7월 | 480 – 700 | 더 올려다봐야 한다 |
| 6월 | 180 – 320 | 가장 멀다 |

**최근일수록 아래(가깝고), 과거일수록 위(멀다).** 시간이 거리로 번역된다.

**연속성의 증거** — 같은 별이 인접한 두 화면에 걸쳐 나타난다. `08.19` 별(세계 y 1010)은 '놓기 직전'에서 화면 상단에 나타났다가 '우리의 하늘'에서 화면 중앙으로 내려온다. `09.13`(세계 y 1240)은 메인에서도 흐릿하게 보인다. 유저는 **같은 별이 움직이는 것**을 보고 하나의 세계임을 안다.

**닫기는 완전한 역방향** — 하늘 하단에서 아래로 쓸면 시점이 1156까지 내려오고 장막이 다시 덮이며 메인 UI가 올라온다. 별도의 전환 화면이 없다.

##### 구현 메모

| 항목 | 방법 |
|---|---|
| 배경 | `ImageBackground` 1장을 `translateY`로 이동. 화면마다 다른 이미지를 쓰지 않는다 |
| 세계 높이 | **화면 높이 × 2.37**. 기기별로 스케일 (SE 667pt → 1581pt, Pro Max 932pt → 2209pt) |
| 별 | 세계 좌표를 갖는 배열 1개. 화면 밖(±40pt) 별은 렌더 제외 |
| 패럴랙스 | **쓰지 않는다.** 배경과 별이 1:1로 움직여야 같은 하늘이다 |
| 메인 UI | 시트가 `translateY`로 내려간다 |

> **주의 — `transform`은 쌓임 맥락을 만든다.** 메인 시트에 `translateY`를 걸면 그 안의 `z-index`가 바깥 장막보다 위로 올라가지 못한다. 시트 자체에 `z-index`를 명시해야 한다. 실제로 이 문제로 목업에서 메인 UI가 통째로 사라졌다.

## 7. 구현 순서

| 순서 | 작업 | 근거 |
|---|---|---|
| 1 | `palette.ts` v2 토큰 + `inkHierarchy` 반환값 교체 | 화면 코드 수정 없이 전체 톤 전환 |
| 2 | `SkyBackground` + `GlowNumeral` + `SoftCard` | 3개로 대부분 화면의 인상이 결정된다 |
| 3 | 메인 탭 재조판 | 가장 자주 보는 화면 |
| 4 | **테마 선택 화면** (스키마 2컬럼 포함) | 자산이 이미 있어 렌더링 비용 0 |
| 5 | 매거진 탭 — 제작 현황 | Phase 10 |
| 6 | 속표지 + 전환 연출 | Phase 8 |
| 7 | 피드 카드형 재조판 | Phase 6 |
| 8 | **우리의 하늘** — 별 + 별자리 | 데이트 기록(Phase 6) 이후 |
| 9 | **우리의 하늘** — 유성 | 다정한 말들 엔진(Phase 7) 이후 |

하늘은 **별(8)과 유성(9)을 나눠 출시**할 수 있다. 별은 데이트 기록만 있으면 되고, 유성은 코너 엔진이 필요하기 때문이다.

**1번이 먼저인 이유**: `inkHierarchy`가 이미 색을 추상화해뒀기 때문에, 토큰과 반환값만 바꾸면 기존 화면들이 전부 새 톤으로 따라온다. 화면 코드를 건드리지 않고 방향 전환을 검증할 수 있다.

## 9. 하지 않기로 한 것

| 항목 | 이유 |
|---|---|
| 캐릭터·마스코트 | 로드맵에서 이미 폐기 결정. 사진이 주인공 |
| 일러스트 배경 | 두 사람의 사진과 경쟁한다 |
| 전면 핑크 배경 | 유치해지고 사진 톤과 충돌 |
| 포인트·출석 게임화 | 관계를 성과로 만든다 |
| 온도 카운트업 | 관측값이지 성과가 아니다 |
| 채팅 인용 예고 | 원문이 연출되기 시작한다 |
| 원형 인디케이터 | 지면 문법이 아니다 |
| 잠긴 테마 미리보기 흐리기 | 막힌 것을 제대로 보여줘야 전환 동기가 생긴다 |
| 자물쇠 아이콘 | 아이콘 정책 위반. 텍스트 배지로 |
| 해지 즉시 테마 되돌리기 | 남은 기간의 구독료는 지불된 것. 미리보기와 결과가 달라진다 |
| 예고 없이 표지 변경 | 유저가 오류로 읽는다 |
| 아이콘 라이브러리 | 재빌드 유발 + 아이콘 수 통제 불능 |
| 발행된 호 테마 변경 | 발행이 되돌려지면 잡지가 아니다 |
| 사진을 별 자체로 쓰기 | 썸네일 수십 개가 뜨면 하늘이 아니라 앨범이 된다 |
| 기록 없는 날에 가짜 별 | 비어 있는 하늘이 채워지는 과정이 재미다 |
| 방금 보낸 말이 바로 유성 | 유성을 만들려고 말을 고르게 된다 |
| 유성 여러 개 동시에 | 하늘이 시끄러워지고 한 말의 무게가 사라진다 |
| 별 개수 경쟁·통계 | 다른 커플과 비교하는 순간 하늘이 성적표가 된다 |
| 별자리 연결선 | 하늘이 도표가 된다. 별자리는 보는 사람이 찾는 것 |
| 스톡 하늘 이미지 | 워터마크·라이선스. 절차 생성으로 대체 |
| 메인과 하늘에 다른 배경 | 장면이 바뀌면 올려다보는 느낌이 사라진다 |
| 배경·별 패럴랙스 | 따로 움직이면 같은 하늘이 아니게 된다 |
