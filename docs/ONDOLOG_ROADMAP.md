```
DOC_REVISION: 2026-10-04-r4
```

**MASTER의 마커와 번호가 독립이다.** 두 문서는 따로 바뀌므로 하나로 묶으면 한쪽만 바뀔 때도
둘 다 올려야 하고, 그러다 한쪽을 빠뜨린다. **사전 점검은 파일별로 확인한다.**

```powershell
Select-String -Path docs/ONDOLOG_ROADMAP.md -Pattern 'DOC_REVISION: <PM이 알려준 값>'
```

> **왜 생겼는가.** r27·r28에서 Phase 11을 신설했으나 저장소의 ROADMAP에 반영되지 않았고,
> MASTER에만 마커가 있어 아무도 잡지 못했다. `ui-builder`에게 Phase 11을 위임했다면 그

**2·4·6·7번은 메인 세션** — 네이티브 빌드 에러와 실기기 테스트가 반복된다.

#### 얼굴 인식 아키텍처 — 3단계

```
1단계 탐지    → 사진 속 얼굴 위치 (네이티브 SDK)
2단계 임베딩  → 얼굴을 숫자 벡터로 (네이티브 SDK)
3단계 매칭    → 벡터 유사도 비교 (순수 함수) ← 라이브러리 의존 없음
```

**1차 채택**: `react-native-expo-facial-recognition` (ArcFace ONNX, 온디바이스)
**교체 트리거**: 오탐지율 체감 / 특정 OS 크래시 / 6개월 방치 / 저사양 기기 성능

> **cloud sync 옵션을 활성화하지 않는다.** 로컬 저장 모드로만 사용한다 (절대 규칙 1).
> 매칭 로직을 `src/engine/faceMatch.ts`로 분리했으므로, 라이브러리를 교체해도 이 함수는 유지된다.

**선행 필요**: ~~생체정보 동의 UI~~ → 2026-08-27 화면 A 구현 완료. **법무 문구는 여전히 자리표시자.**

```
원재료 수집 → 충분성 판정 → LLM 호출 → JSON+Zod 파싱(3회 재시도)
→ 금지 키 검사 + 원문 대조 → 미디어를 magazine 버킷 복제 → 저장
```

**절대 놓치면 안 되는 것**
- 6단계(미디어 복제) 생략 시 원본 삭제하면 발행물이 깨진다
- `sweet_words`는 저장 전 원문과 **문자 단위 대조**
- MVP 외 7개 코너는 **content 구조가 없으므로 생성 코드 작성 금지**

**선행 필요**
- ~~AI 매거진 메이커 캐릭터 설계~~ → **폐기.** 캐릭터화하지 않는다 (MASTER Part 9-3)

| 규칙 | 내용 |

Phase 9까지 끝나면 MASTER Part 7-5의 Must Have 8개가 모두 구현된 상태가 된다.

## 7. Phase 2 확장 (MVP 이후)

> ⚠️ **선행 조건: Phase 10(매거진 제작 탭)이 완료되어야 착수 가능하다.**
> 참여형 코너 3종(셋로그·인터뷰·특별 게스트)이 제작 탭을 유일한 입력 창구로 삼는다.

MVP 9개 항목이 검증된 뒤 착수한다. **기획은 완료, 구현은 미착수.**

| 코너 | 기획 | 스키마 | content 구조 |
|---|---|---|---|
| 우리 사이 인터뷰 | ✅ MASTER 17-6 | ✅ SCHEMA 9-B | ❌ |
| 오프라인 셋로그 | ✅ MASTER 17-7 | ✅ `entry_type` 확장 | ❌ |
| 특별 게스트 | ✅ MASTER 17-8 | ✅ SCHEMA 9-B | ❌ |
| 얼렁뚱땅 어림짐작 | ✅ MASTER 17-9 | 신규 테이블 불필요 | ❌ |

**착수 순서 제안**

| 순서 | 코너 | 이유 |
|---|---|---|
| 1 | 얼렁뚱땅 어림짐작 | 새 테이블 없음, LLM 호출 거의 없음, `engine-dev` 단독 |
| 2 | 오프라인 셋로그 | `entry_type` 추가만. 매거진 제작 탭 입력 구조 검증 |
| 3 | 우리 사이 인터뷰 | 신규 테이블 3종 + 참여 플로우 |

난이도와 인프라 부담이 낮은 순서다. 4번은 앱 밖 웹 호스팅이 처음 등장하는 지점이라 마지막에 둔다.

**선행 조건**: 매거진 제작 탭(MASTER Part 9-5)이 구현되어 있어야 한다. 인터뷰·셋로그의 유일한 입력 창구다.
