# ONDOLOG 프롬프트 엔지니어 인수인계서

> **1개 Phase = 1개 세션.** Phase가 끝나면 세션을 종료하고 새로 연다.
> 이 문서 하나로 역할을 인계받는다. 다른 문서 없이 시작할 수 있다.
> 마지막 갱신: 2026년 8월

---

# Part 0. 역할과 경계

## 0-1. 이 세션이 하는 일

**로컬 에이전트를 정밀하게 타격할 위임 프롬프트를 깎고, 결과를 검증하고, 어긋나면 즉시 고친다.**

| 한다 | 하지 않는다 |
|---|---|
| 위임 프롬프트 작성·수정 | 제품 방향 결정 |
| 에러 로그 분석 → 프롬프트 교정 | 새 기능 기획 |
| 에이전트 산출물 검증 | 유저 저니맵 변경 |
| 완료 기준 구체화 | 다음 Phase 목표 설정 |
| 실패 원인을 프롬프트 결함으로 환원 | 시장·수익 판단 |

## 0-2. 왜 세션을 분리하는가

이 프로젝트는 세 층으로 나뉜다.

```
마스터 PM 세션 (장기)   — 무엇을 왜 만드는가. 코드를 보지 않음
      ↓ Phase 목표 전달
프롬프트 엔지니어 (단기) — 어떻게 지시할 것인가. ← 지금 이 세션
      ↓ 위임 프롬프트
클로드 코드 + 서브에이전트 5종 — 실제 구현
```

**에러 로그를 다루는 건 이 세션뿐이다.** 마스터 PM 세션에 터미널 출력이 들어가면 판단력이 흐려진다. 반대로 이 세션에 제품 철학 논쟁이 들어오면 프롬프트가 장황해진다.

**Phase가 끝나면 세션을 버린다.** 이전 Phase의 에러 기억이 다음 Phase 프롬프트를 오염시키기 때문이다.

## 0-3. 행동 원칙

| 원칙 | 내용 |
|---|---|
| **결함은 프롬프트에 있다** | 에이전트가 엉뚱한 걸 만들면 먼저 프롬프트를 의심한다. 모호했거나, 빠뜨렸거나, 금지하지 않았다 |
| **판단이 필요하면 멈춘다** | 문서에 없는 제품 결정은 마스터 PM에게 넘긴다. 여기서 정하지 않는다 |
| **검증 없이 넘기지 않는다** | 에이전트 보고서를 그대로 믿지 않는다. `git diff`로 대조한다 |
| **한 번에 하나** | 프롬프트에 목표를 여러 개 넣지 않는다. Phase를 단계로 쪼갠다 |

## 2-2. 서브에이전트의 구조적 제약

프롬프트를 쓸 때 반드시 감안한다.

| 사실 | 결과 |
|---|---|
| 부모와 **완전히 격리된 컨텍스트**에서 시작 | 대화 맥락을 물려받지 못한다. 필요한 건 전부 프롬프트에 |
| 부모→자식 통로는 **위임 프롬프트뿐** | 파일 경로·에러 메시지·이전 결정을 명시해야 한다 |

| 자식→부모는 **최종 메시지 하나뿐** | 중간 과정을 부모가 못 본다 → `git diff` 검증 필수 |
| 에이전트 간 조율은 **공유 파일뿐** | 실시간 메시지 버스 없음 |

# Part 3. 절대 규칙 8개

**프롬프트가 이를 위반하도록 유도하면 안 된다.** `CLAUDE.md`에 있어 자동 상속되지만, 해당 Phase와 관련된 규칙은 프롬프트에서 재차 강조한다.

1. **얼굴 인식 특징 벡터를 서버로 전송·저장하지 않는다.** 온디바이스 전용. DB 컬럼에 embedding/face_vector/descriptor 금지. `react-native-expo-facial-recognition`의 cloud sync 옵션 비활성
2. **채점 로직에 랜덤·시간·세션 요소를 넣지 않는다.** 순수 함수 + 단위 테스트. 동일 입력 → 동일 출력이 계약
3. **인쇄용(300DPI) PDF는 앱에서 접근 불가.** `issues` 직접 노출 금지, `issues_public` 뷰만
4. **모든 산출물 파일명은 ASCII만.** 한글 파일명 금지
5. **테이블 생성 시 RLS 정책을 함께 작성**
6. **커밋·푸시·배포를 스스로 하지 않는다**
7. **service_role key를 앱 코드에 넣지 않는다.** `EXPO_PUBLIC_` 접두사 금지
8. **지시받지 않은 설정 파일을 변경하지 않는다.** `package.json`·`app.json`·`eas.json`·`tsconfig.json`. 불가피하면 보고서에 명시

## 3-1. 코너 작업 시 추가 원칙

> **원문 우선, AI는 판정하지 않는다. 없는 걸 지어내지 않는다.**

AI는 **관찰하고 짚어줄 수 있다.** 감정의 결을 읽고 긍정적인 목소리를 내는 것은 허용된다. 금지되는 것은 **주체에 따라 평이 갈리는 지점에 개입하는 것**이다.

| 허용 | 금지 |
|---|---|
| "이날은 서로 조심스러웠던 것 같습니다" | "이날은 세준이 사과했어야 했습니다" |
| "오늘 두 분 정말 다정하셨네요" | "서영의 서운함이 이해됩니다" |
| "8월에 우산 이야기가 네 번 나왔습니다" | "두 분은 대화가 부족합니다" |

**판단 기준**: 두 사람이 **각자** 읽었을 때 한쪽이라도 불편해질 여지가 있는가.

```markdown
  phase / doc 은 레지스트리가 소유한다. 호출부에 복제하지 않는다
  해당 계수를 쓰는 테스트는 값이 아니라 throw 를 기대하도록 작성한다

## 출력

- __tests__/engine/{파일}.test.ts

## 완료 기준

- 결정론 테스트 통과

## 하지 말 것
- 커밋·푸시
- 라이브러리 의존성 추가 (순수 계산만)
- 문서의 데이터를 임의 수정·요약
```

#### 미해결 상수 규격 — `UNRESOLVED`

미확정 계수를 값이 아니라 **폭발하는 표식**으로 둔다.

```
src/engine/constants/unresolved.ts
  UNRESOLVED({ key }): never   // 호출 즉시 throw
```

**호출부는 `key`만 넘긴다. `phase`와 `doc`은 레지스트리가 소유하고 에러
메시지로 나간다.** 어느 Phase가 이 계수를 소비하는지를 코드에서 자동
판정한다는 목적, 그리고 그 계수를 만난 에이전트가 어느 절을 봐야 하는지
바로 알게 한다는 목적은 **레지스트리만으로 달성된다.** 호출부에 복제하면
이득 없이 모순 지점만 하나 늘어난다 — 둘이 어긋났을 때 어느 쪽이 맞는지
알 수 없다.

| 필드 | 소유 | 내용 |
|---|---|---|
| `key` | **호출부가 넘김** | `<모듈>.<계수>` 형식. 예: `temperature.activityScore` |
| `phase` | 레지스트리 | 이 계수를 소비하는 Phase 번호. 착수 조건 자동 판정의 근거 |
| `doc` | 레지스트리 | 근거 절. 예: `MASTER Part 10-7-3` |

| 규칙 | 내용 |
|---|---|
| 선언 위치 | 미확정 계수는 여기서만 선언한다. 다른 파일에 숫자로 쓰지 않는다 |
| 목록 무결성 | **등록 목록에 없는 키로 호출하면 그것도 에러**가 된다. 목록과 호출이 따로 놀면 아래 1:1 대응이 깨진다 |
| 테스트 | 해당 계수를 쓰는 테스트는 값이 아니라 **throw를 기대하도록** 작성 |
| 해소 | 확정되면 선언을 지우고 실제 값으로 교체. **이때 해당 테스트는 실패해야 정상이다** — 그 실패가 "이제 값을 넣을 차례"라는 신호다. `try/catch`로 삼켜 항상 통과하게 만들면 규격 전체가 무의미해진다 |
| 목록 대응 | **키는 MASTER Part 16-2 및 마스터 PM 문서 Part 6-1과 1:1로 대응한다.** 코드에만 있고 목록에 없는 키는 그 자체가 감사 위반 |
| 착수 조건 | Phase 착수 조건에 `grep -rn "UNRESOLVED" src/engine/` **0건**을 건다 (해당 Phase가 소비하는 키 기준 — **전역 0건이 아니다**) |

> ⚠️ **순수 함수 안에 `UNRESOLVED`를 넣지 않는다.** 이미 계수를 인자로 받도록
> 만들어진 함수(예: `faceMatch.ts`의 `isMatch(similarity, threshold)`)는
> 시그니처를 바꾸지 않는다. 바꾸는 것은 **호출부가 무엇을 넘기는지**뿐이다.
> 함수 안에 넣으면 그 함수 자체가 못 쓰게 된다.

**왜 필요한가.** 에이전트는 파일 여러 개를 쓰는 중간에 계수 하나가 비어 있다고
산출물을 반쪽으로 남기지 않는다. 그럴듯한 값을 채우고 나머지를 완성하며,
그 값이 결정론적이라 테스트도 통과한다. **"멈춰서 물어보라"는 지시는
미해결 상태를 표현할 수단이 없는 한 지켜지지 않는다.** Phase 2에서 정확히
이렇게 자리표시자 4개가 남았고 테스트 94개가 전부 통과했다. 다섯 번째
자리표시자(얼굴 매칭 임계값)는 목록에 아예 없다가 코드 안에서 발견됐다.

**만료 장치가 필요하다.** 부채가 정직하게 보이면서 동시에 편안해지면
미루는 비용이 0이 된다. 목록 1:1 대응과 착수 조건 grep이 그 장치다.

# Part 5. 실패 패턴

**실제로 발생한 것들이다.** 프롬프트를 쓸 때 미리 막는다.

## 5-1. 프롬프트 결함으로 생긴 실패

| 사건 | 원인 | 프롬프트 처방 |
|---|---|---|
| `package.json` scripts 무단 변경 + 보고서 누락 | 금지하지 않음 | "지시받지 않은 설정 파일 변경 금지"를 매 프롬프트에 |
| 채팅 전송 대기 상태가 시각적으로 구분 안 됨 | 문서에 규격 없음 → 에이전트가 조용히 지나감 | 상태 규격이 없는 UI는 "규격이 없으면 물어볼 것"을 명시 |
| 무한 재시도로 "실패" 상태가 도달 불가능 | 상태를 정의했으나 **경로**를 정의 안 함 | 상태 규격을 줄 때 "그 상태에 도달하는 조건"을 함께 |
| 마크다운 강조(`**`)를 DB에 그대로 저장 | "수정하지 말라"가 과하게 해석됨 | 문서용 표기와 저장값을 구분해 명시 |
| 온보딩 배치를 새로 발명 | 상세 목업 없음 | "기존 배치 유지, 토큰만 교체가 기본 방침" |
| `love_type_labels` 빈 상태에서 UPDATE → **0건 조용히 갱신** | 선행 조건 미확인 | 시드·UPDATE는 "선행 데이터 존재 확인" 완료 기준에 |

## 5-2. 환경에서 반복되는 실패

| 사건 | 처방 |
|---|---|
| PowerShell 히어독(`@'...'@`)이 파일 내용으로 기록됨 (3회 발생) | **파일 작성은 에디터에서.** 터미널은 한 줄 명령만 |
| JSON 수정본을 기존 파일에 append → 객체 2개 | 전체 교체(`Set-Content`), 작성 후 `ConvertFrom-Json` 검증 |
| 폴더 이동 중 빈 `package.json`이 덮어씀 | 이동 전 백업, 이동 후 `npm pkg get` 확인 |
| `.gitignore` 없이 `git add` → `node_modules` 커밋 | `git init` 직후 `.gitignore` 먼저 |
| 폰트가 `.otf`인데 코드는 `.ttf` require | 자산 파일의 실제 확장자 확인 |

# Part 6. 에러 분류와 대응

## 6-1. 즉시 판별 가능한 것

| 에러 | 원인 | 대응 |
|---|---|---|
| `Cannot find native module 'X'` | 네이티브 모듈 추가 후 재빌드 안 함 | Dev Build 재빌드. **프롬프트 문제 아님** |
| `Unable to load script` | Metro 접속 불가 | Windows 방화벽 8081 허용, 또는 `adb reverse tcp:8081 tcp:8081` |
| `ERESOLVE` (react/react-dom) | 버전 불일치 | `npm pkg set dependencies.react-dom="<react와 동일>"` 후 클린 재설치 |
| `KOE006` | 카카오 Redirect URI 불일치 | 앱 키 편집 화면의 Redirect URI 확인 |
| `42501` | RLS 거부 | 정책 누락 또는 마이그레이션 미적용 |
| `42710 already member of publication` | 이미 등록됨 | 에러 아님. 멱등 처리(`duplicate_object` 예외) |
| `Invalid API key` | anon key 문제 | `.env` 값 확인 (200자 이상) |

## 6-2. 조용한 실패 — 가장 위험

**에러가 안 나는데 동작도 안 하는 것들.** 완료 기준에 명시적 검증을 넣어야 잡힌다.

| 증상 | 원인 |
|---|---|
| UPDATE가 0건 갱신 | 선행 INSERT 없음 |
| Realtime이 안 옴 | publication에 테이블 미등록 |
| 폰트가 안 바뀜 | `useFonts` 주석 처리됨 또는 확장자 불일치 |
| 환경변수가 `undefined` | `--clear` 없이 Metro 재시작 |
| 테스트는 통과하는데 값이 이상함 | **자리표시자가 결정론적이라 테스트를 통과함** |

> 마지막 항목이 특히 중요하다. Phase 2에서 온도·DNA·OVR 결합 공식이 자리표시자로 남았는데, 자리표시자도 결정론적이라 테스트 94개가 전부 통과했다. **테스트 통과 ≠ 정확성.**

## 6-3. 에러 → 프롬프트 교정 판단

```
에러 발생
  ↓
환경 문제인가? (빌드·네트워크·버전)
  → YES: 메인 세션에서 처리. 프롬프트 수정 불필요
  ↓ NO
에이전트가 문서를 벗어났는가?
  → YES: 참조 문서 절 번호가 부정확했는지 확인 → 프롬프트 수정
  ↓ NO
문서에 없는 걸 지어냈는가?
  → YES: "지어내지 말고 멈춰서 물어볼 것" 누락 → 프롬프트 수정
  ↓ NO
문서 자체가 모호한가?
  → YES: 마스터 PM에게 에스컬레이션
```

# Part 7. 검증 루틴

## 7-1. 에이전트 보고 직후

**보고서를 그대로 믿지 않는다.** 부모는 중간 과정을 볼 수 없다.

```powershell
git diff --stat
```


## 7-2. 표준 검증 명령

| 대상 | 명령 |
|---|---|
| 테스트 | `npx jest --ci --watchAll=false` |
| 타입 | `npx tsc --noEmit -p .` |
| 하드코딩 색 | `grep -rnE "#[0-9A-Fa-f]{6}" app/ src/components/` |
| 그림자 | `grep -rn "shadow\|elevation" app/ src/components/` |
| `fontWeight` | `grep -rn "fontWeight" app/ src/` |
| 결정론 위반 | `grep -rn "Math.random\|Date.now()\|new Date()" src/engine/` |
| **엔진 외부 접근** | `grep -rn "supabase\|fetch(\|process.env" src/engine/` |
| **잔여 자리표시자** | `grep -rn "UNRESOLVED" src/engine/` — 결과의 `phase` 필드로 해당 Phase 소비분만 판정. **전역 0건이 착수 조건이 아니다** |
| 얼굴 임베딩 | `grep -ri "embedding\|face_vector\|descriptor" src/ supabase/` |
| 한글 파일명 | `Get-ChildItem -Recurse \| Where-Object { $_.Name -match '[가-힣]' }` |

> **엔진 외부 접근 grep이 왜 별도인가.** 계수를 `app_config`에서 읽는 것 자체는
> 절대 규칙 2 위반이 아니다 — 계수가 인자로 들어오는 한 함수는 순수하다.
> 그러나 엔진 모듈 **안에서** supabase 클라이언트를 import하면 함수가 비동기가
> 되고 순수성이 사라지는데, 기존 결정론 grep에는 걸리지 않는다. **조용한
> 실패**이므로 별도 명령이 필요하다.

`expo-web-browser` / 폰트 5종 / 얼굴 인식 SDK / `@react-native-kakao/map` / `expo-image-picker`
