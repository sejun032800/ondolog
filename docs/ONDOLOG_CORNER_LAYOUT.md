# ONDOLOG 코너별 지면 설계 명세

> 대상: `date_archive` / `love_dna` / `sweet_words` / `this_month` / `league_weekly` / `league_monthly`
> 전제: 5테마(기본·힙·러블리·야간·온돌) × 6코너 = 30조합이 자동 생성된다.

---

## 0. 설계 원칙

### 0-1. 왜 코너를 다르게 해야 하는가

잡지에서 코너마다 색과 서체가 다른 이유는 **장식이 아니라 항법**이다. 독자가 페이지를 넘기다 "여기서부터 다른 이야기"임을 활자를 읽기 전에 알아야 한다. 온도록은 매호 구성이 달라지므로(코너 스킵·분량 축소) 이 신호가 종이 잡지보다 더 중요하다.

### 0-2. 그런데 자유 변주는 안 된다

30조합이 자동 생성되는 구조에서 코너마다 색·서체를 자유롭게 고르면 잡지가 아니라 짜깁기가 된다. 실제 잡지도 코너별로 아무거나 쓰지 않는다. **정해진 소수의 변수만 코너에 위임한다.**

### 0-3. 고정 / 위임 분리

| 구분 | 항목 | 결정 주체 |
|---|---|---|
| **고정** | 판형 A4 210×297, 마진, 폴리오 위치·서체 | 테마 |
| **고정** | 본문 서체·본문 크기·행간 | 테마 |
| **고정** | 사진 듀오톤 방식 | 테마 |
| **고정** | 배경색 세트 | 테마 |
| 위임 | 코너 잉크 (3단계 중 1) | 코너 |
| 위임 | 디스플레이 서체의 **사용법** (서체 자체가 아님) | 코너 |
| 위임 | 그리드 유형 | 코너 |
| 위임 | 사진 밀도 | 코너 |
| 위임 | 활자 밀도 | 코너 |
| 위임 | 오프너 유형 | 코너 |

**서체 파일은 코너가 바꾸지 않는다.** 테마가 정한 디스플레이 서체 1종을 웨이트·스타일·자간·크기로만 변주한다. 폰트 로딩 비용과 일관성 두 가지 이유다.

### 0-3b. 판면·조판 밀도 규격 (A4 잡지 관행 기준)

여백은 미감의 문제이기 전에 **분량의 문제**다. 초기 조판은 관행 대비 과도하게 헐거웠고, 그만큼 지면에 실을 수 있는 내용이 줄었다.

| 항목 | 초기값 | 잡지 관행 | 확정값 |
|---|---|---|---|
| 상단 마진 | 22mm | 10mm | **16mm** |
| 하단 마진 | 28mm | 10mm | **20mm** (폴리오 여유) |
| 좌우 마진 | 22 / 22mm | 13(안) / 20(밖) | **18 / 18mm** |
| 판면 | 166 × 247mm | — | **174 × 261mm** (+12%) |
| 본문 크기 | 9.6pt | 9pt (최소 9pt) | **9.4pt** |
| 행간 | 205% | 라틴 120~150% | **172%** (한글 권장 170~180%) |
| 본문 폭 | 92~104mm | 라틴 50~70자 | **132~140mm** (한글 38~42자) |

> **행간이 가장 큰 지렛대였다.** 205% → 172%만으로 같은 지면에 약 19% 더 들어간다. 한글은 라틴보다 행간이 필요하므로 관행값(120~150%)을 그대로 쓰지 않고 170~180% 안에서 하한을 택했다.

> **지면당 분량 하한:** 한 지면이 담는 요소가 3종 미만이면 통합을 검토한다. 사진 1장 + 캡션 한 줄짜리 지면은 오프너를 제외하고 만들지 않는다.

> **본문 폭은 55% 규칙을 폐기했다.** 한글 9.4pt에서 92mm는 한 줄 27자로, 권장(35~45자)에 크게 못 미쳐 시선이 자주 되돌아온다. 다만 `sweet_words`는 인용 코너이므로 68%(118mm, 약 35자)로 별도 상한을 둔다.

> 온도록은 좌우 대칭 단면 PDF이므로 안쪽/바깥쪽 마진을 나누지 않고 좌우를 같게 둔다. 실물 인쇄(Year 2)로 갈 때 안쪽 마진을 13mm에서 최소 **20mm**로 늘려야 한다 — 제본으로 판면이 먹힌다.

### 0-4. 잉크 3단계 — 편집 철학과 연결

코너 잉크는 테마 팔레트 안에서 **강 / 중 / 약** 3단계만 순환한다. 배정 기준은 미적 취향이 아니라 **AI가 얼마나 개입하는가**다.

| 단계 | 코너 | 이유 |
|---|---|---|
| **강** | `love_dna`, `league_weekly`, `league_monthly` | 수치 코너. AI 산출물이 지면의 주인공 |
| **중** | `date_archive`, `this_month` | 서사 코너. 유저 기록 위에 AI가 구조를 얹음 |
| **약** | `sweet_words` | 원문 코너. AI 문장이 `context` 하나뿐 |

`sweet_words`가 가장 옅은 잉크를 쓰는 건 "AI는 물러난다"를 지면 차원에서 구현한 것이다. 이 코너만 디스플레이 서체를 아예 쓰지 않는다.

### 0-5. 밀도 교차 — 리듬의 정체

사진 밀도와 활자 밀도를 **반대로 걸어** 지면 리듬을 만든다.

```
              사진 많음 ────────────── 사진 없음
활자 희박   date_archive              sweet_words
                 │                        │
                 │      this_month        │
                 │                        │
활자 조밀   (해당 없음)              league_weekly / monthly
                                     love_dna
```

`sweet_words`(사진0·활자희박)와 `league`(사진0·활자조밀)가 대각선 양극이다. 두 코너를 인접 배치하면 안 된다 — 대수 순서에서 반드시 `this_month`를 사이에 둔다.

## 2. 테마별 코너 잉크 값

각 테마는 강·중·약 3값을 정의한다. 코너는 §1의 배정에 따라 이 중 하나를 받는다.

| 테마 | 강 (수치 코너) | 중 (서사 코너) | 약 (원문 코너) | 별지 지면 |
|---|---|---|---|---|
| **기본** | `#6E7F6B` 세이지 | `#7E7568` 먹 | `#8C8378` 담묵 | `#2A2A26` 다크 |
| **힙** | `#2BFF9E` 네온 | `#17EAD9` 틸 | `#0E5C3F` 딥그린 | `#07110D` 다크 |
| **러블리** | `#D9748F` 로즈 | `#B4576F` 진한로즈 | `#8A8072` 회갈 | `#4A2836` 딥플럼 |
| **야간** | `#E3D0A4` 샴페인 | `#C9B27E` 다크골드 | `#8D93A8` 청회 | `#F2EFE7` **반전** |
| **온돌** | `#A8332A` 주칠 | `#1F1B18` 먹 | `#6B6055` 담묵 | `#231F1B` 다크 |

> **야간만 별지가 반전(밝은 지면)이다.** 다른 테마는 밝은 본지 → 어두운 별지로 낙차를 만들지만, 야간은 본지가 이미 어두우므로 방향을 뒤집는다.

> **온돌 주칠 제한:** 주칠은 지면당 한 점만. `love_dna`에서도 대형 숫자 전체가 아니라 소수점 이하 또는 델타 기호에만 쓴다.

## 3-0. `publication_note` — 발행 노트 (부속 지면)

**성격:** 부속. 코너가 아니다. 잡지의 판권·속표지에 해당하는 지면으로, **잉크 3단계 체계 밖에 있다.**

### 왜 코너가 아닌가

기존 12종은 전부 데이터 코너다. 표지 다음 바로 기사가 시작하고 뒤표지로 끝나는 구성이라, 읽고 나면 "잡지를 봤다"보다 "리포트를 봤다"에 가깝다. 실제 잡지는 판권·권두언·예고 같은 **부속 지면**이 리듬과 신뢰를 만든다.

### 잉크 규칙 — 체계 밖

| 지면 | 잉크 |
|---|---|
| 코너 | 강 / 중 / 약 3단계 순환 (§0-4) |
| **부속** | **코너 잉크를 쓰지 않는다. 무채(`--ink-2`)만.** |

4단계를 새로 만들면 체계가 무너진다. 부속을 체계 밖에 두는 것이 실제 잡지의 판권 처리 방식이고, 독자에게도 "여기는 기사가 아니다"라는 신호가 된다. 목차에서도 코너는 잉크 사각형, 부속은 헤어라인으로 구분한다.

### 편집 원칙 — 이 지면에는 형용사가 없다

발행 노트는 **재료를 공개할 뿐 평가하지 않는다.** 숫자와 명사로만 쓴다. "풍성한 한 달이었습니다" 같은 문장이 들어오는 순간 이 지면의 기능이 사라진다.

담는 것:
1. 수집 기간과 재료 집계 — 원본 수량과 **실제 게재 수량을 나란히** ("사진 34장 · 이 중 17장을 게재")
2. **문장의 출처 비율** — 두 사람이 쓴 문장 vs 온도록이 쓴 문장
3. 싣지 않은 것과 그 사유
4. 비어 있는 코너와 스킵 사유
5. 정정 요청 창구

### 지면 구성 (1면)

```
킥커 Publication Note ─────────────── 호수 · 발행일
━━ 1.6pt 무채 ━━
「이 호는 무엇으로 만들어졌나」   20pt
리드 3줄                          폭 140mm
── 수집한 재료 ── (ed-table)
  항목 ······ 수량 ······ 실제 게재
── 문장의 출처 ──
  [■■■■ 두 사람 42% │ ░░░░░ 온도록 58% ]
── 하단 2열 ──
  싣지 않은 것 │ 비어 있는 코너
  정정 요청 안내
```

### 문장 출처 막대 — 이 지면의 핵심

"AI는 물러난다"는 원칙을 **말이 아니라 수치로** 보여주는 유일한 장치다. 렌더러가 지면에 실린 문장을 두 종류로 세어 산출한다.

| 분류 | 포함 |
|---|---|
| 두 사람이 쓴 문장 | `userNotes[].text`, `sweet_words.main[].turns[]`, `sub[]`, `evidence.excerpt` |
| 온도록이 쓴 문장 | `aiCaption`, 코너 리드, `context`, `explanation`, `headline`, `closingQuestions` |
| 집계 수치 | 어느 쪽도 아님 — 막대에서 제외 |

**비율이 나쁘게 나와도 그대로 싣는다.** 58%가 AI 문장이라는 사실을 감추면 이 지면의 존재 이유가 없어진다.

### 슬롯 매핑

| 지면 요소 | 출처 | 폴백 |
|---|---|---|
| 수집 기간 | `issues.period_start`, `period_end` | 필수 |
| 재료 집계 | 원재료 수집 단계의 카운트 | 0이면 해당 행 삭제 |
| 게재 수량 | 렌더러가 실제 조판된 개수를 셈 | 필수 |
| 문장 출처 | 위 분류표대로 렌더러가 산출 | 필수 |
| 싣지 않은 것 | 상한 초과분, 미채택 항목 | 없으면 "모두 실었습니다" |
| 비어 있는 코너 | `corners.status = 'skipped'` + `skip_reason` | 없으면 "이번 호에는 없습니다" |

> **스킵 사유를 유저 언어로 번역한다.** `no_warm_messages`를 그대로 쓰면 안 된다. 다만 §3-3에서 정한 대로 **감정적 해석을 덧붙이지 않는다** — "다정한 말이 없었습니다"가 아니라 "인용할 만한 대화를 찾지 못했습니다".

### 배치

표지 → 목차 → **발행 노트** → 본지. 권두에 두는 이유는, 독자가 기사를 읽기 **전에** 재료를 알아야 기사를 어떻게 읽을지 정할 수 있기 때문이다.

### 3-1. `date_archive` — 데이트 아카이브

**성격:** 화보. 이 잡지에서 사진이 가장 많은 코너이자, 유저 기록이 가장 직접적으로 드러나는 곳.

#### 대수 구성 (가변) — 4면 기준

초기 설계는 7면이었으나 지면당 분량이 지나치게 적었다. **한 지면이 하나의 요소만 담으면 여백이 콘텐츠를 대신하게 된다.** 아래로 통합했다.

```
[1면] 오프너 + 기사 헤드   사진 풀블리드 130mm + 코너 리드 + 지명/제목/리드 + 요약 수치 + 부속 정보
[2면] 타임라인 전체        stops 전부를 한 면에 (사진 크기로 조절)
[3면] 이동 경로 + 세 물음   지도 132mm + 장소 목록 + closingQuestions 3열
[4면] 기사 2 (재소환)      사진 92mm + 헤드 + 본문/수치 2단 + 그날 사진 3장
```

| 통합 전 | 통합 후 | 근거 |
|---|---|---|
| 오프너 · 기사 헤드 (2면) | 1면 | 오프너 침묵면이 사진 1장 + 캡션 한 줄만 담아 지면의 80%가 비었음 |
| 타임라인 (2면) | 1면 | stop당 사진 높이를 94→68mm, 60/40→50/34mm로 줄이면 3 stop이 한 면에 들어감 |
| 지도 · 질문 (2면) | 1면 | 질문 3개를 세로 나열에서 3열로 바꾸면 40mm면 충분 |
| 기사 2 (1면) | 1면 | 하단 여백에 그날 사진 3장을 실어 채움 |

**stops 수용 한계:** 판면 261mm 기준, `사진 1장` stop은 약 90mm, `사진 0장` stop은 약 16mm, `사진 3장` stop은 약 104mm를 차지한다. 합이 240mm를 넘으면 타임라인을 2면으로 분리한다.

`articles`가 2편 이상이면 두 번째 기사부터는 **오프너를 생략**하고 헤드를 절반 크기로 줄인다. 오프너는 코너당 1회.

#### 슬롯 매핑

| 지면 요소 | jsonb 경로 | 폴백 |
|---|---|---|
| 오프너 사진 | `articles[featured].stops[0].photos[0]` | 전체 stops 중 첫 사진 |
| 오프너 캡션 | `header.title` + `summary.regions` | 지역 없으면 날짜만 |
| 기사 지명 | `articles[i].region` | `null`이면 지명 줄 자체를 삭제 (공백 유지 금지) |
| 기사 제목 | `articles[i].title` | 필수 |
| 요약 수치 | 첫 stop `time` / 마지막 stop `time` / `stops.length` / 총 photos | — |
| 타임라인 시각 | `stops[j].time` | 필수 |
| 타임라인 장소 | `stops[j].placeName` | `null`이면 시각만 표기. **지어내지 않는다** |
| 주인공 활자 | `stops[j].userNotes[].text` | 없으면 아래로 |
| 보조 활자 | `stops[j].aiCaption` | userNotes 있으면 반드시 null |
| 재소환 배지 | `articles[i].recalled` | false면 배지 미표시 |

#### 사진 배치 규칙

stop당 사진 개수에 따라 레이아웃이 결정된다. **AI가 고르는 게 아니라 개수가 결정한다.**

| photos.length | 배치 | 높이 |
|---|---|---|
| 0 | 사진 블록 생략, 활자만 | — |
| 1 | 단독 · 우측 컬럼 전폭 | 90~96mm |
| 2 | 대칭 쌍 · 같은 높이 | 84~88mm |
| 3 | 큰 것 1 + 작은 것 2 (하단) | 60mm + 40mm |
| 4 이상 | 상위 3장만 지면 게재, 나머지는 미게재 | 상동 |

> 한 stop에서 4장을 넘기면 지면이 앨범이 된다. 잡지는 앨범이 아니다. **초과분은 버린다**(디지털 아카이브에는 남아 있다).

#### 활자 위계 — 이 코너의 핵심

```
유저 메모        13~15pt / 본문 서체 Regular / 잉크 100%
  ↓ 확연한 낙차
작성자 표기       7.6pt / 잉크 60%
AI 캡션          8.2pt / 잉크 45% + 별도 라벨 "AI 캡션"
```

유저 메모와 AI 캡션 사이에 **크기 1.6배 + 명도 2단계** 차이를 강제한다. 둘이 비슷해 보이면 이 코너의 존재 이유가 사라진다.

#### 지도 지면 (`mapInfographic`) — 신규

현재 샘플에 없는 지면이다. 설계:

- 지면 전체를 **여백 처리한 단색 지도**로. 실제 지도 타일을 쓰지 않는다 (저작권·톤 충돌)
- `bounds`로 범위를 잡고 `pins`를 좌표 변환해 점으로 찍음
- 점은 코너 잉크(중), 연결선은 0.4pt 헤어라인, 순서는 `order`
- 라벨은 핀 옆 7pt. 핀이 5개를 넘으면 라벨을 생략하고 번호만
- `mapInfographic: null`이면 **이 지면을 통째로 생략**한다

### 3-2. `love_dna` — 우리의 연애 DNA

**성격:** 지표. 온도록에서 숫자가 가장 크게 나오는 곳.

#### 대수 구성 (고정 2면)

```
[1면] 대형숫자면 — total + delta + 산출 설명 + 두 사람 유형 카드
[2면] 축 비교면 — bigFive 5축 + 겹침/다름 + attachmentCombo
```

#### 슬롯 매핑

| 지면 요소 | jsonb 경로 | 폴백 |
|---|---|---|
| 대형 숫자 | `score.total` | 필수 |
| 델타 | `score.delta`, `score.previousTotal` | `null`이면 "첫 호" 표기, 삼각 기호 미표시 |
| 산출 설명 | `score.base`, `score.chatDelta` | 필수 |
| 유형 카드 | `partners[].labelEn`, `labelKo`, `mbti`, `enneagram`, `attachment` | 필수 |
| 축 | `bigFiveComparison[]` | 5개 고정 |
| 겹침/다름 | `strengths[]`, `complements[]` | 각 2~4개 |
| 애착 | `attachmentCombo.pairLabel`, `headline` | 필수 |
| 실천 팁 | `actionTips[]` | `total > 60`이면 빈 배열 → **팁 블록 생략** |

#### 대형 숫자 조판 규칙

```
정수부  96~150pt (테마별)
소수부  정수부의 0.44배, 베이스라인 정렬
lining-nums 강제  ← 세리프 기본 올드스타일이면 숫자가 흘러내림
```

> 이건 실제로 걸렸던 문제다. Cormorant·Playfair는 기본이 올드스타일 숫자라 `28`, `61` 같은 값에 디센더가 생긴다. `font-variant-numeric: lining-nums` 없이는 수치 지면이 전부 깨진다.

#### 5축 표기 — 테마별로 방식이 다르다

| 테마 | 표기 |
|---|---|
| 기본·야간 | 헤어라인 위 점 2개 (● 세준 / ○ 서영) |
| 힙 | 사람별 막대 2줄 (네온 / 틸) |
| 러블리 | 사람별 둥근 막대 2줄 |
| 온돌 | 헤어라인 위 세로 눈금 (│ 먹 / ┊ 주칠) |

**두 값이 동일할 때(gap 0) 처리를 반드시 넣는다.** 점 방식은 한 사람이 사라진다 — 동심원으로 크기를 달리하거나 눈금 길이를 다르게 한다.

#### `actionTips` 블록

`total ≤ 60`일 때만 나타나는 조건부 블록이다. 2면 하단에 배치하되, **팁이 있으면 `complements` 블록을 1면으로 올린다.** 두 블록이 같은 면에 겹치면 지면이 조언서가 된다.

### 3-3. `sweet_words` — 다정한 말들

**성격:** 인용. 이 잡지에서 AI가 가장 적게 쓰는 지면.

#### 대수 구성 (2~3면) — `main` 개수가 지면 수를 결정한다

| main.length | 구성 |
|---|---|
| 1~2 | 오프너 1면 + 인용 1면 (총 2면) |
| 3 | 오프너 1면 + 인용 2면 (총 3면) |

**main 3개를 인용면 1장에 넣으면 하단 `sub` 블록과 충돌한다.** 실제로 겹침이 발생했다. 인용 조판은 12.5pt / 행간 175%로 한 대화가 약 40~55mm를 차지하므로, 판면 261mm에 들어가는 대화는 최대 2개다.

```
[오프너 1면]   침묵면 — 사진 1장 + 다정 지수
[인용면 1]     main[0], main[1]
[인용면 2]     main[2] + sub[] 6개 + 원문 고지     ← main 3개일 때만
```

#### 이 코너만의 규칙

1. **디스플레이 서체를 쓰지 않는다.** 영문 대제목·초대형 활자 금지. 오프너의 코너명만 예외.
2. **본문 사진 0장.** 오프너 1장이 전부. 사진이 들어오면 대화가 사진의 캡션이 된다.
3. **텍스트 블록 폭 최대 55%.** 다른 코너보다 좁게. 인용은 좁을수록 인용처럼 읽힌다.
4. **잉크 약(가장 옅은 값).** 이 코너만 액센트를 거의 쓰지 않는다.

#### 슬롯 매핑

| 지면 요소 | jsonb 경로 | 조판 |
|---|---|---|
| 다정 지수 | `warmthIndex` | `null`이면 표기 생략. 0 표기 금지 |
| 정황 | `main[i].context` | 9.5pt Regular — **AI가 쓰는 유일한 문장** |
| 출처 | `main[i].attribution.display` | 7.4pt / 잉크 55% / 정황 바로 아래 |
| 대화 | `main[i].turns[]` | **12.5~15pt** — 지면에서 가장 큰 활자 |
| 화자 | `turns[j].speaker` | 7.6pt / 발화 위 |
| 단문 | `sub[]` | 9pt / 하단 2×2 그리드 |

#### 발화 조판

```
turns[0]        들여쓰기 0
turns[1]        들여쓰기 10~12mm      ← 주고받음을 위치로 표현
turns[2]        들여쓰기 0
turns[3]        들여쓰기 10~12mm
```

말풍선·따옴표 그래픽을 쓰지 않는다. 채팅 UI를 지면에 옮기면 잡지가 아니라 스크린샷이 된다. **위치와 여백만으로 대화임을 표현한다.**

#### 스킵 처리 — 반드시 필요

`status = 'skipped'`, `skip_reason = 'no_warm_messages'`인 달이 실제로 발생한다. 이때:

- 코너를 통째로 빼고 목차에서도 제거
- **대체 지면을 만들지 않는다.** "이번 달은 다정한 말이 없었습니다" 같은 지면은 유저에게 상처가 된다
- 목차 페이지 번호를 재계산

### 3-4. `this_month` — 이달의 우리

**성격:** 기사. 활자 밀도가 가장 높은 본지 코너.

#### 대수 구성 (고정 2면)

```
[1면] 저중심면 — 테마 헤드라인 + 리드 + 신호 근거 + 요약 수치 3개
[2면] 소기사 n단 + 마무리 한 줄
```

#### `articles` 개수별 그리드 — 가변 대응의 핵심

`articles`는 2~4편으로 변한다. 3단 고정 그리드는 2편·4편에서 깨진다.

| articles.length | 그리드 | 사진 높이 |
|---|---|---|
| 2 | 2단 (좌우 균등) | 88mm |
| 3 | 3단 균등 | 62mm |
| 4 | 2×2 | 54mm |

#### 소기사 제목 높이 고정 — 반드시

제목이 1줄인 기사와 2줄인 기사가 섞이면 본문 시작선이 어긋난다. 실제 데이터에서 제목 길이는 매호 다르므로 **구조적 결함**이다.

```css
.sub-article-title { min-height: 12.6mm; }  /* 2줄분 */
```

3줄 제목은 생성 단계에서 막는다 (`title` 길이 상한 필요 — §5 참조).

#### 근거 표기

`articles[].evidence`는 최소 1개가 보장된다. 지면에는 **본문 아래 7.2pt 한 줄**로 표기한다.

```
근거 · 신규 방문 5곳 · 사진 34장
```

`evidence.type`별 표기:
- `message` → `excerpt`를 따옴표로 (원문 그대로, 15자 초과 시 지면 게재 대신 날짜만)
- `photo` → "사진 n장"
- `metric` → `metricKey` 한글 라벨 + `metricValue`

### 3-5. `league_weekly` — 연애리그 주간판

**성격:** 카드. 별지. 이 잡지에서 유일하게 게임 문법을 쓰는 지면.

#### 대수 구성 (1~2면)

```
[1면] 별지 표지 겸 스탯 카드 2장 + 매치 리포트 11항목
```

지면이 넘치면 카드 1면 / 리포트 1면으로 분리.

#### 이 코너만의 규칙

1. **별지 지면색을 쓴다** (§2 표 참조). 본지와 명확히 다른 배경.
2. **사진 0장.** 게임 카드에 사진이 들어가면 SNS 프로필이 된다.
3. **본지 폴리오 대신 "별지" 표기**를 병기.
4. 잉크 강 단계 + 사람별 색 2개로 구분.

#### 스탯 카드

```
OVR 숫자     40~52pt / 잉크 강
이름         11~12pt
티어·델타     7.2pt — ovrTier, ovrDelta
──────────
6개 스탯 행:
  라벨 7.8pt (좌) ····· 값 9pt (우)
  막대 폭 = 값 / 100
```

`ovrDelta`가 `null`인 첫 호는 델타 줄을 생략한다. `▲0` 표기 금지.

**두 사람의 막대 색은 반드시 명도로도 구분되어야 한다.** 색상만 다르면 흑백 인쇄와 색각 이상에서 구분이 사라진다.

#### 매치 리포트 11항목

`format`별로 행 구조가 다르다. 이게 이 지면의 조판 난점이다.

| format | 행 구조 | 예 |
|---|---|---|
| `split_percent` | `a` ─ 라벨 ─ `b` | 42 / 예상 대화 점유율 / 58 |
| `split_count` | `a` ─ 라벨 ─ `b` | 3 / 리액션 어시스트 / 7 |
| `single_value` | `—` ─ 라벨 ─ `value` | — / 연애 주도권 스코어 / 2:1 |
| `single_percent` | `—` ─ 라벨 ─ `value%` | — / 티키타카 성공률 / 83 |
| `event` | 라벨 ─ `value` (전폭) | 막판 감동 극장골 / 08.27 23:41 |

`event`만 2열 구조라 나머지 3열 행들 사이에서 튄다. **`event` 항목은 리포트 맨 아래로 몰아 배치**한다.

#### `measured` 표기 — 정직성

`measured: false`인 항목은 추정치다. 개별 행에 표시하지 않고 **리포트 하단에 한 줄로 묶어 명시**한다.

```
점유율 · 티키타카 · 어시스트는 실제 대화 기록으로 산출했습니다. 나머지는 추정치입니다.
```

행마다 별표를 달면 지면이 각주투성이가 된다.

### 3-6. `league_monthly` — 연애리그 월간판 (신규 지면)

**성격:** 서사 + 표. 주간판이 "결과"라면 월간판은 **"왜 그렇게 됐는지"**를 다룬다. 현재 샘플에 없는 지면이다.

#### 대수 구성 (2~3면)

```
[1면] 시즌 개요 — season + standings.initiativeTrend 꺾은선 + summary
[2면] 스탯 변동 서사 — statChanges 2~3개 (각각 explanation + evidence)
[3면] 능력치 배분표 — statBreakdown (선택, 지면 여유 시)
```

#### 1면: 주도권 추이

`standings.initiativeTrend`는 주차별 a/b 값 배열이다.

- 꺾은선 2줄. 축 없이 **헤어라인 기준선 1개**만
- 주차 라벨은 하단 7pt
- 두 선의 교차점에만 점 표시 (주도권이 바뀐 지점)
- `summary` 한 줄을 그래프 아래 9.5pt

#### 2면: 스탯 변동 서사 — 이 코너의 핵심

`statChanges`는 절대 변동폭 상위 2~3개다. 항목당 블록:

```
┌────────────────────────────────────
│  감정 공감력          62 → 71   ▲9
│  ─────────────────────────────
│  [explanation 서사 9.4pt / 폭 55%]
│
│  근거
│  "오늘 고생했어 진짜"
│  — 2026.08.11 23:40, 밤 대화 중
└────────────────────────────────────
```

- `from → to` 는 대형 숫자 아님. 18~22pt
- `explanation`은 서사 문장이지만 **평가가 아니다.** 지면에서도 본문 서체로 조판해 "기사"처럼 보이게 한다
- `evidence`는 최소 1개 보장. `type: 'message'`면 원문을 인용 조판(§3-3 규칙 준용), `photo`면 소형 썸네일 1장, `metric`이면 수치 한 줄

**증거 사진은 이 코너에서만 소형(28×28mm)으로 쓴다.** 화보가 아니라 각주이기 때문이다.

#### 3면: 능력치 배분표

`statBreakdown[].contributions`는 share 합이 1.0이다. 100% 누적 막대 1줄로 표기.

```
감정 공감력  89
├─ 우호성 42% ─┼─ 친밀감 33% ─┼─ 애니어그램 25% ─┤
```

- 구간 색은 잉크 강 → 중 → 약 순으로 명도 하강
- 구간 라벨은 `sourceLabel` + `share` 백분율
- share가 8% 미만인 구간은 라벨을 생략하고 색만 (지면에서 안 읽힘)

#### 압축 모드 배지

`publish_mode = 'compressed'`면 변동폭이 비현실적으로 크게 나온다. 1면 상단에 배지 표기:

```
압축 발행 · 변동폭이 실제보다 크게 나타날 수 있습니다
```

#### 첫 달 처리

이전 스냅샷이 없으면 `statChanges: []`다. 이때 2면을 통째로 빼고 **1면 + 배분표 구성**으로 줄인다.

## 4. 가변 데이터 폴백 규칙 (전 코너 공통)

| 상황 | 처리 |
|---|---|
| 코너 `status = 'skipped'` | 지면 통째 제거 + 목차에서 제거 + 페이지 번호 재계산 |
| 배열이 예상보다 짧음 | 그리드를 개수에 맞게 전환 (§3-4 표) |
| 배열이 예상보다 김 | 상한까지만 게재. 초과분은 버림 |
| 문자열이 예상보다 김 | 지면 게재 대신 요약 표기로 전환. **절대 넘치게 두지 않음** |
| `null` 필드 | 해당 줄 **삭제**. 빈 자리를 남기지 않음 |
| 사진 0장 | 사진 블록 삭제 후 활자를 위로 당김 |
| 첫 호 (델타 없음) | 델타 줄 삭제. `▲0` / `-` 표기 금지 |

### 4-0. 서사와 도해의 일관성 검증

AI가 쓴 요약 문장과 데이터가 그리는 도해가 **서로 다른 이야기를 할 수 있다.** 실제로 발생했다: `standings.summary`가 "주도권은 3주차에 한 번 바뀌었습니다"라고 썼는데 `initiativeTrend` 값은 두 번 교차했다.

문장은 생성 모델이 쓰고 도해는 렌더러가 그리므로, **둘을 대조하는 검증이 없으면 불일치가 그대로 발행된다.**

| 코너 | 대조 대상 | 검증 규칙 |
|---|---|---|
| `league_monthly` | `standings.summary` ↔ `initiativeTrend` | 문장이 명시한 교차 횟수·시점이 실제 부호 변화와 일치 |
| `love_dna` | `attachmentCombo.headline` ↔ `bigFiveComparison[].relation` | "서로 다르다"류 서술이 `complementary` 축 존재와 일치 |
| `love_dna` | `score.total` ↔ `base + chatDelta` | 합이 일치 (±0.1), 클램프 적용 시 플래그 |
| `this_month` | `theme.headline` ↔ `theme.signals` | 헤드라인이 지목한 대상이 `signals`에 존재 |
| `date_archive` | `summary.dateCount` ↔ `articles.length` | 일치 |
| `date_archive` | `summary.regions` ↔ `articles[].region` | 헤드라인·캡션의 지역명이 실제 `region` 값에 존재 |
| `league_weekly` | 하단 실측 고지 ↔ `items[].measured` | 고지에 나열한 항목이 `measured: true` 집합과 정확히 일치 |
| `league_monthly` | `statChanges[].delta` ↔ `to - from` | 일치 |
| `league_monthly` | `statBreakdown[].contributions[].share` | 합 1.0 (±0.01) |

**불일치 처리:** 도해를 문장에 맞추지 않는다. **문장을 재생성한다.** 데이터가 사실이고 문장이 해석이기 때문이다.

이 검증은 `rule-auditor` 에이전트가 맡되, 위 표는 결정론적 비교라 순수 함수로 구현 가능하다 — 모델 호출 없이 엔진 계층에서 처리한다.

### 4-1. 넘침 방지는 렌더러가 아니라 생성 단계에서

지면이 넘치면 렌더러가 줄일 수 없다. **생성 단계에서 문자열 길이 상한을 강제**해야 한다. §5 참조.

## 5. 스키마에 추가가 필요한 항목

지면 설계 과정에서 드러난 누락이다.

| 항목 | 이유 | 제안 |
|---|---|---|
| `articles[].title` 길이 상한 | 3줄 제목이 오면 소기사 그리드가 깨짐 | 20자 |
| `theme.headline` 길이 상한 | 저중심면 대제목이 3줄을 넘으면 리드가 밀림 | 16자 |
| `statChanges[].explanation` 길이 상한 | 폭 55% 조판에서 넘침 | 120자 |
| 코너 제목 길이 상한 | **온돌 테마 세로쓰기가 7자 초과 시 열이 분리됨** | 7자 |
| `PhotoRef` 방향 판별 | 세로/가로 혼재 시 대칭 쌍 배치가 깨짐 | `width`/`height`로 렌더러가 판정 (스키마 변경 불필요) |
| `sweet_words` 지면 수 산출 | `main` 3개면 인용면 2장이 필요 | 렌더러가 `main.length`로 결정 (스키마 변경 불필요) |
| `standings.summary` 검증 | 문장과 꺾은선이 어긋남 | §4-0 대조 규칙 |
| `pdf_profiles.scale` 재정의 | Chromium은 텍스트를 벡터로 출력해 scale이 무의미 | 원본 화질 + bleed + 색공간으로 재정의 |

## 6. 대수 순서 (권장)

밀도 교차(§0-5)를 지키는 배치다.

```
표지
목차
발행 노트        부속 · 재료 공개
── 본지 ────────────────
data_archive     화보 · 사진 최대
love_dna         지표 · 숫자
sweet_words      인용 · 가장 희박      ← 숫자 뒤에 여백
this_month       기사 · 조밀           ← 완충
── 별지 ────────────────
league_weekly    카드 · 가장 조밀
league_monthly   서사 + 표
────────────────────────
뒤표지
```

`sweet_words`와 `league`가 인접하지 않도록 `this_month`가 사이에 들어간다. 만약 `this_month`가 스킵되면 **`sweet_words`를 `love_dna` 앞으로 이동**시켜 완충을 유지한다.

## 7. 지면 검사 도구 (`audit.py`)

지면은 눈으로만 보면 놓친다. 브라우저에서 요소별 사각형과 색을 계산해 기계적으로 검사한다.

| 검사 | 내용 | 실제로 잡은 것 |
|---|---|---|
| 지면 밖 넘침 | 요소가 210×297 밖으로 나감 | — |
| safe 이탈 | 판면 밖으로 나감 | — |
| **요소 겹침** | 형제 요소의 사각형이 2px 이상 교차 | `sweet_words` 세 번째 인용이 하단 `sub` 블록을 덮음 |
| 깨진 이미지 | `naturalWidth === 0` | — |
| 저대비 | 30px 미만 활자가 배경 대비 2.6:1 미만 | 5테마 86건 (캡션·킥커·AI 캡션 전반) |
| 과소 활자 | 7.6pt 미만 | — |

**겹침 검사는 나중에 추가했다.** 경계 검사만으로는 "지면 안에 있지만 서로 겹친" 상태를 못 잡는다. 절대배치 요소는 의도적 중첩이 많아 제외하고, 본문 계열 클래스(`body` `turn` `h-kr` `note` `cap` `num` `sub-title` `aicap`)만 대상으로 한다.

코너·테마를 추가할 때마다 이 스크립트를 돌린다.
